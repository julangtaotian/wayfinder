# REQ-2026-023：UI 验收工作流超长文件模块化

## 基本信息

- 状态：已验收
- 提出人：用户
- 负责人：Codex
- 目标版本：0.13.0
- 关联页面或模块：UI Review 配置、采集计划、运行状态、持久化与兼容 CLI
- 关联变更：`modularize-ui-review-workflow`

## 背景与目标

`plugins/frontend-ai-workflow/scripts/ui-review-workflow.mjs` 当前为 1239 行，同时承担配置校验、安全路径、采集计划、运行状态机、持久化和 CLI 调度；对应的 `tests/ui-review-automation.test.mjs` 为 1415 行，30 个测试覆盖配置、状态、比较、浏览器运行时和命令入口。两者行为完整且测试通过，但职责聚集使局部修改需要阅读整份文件，也增加冲突和回归定位成本。

本需求只做内部模块化：保留原生产入口、全部公开导出、CLI 命令、JSON 字段、错误文案和退出语义；测试保留原入口路径与 30 个既有测试名称，将实现和测试分别按职责拆分。该变更不新增用户能力，也不改变任何可观察行为。

## 范围

### 包含

- 拆分 UI Review 配置/合同、安全路径、采集计划、运行状态、状态存储和 CLI 调度职责。
- 保留 `ui-review-workflow.mjs` 作为唯一兼容入口和直接运行入口。
- 保持原有 18 个公开导出、两个内部消费者的导入路径及稳定命令合同。
- 将 30 个既有测试按配置、状态、采集/浏览器、CLI/技能合同分组，并保留原聚焦测试入口。
- 增加结构断言，防止兼容门面再次吸收实现或拆分后文件重新失控。
- 完成插件 cachebuster 更新、校验和本地重装。

### 不包含

- 新增 UI Review 功能、命令、配置字段、状态或错误文案。
- 修改比较算法、浏览器交互、受信适配器、安全边界或退出码。
- 拆分 `tests/workflow.test.mjs`、`tests/lanhu-ui-reconstruction.test.mjs` 或其他文件。
- 修改 OpenSpec 运行时、Playwright 运行时、LFS 资产或验收输出。
- 修改 marketplace 条目内容或提升功能版本号。

## 当前行为

- `ui-review-workflow.mjs` 以单文件实现 18 个公开导出和直接 CLI，代码 1239 行。
- `ui-review-automation.test.mjs` 在单文件中定义 fixture、30 个测试和多类端到端场景，代码 1415 行。
- `ui-review-runner.mjs` 与 `playwright-adapter-runner.mjs` 都从原入口导入公共 API。
- 聚焦测试和仓库完整验证当前通过，可作为等价重构基线。

## 期望行为

### 场景：公共 API 保持兼容

- 前置条件：现有消费者继续从 `ui-review-workflow.mjs` 导入任一公开符号。
- 当：模块化重构完成并加载入口。
- 则：原 18 个公开符号仍存在，名称和调用结果不变。
- 并且：消费者不需要改导入路径。
- 异常或边界：内部模块不得绕过原有安全校验或产生循环依赖。

### 场景：兼容 CLI 保持一致

- 前置条件：调用 `inspect`、`capture-plan`、`start-*`、`complete-*` 或 `repair-gate`。
- 当：使用相同参数和 fixture 执行重构后的入口。
- 则：JSON 输出、写入/预览行为、错误文案和退出状态与基线一致。
- 并且：直接运行检测仍只在入口作为主模块时触发。
- 异常或边界：非法路径、未知参数、覆盖冲突和不可信适配器继续失败关闭。

### 场景：测试入口保持可追溯

- 前置条件：历史需求和开发命令引用 `tests/ui-review-automation.test.mjs`。
- 当：执行原聚焦测试命令。
- 则：聚合入口加载全部 30 个既有测试且名称不变。
- 并且：共享 fixture 只有一个事实源，领域测试文件职责明确。
- 异常或边界：子目录测试单元不能被默认测试发现重复执行。

### 场景：模块规模受控

- 前置条件：重构后的生产和测试文件完成拆分。
- 当：结构校验统计行数和入口导出。
- 则：兼容门面与测试聚合入口满足较小上限，领域模块均不超过 500 行。
- 并且：后续功能应进入对应模块而不是重新堆回门面。
- 异常或边界：不得通过压缩代码、移除中文错误说明或合并多条语句规避行数约束。

## 兼容性与风险

- 受影响页面、公共组件、路由、权限或接口：不涉及业务页面；影响插件内部公共 ESM 入口和细粒度 CLI。
- 历史数据与兼容策略：原入口、公开导出和测试入口路径保持不变，既有运行状态继续可读。
- 上线与回滚注意事项：重构可以按文件回退；不得与新功能或格式迁移混合。
- 主要风险：拆分时形成循环依赖、遗漏私有 helper、改变对象规范化顺序、重复发现测试或直接运行检测失效。
