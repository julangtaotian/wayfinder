# REQ-2026-022：仓库提交过滤与插件健康审查

## 基本信息

- 状态：已验收
- 提出人：用户
- 负责人：Codex
- 目标版本：0.13.0
- 关联页面或模块：根 `.gitignore`、插件发布边界、仓库验证、维护性审查
- 关联变更：`harden-repository-ignore-policy`

## 背景与目标

仓库已忽略 `.DS_Store`、IDE 配置、普通 `node_modules`、覆盖率和日志，并通过例外规则纳管插件内置 OpenSpec 与 Playwright 运行时。当前工作区没有未分类的未跟踪文件，但 OpenSpec 的 `node_modules/.bin/` 会被运行时例外重新纳入，未来安装或重建运行时时可能把可重建命令链接误带入提交；环境文件、常见测试报告、包管理器缓存和编辑器临时文件也缺少统一过滤。

本需求在不移除任何现有受管资产的前提下完善提交过滤，并对插件体积、发布方式和维护热点形成分级审查结论。过滤规则必须保留离线运行时、LFS 浏览器资产、验收证据、需求、规格和归档变更，且能够由自动测试证明关键忽略与反忽略边界。

## 范围

### 包含

- 审查当前 Git 状态、已忽略文件、未跟踪文件、受管大文件、LFS、插件结构和维护热点。
- 重构根 `.gitignore` 的分组与说明，补充环境、本机、编辑器、缓存、临时文件和测试报告规则。
- 修复 OpenSpec 内置运行时 `.bin/` 可能被重新纳管的例外漏洞。
- 移除已经受 Git 跟踪、但不参与运行时入口或完整性校验的 OpenSpec `.bin/node-which` 与 `.bin/yaml` 可重建链接。
- 保持 OpenSpec、Playwright、平台资产、验证证据和生成交付物的现有跟踪语义。
- 新增确定性的仓库卫生测试，覆盖关键忽略与反忽略样例。
- 输出插件后续优化建议及其优先级，不在同一变更中扩大实现范围。

### 不包含

- 删除或取消跟踪任何生产依赖、锁文件、许可证、完整性清单、平台资产或持久验收证据；只允许移除范围内两个可重建 `.bin` 链接。
- 把离线 Chromium、OpenSpec 运行时或验收证据迁移到新的下载服务、Release 或制品仓库。
- 拆分 `ui-review-workflow.mjs`、大型测试或其他业务模块。
- 修改 marketplace、插件 manifest、功能版本或已安装缓存。
- 忽略全部 `dist/`、`build/`、`outputs/`、`.frontend-ui-review/`、`openspec/` 或 `requirements/`。

## 当前行为

- 当前工作区干净；出现的 `.DS_Store`、`.idea/`、输出工程 `node_modules` 和 Playwright `.bin/` 已被过滤。
- 根 `.gitignore` 仅覆盖 macOS、IDE、依赖、Playwright `.bin`、覆盖率和日志。
- OpenSpec `node_modules` 被完整反忽略，`.bin/` 没有二次过滤。
- OpenSpec `.bin/node-which` 与 `.bin/yaml` 已受 Git 跟踪；Playwright `node_modules/.DS_Store` 会被运行时反忽略规则重新放行。
- 环境文件、Windows 元数据、VS Code 本机配置、包管理器缓存、通用构建缓存和测试报告尚未统一过滤。
- Playwright 平台运行时约 482.7 MiB，但已使用 Git LFS；`outputs` 中约 64.1 MiB 为现有验收证据。
- `ui-review-workflow.mjs` 与三份核心测试文件超过千行，是维护性热点，但没有本次过滤变更必须同时解决的正确性问题。

## 期望行为

### 场景：过滤本机与敏感文件

- 前置条件：开发者在任意子目录生成环境文件、编辑器配置、系统元数据、缓存或临时文件。
- 当：Git 计算工作区状态。
- 则：这些可重建或本机专属文件不进入候选提交。
- 并且：公开环境模板仍可进入版本控制。
- 异常或边界：不得使用宽泛后缀或目录规则误排业务源码、发布说明或验收证据。

### 场景：保留内置离线运行时

- 前置条件：插件依赖仓库内置 OpenSpec、Playwright 生产依赖和两套平台资产离线执行。
- 当：Git 应用普通 `node_modules/` 忽略规则和运行时例外。
- 则：运行时包文件、许可证、锁文件、完整性清单和 LFS 平台资产继续可提交。
- 并且：两套运行时的 `.bin/`、`.DS_Store` 与缓存仍被过滤。
- 异常或边界：新增生产依赖文件不能因为父级 `node_modules/` 规则被静默忽略。
- 异常或边界：已经受跟踪但不参与交付的 `.bin` 链接必须从仓库移除，否则新增忽略规则无法阻止其继续上传。

### 场景：保留持久验收证据

- 前置条件：仓库已有 UI 复验运行记录、输出规范、截图与 OpenSpec 归档。
- 当：提交过滤规则升级。
- 则：当前已跟踪证据和规划资产保持受管，测试可继续读取。
- 并且：通用 Playwright 报告和测试临时结果被过滤。
- 异常或边界：`.frontend-ui-review/runs` 不能因通用报告规则被误排。

### 场景：形成可执行优化清单

- 前置条件：插件同时包含离线运行时、跨平台浏览器、长脚本和大量验收证据。
- 当：完成仓库健康审查。
- 则：报告区分本次立即修复、值得后续独立立项和基于产品约束暂不调整的项目。
- 并且：每项结论包含仓库证据和权衡，不把体积大直接等同于冗余。
- 异常或边界：未经独立需求和迁移验证，不删除 LFS、运行时或持久证据。

## 兼容性与风险

- 受影响页面、公共组件、路由、权限或接口：不涉及业务页面；影响 Git 候选提交范围和仓库开发体验。
- 历史数据与兼容策略：仅移除两个不参与入口或完整性校验的 OpenSpec `.bin` 命令链接；对生产运行时和所有持久交付路径建立反忽略与索引断言。
- 上线与回滚注意事项：规则变更可通过回退 `.gitignore` 恢复；实施前后对同一组样例运行 `git check-ignore`。
- 主要风险：宽泛缓存、编辑器或构建目录规则误排未来需要共享的配置；运行时例外顺序错误导致生产依赖无法添加。
