# REQ-2026-019：AI UI 验收标注截图与节点报告

## 基本信息

- 状态：已验收
- 提出人：用户
- 负责人：Codex
- 目标版本：当前开发迭代
- 关联页面或模块：`outputs/lanhu-design-spec/validation-tools/`、`outputs/lanhu-design-spec/validation-element-plus/`、`outputs/lanhu-design-spec/validation-element-ui/`、`outputs/lanhu-design-spec/ai-ui-review/`
- 关联变更：`add-ai-ui-review-artifacts`、`enhance-ai-ui-review-source-guidance`、`fix-ai-ui-review-ci-portability`

## 背景与目标

现有蓝湖 UI 还原验收已经保留大量参考图、实际图和对照图，但设计验收仍依赖人工逐项观察，问题也没有稳定映射到页面 DOM 节点。用户希望由 AI 完成视觉验收：AI 读取设计规范或参考设计与真实运行页面，识别高置信度的颜色、字体、字号、尺寸、间距等差异，并直接输出可查看的标注截图以及一份可供 AI 或开发人员执行的 Markdown。

本需求先在 `outputs/lanhu-design-spec/` 内落地最小闭环，并分别用现有 Vue 3 + Element Plus、Vue 2 + Element UI 项目生成真实验收结果。每个项目的交付物固定为一张 `ui-review.png` 和一份 `ui-review.md`；原始截图、DOM 快照和中间数据只作为临时输入，不进入交付目录。

## 范围

### 包含

- 新增可复用的验收产物生成器，接收 AI 给出的页面信息、节点定位、截图坐标和问题结论。
- 校验问题编号、置信度、节点选择器、坐标、当前值、目标值和修改要求，拒绝无法定位的交付问题。
- 在实际页面截图上绘制编号、边框、短标签和整体结论。
- 生成与截图编号一一对应的 Markdown，零问题时输出明确的通过结论与覆盖范围。
- 为每个交付问题生成可直接指导 AI 落到源码的修复上下文与复验步骤，不额外增加交付文件。
- 分别运行两个现有组件库项目，并在 `1440 × 900` 视口生成真实结果。
- 增加聚焦测试，验证两文件约束、节点字段、问题上限、低置信度过滤和零问题行为。

### 不包含

- 接入第三方大模型 API、蓝湖 API、Figma API 或远程发布服务。
- 修改两个组件库项目的业务 UI，或为了展示标注而故意制造视觉问题。
- 代替完整的 183 场景回归矩阵；首轮结果只声明实际打开和检查的页面范围。
- 将临时原始截图、DOM 全量快照、AI 推理过程或机器中间 JSON 保存为交付文件。
- 自动修改被验收项目源码。
- 把源码行号作为唯一定位依据，或允许报告引导 AI 修改 `node_modules`、组件库上游源码和未声明的全局样式。

## 当前行为

- 两套项目存在 `data-scenario-id`、`data-component-id` 和组件库标识，可定位到场景卡片，但当前没有面向 AI 的两文件验收产物生成入口。
- 历史证据目录包含大量参考、实际、状态和对照图片，不符合本需求的精简交付方式。
- 现有报告能够描述场景是否通过，但不能在单张实际页面截图上把问题编号与具体 DOM 节点关联起来。

## 期望行为

### 场景：AI 发现高置信度视觉差异

- 前置条件：AI 已打开真实页面，获得当前截图、目标设计规则、目标节点选择器和可见坐标。
- 当：AI 提交一到十条高置信度问题给验收产物生成器。
- 则：生成的 `ui-review.png` 在对应节点位置显示同号边框和短标签。
- 并且：`ui-review.md` 使用相同编号记录稳定节点、页面位置、当前值、目标值和可执行修改要求。
- 异常或边界：低置信度问题被过滤；超过十条、编号重复、坐标越界或缺少节点定位时生成失败，不产生半成品交付物。

### 场景：AI 未发现高置信度差异

- 前置条件：AI 已按声明的页面、视口和规范范围完成检查。
- 当：AI 提交零条问题。
- 则：截图显示“AI 验收通过”状态且没有伪造的问题框。
- 并且：Markdown 明确问题数为 0、覆盖范围、节点定位方式和“未发现高置信度差异”的有限结论。
- 异常或边界：该结论不扩大为未检查页面、状态或视口也全部通过。

### 场景：分别验收两个组件库项目

- 前置条件：两套项目可以在本地构建并打开指定页面。
- 当：AI 在相同 `1440 × 900` 视口检查 Element Plus 与 Element UI 项目。
- 则：两个项目目录各自只包含 `ui-review.png` 和 `ui-review.md`。
- 并且：两份报告分别记录项目、运行时、页面入口、视口和实际节点证据，不混用结论。
- 异常或边界：任一项目无法启动或截图时，该项目不得生成“通过”报告。

### 场景：AI 根据报告定位源码并准备修复

- 前置条件：问题已映射到真实 DOM 节点，并且 AI 验收过程能够读取被验收仓库源码。
- 当：生成器输出有问题的 `ui-review.md`。
- 则：每个问题同时提供仓库相对源码文件与稳定代码锚点，AI 无需仅凭 DOM 选择器猜测文件。
- 并且：报告明确当前样式来源、建议修改、允许作用域、禁止修改范围，以及复验工作目录、命令、页面和可观察断言。
- 异常或边界：源码路径必须是仓库相对路径且不能包含 `..`；修复上下文缺失、锚点缺失或复验断言为空时生成失败，不产生不完整报告。

## 页面与交互

- 入口与操作路径：启动对应项目，打开本次声明的组件场景页面，由 AI 读取实际 DOM 与计算样式后生成验收产物。
- 字段、文案与默认值：截图使用编号和短标签；Markdown 使用项目、页面、视口、结论、节点、问题、当前值、目标值、源码目标、稳定锚点、样式来源、精确修改、作用域、禁止修改范围、复验步骤和置信度。
- 加载态、空态、错误态、禁用态：页面未完成渲染属于采集错误；零问题属于有效空态；生成器输入错误必须输出中文错误并避免半成品。
- 权限与角色差异：本地静态验收项目不涉及登录和业务权限。
- 设计稿链接：使用 `outputs/lanhu-design-spec/` 下规范与已保存的本地参考证据，不新增外部依赖。

## 接口与数据

- 接口文档链接：不涉及网络接口。
- 请求方法与路径：生成器读取本地截图和 AI 提供的结构化验收输入；真实页面采集由当前 AI 浏览器会话完成。
- 请求字段及空值语义：`findings: []` 表示本次声明范围内没有高置信度问题；不表示所有页面和状态均无差异。
- 响应字段及状态码：成功时输出 PNG 和 Markdown 路径；失败时非零退出并输出中文错误。
- 鉴权、加解密或敏感信息要求：不读取认证信息，不在报告中保存 Cookie、存储数据、完整 DOM 或用户敏感值。

## 兼容性与风险

- 受影响页面、公共组件、路由、权限或接口：不修改两套项目页面行为，只新增验证工具、聚焦测试和独立结果目录。
- 历史数据与兼容策略：保留现有 `validation-evidence/` 历史证据；新两文件结果不替换 183 场景矩阵。
- 上线与回滚注意事项：正式截图标注仍依赖运行环境提供可用 FFmpeg 和中文字体，缺失时应明确失败；自动测试的输入图片不得依赖固定操作系统路径。AI 判断仍可能受字体渲染和抗锯齿影响，因此只交付高置信度差异并声明覆盖范围。
