# REQ-2026-005：OpenSpec 1.7.0 受控升级

## 基本信息

- 状态：已验收
- 提出人：用户
- 负责人：AI 协作实施
- 目标版本：0.10.0
- 关联页面或模块：内置 OpenSpec 运行时、规划状态、实施指令、完成门禁、规格同步与归档
- 关联变更：`upgrade-openspec-1-7`

## 背景与目标

插件当前固定内置 OpenSpec 1.6.0。OpenSpec 1.7.0 新增无规格变更元数据、apply/archive 动态操作输入、嵌套规格目录、默认 Store 和日期或数字前缀变更名，并增强归档同步、Markdown 解析与 Codex Skill 交付。

本需求在保持插件固定内置运行时、默认只读、需求事实源、严格完成门禁和不覆盖业务内容的前提下升级到 1.7.0，并让插件显式理解新状态与新路径，避免仅替换版本后产生静默兼容偏差。

## 范围

### 包含

- 替换插件内置 OpenSpec 1.6.0 为精确固定的 1.7.0 生产运行时。
- 更新运行时版本、第三方声明、插件版本和受管项目元数据。
- 接入 artifact `skipped`、`skip_specs`、apply/archive 动态操作输入。
- 修复数字或日期前缀变更名、归档目标预检和需求关联匹配。
- 兼容嵌套规格路径、可选 archive warnings 和机器默认 Store 来源。
- 三方合并 OpenSpec 1.7.0 内部参考，同时保留插件需求治理与完成硬门禁。
- 扩展端到端测试、严格规格校验和已安装插件运行时验证。

### 不包含

- 调用全局安装、全局 `openspec update` 或自动升级用户机器上的 OpenSpec。
- 在业务项目中生成 OpenSpec 自带的 Codex Skill 或命令文件。
- 自动迁移历史变更名、历史规格目录或历史需求业务事实。
- 新增 React、Angular、Svelte 或 Monorepo 专项适配。
- 放宽未完成任务、未通过验收、无证据或严格校验失败时的归档阻断。

## 当前行为

- [plugins/frontend-ai-workflow/scripts/openspec-cli.mjs](../plugins/frontend-ai-workflow/scripts/openspec-cli.mjs) 固定版本为 1.6.0。
- 完成检查只确认 `status` 命令退出成功，没有验证 `planningStatus.isComplete` 和每个 artifact 状态。
- 归档目标预检总是增加当天日期，与 1.7.0 已有日期前缀保持原名的规则不一致。
- 需求关联校验无条件剥离目录名的首个日期前缀，可能误判原本就以日期开头的变更。
- 实施参考读取 apply instructions，但尚未处理新增的 context 和 operationGuidance；完成预览没有读取 archive instructions。
- 内部参考及第三方声明仍标记为 OpenSpec 1.6.0。

## 期望行为

### 场景：在不改变项目事实的前提下升级运行时

- 前置条件：插件源码和已有 OpenSpec 1.6.0 项目数据保持不变。
- 当：将内置运行时升级到 1.7.0 并运行严格校验。
- 则：现有变更、规格、状态和归档结果继续可读，现有严格校验全部通过。
- 并且：插件只调用内置 1.7.0，不探测或调用全局 OpenSpec。
- 异常或边界：临时包、生产依赖、版本、入口或许可证核验失败时停止替换，保留原运行时。

### 场景：完成普通或无规格变更

- 前置条件：需求、任务、验证和 OpenSpec artifact 已达到对应完成状态。
- 当：执行完成预览或显式归档。
- 则：普通变更完成规格同步；合法 `skip_specs: true` 变更允许 specs artifact 为 `skipped` 且不产生规格写入。
- 并且：`ready`、`blocked`、未知状态、滥用 skip_specs、未完成任务或严格校验失败均阻断归档。
- 异常或边界：用户确认不能覆盖任何硬门禁，完成脚本不接受 `--skip-specs` 或 `--no-validate`。

### 场景：使用新命名、嵌套规格和操作输入

- 前置条件：变更名可能带数字或完整日期前缀，规格可能位于嵌套目录，项目配置可能包含 operations guidance。
- 当：实施、检查、同步或归档该变更。
- 则：使用运行时返回的具体路径，归档目标不叠加日期，需求关联优先按完整变更名匹配。
- 并且：apply/archive context 与 guidance 被报告和考虑，但不能改写需求事实、已选择根目录或完成门禁。
- 异常或边界：未明确选择的 `global_default` Store 被阻断，不允许静默把本地工作写入机器级规划根。

### 场景：升级已有业务项目的受管工作流

- 前置条件：项目已由旧版插件初始化，可能含自定义 AGENTS、Wayfinder、需求和 OpenSpec 内容。
- 当：预览或显式执行插件工作流升级。
- 则：预览保持只读；显式写入仅替换受管区块并记录 OpenSpec 1.7.0。
- 并且：项目自定义内容、历史需求、历史变更与规格保持不变。
- 异常或边界：无受管标记的文件继续跳过并报告冲突，不自动接管。

## 兼容性与风险

- 受影响页面、公共组件、路由、权限或接口：不涉及业务页面；影响所有使用插件规划、检查、同步、归档和升级的项目。
- 历史数据与兼容策略：使用 1.7.0 对当前仓库进行影子严格校验；旧变更和旧规格不自动改写。
- 上线与回滚注意事项：运行时先在临时目录组装和验证，替换失败保留 1.6.0；发布后通过插件 cachebuster 重装，新任务验证。
- 主要风险：错误接受 `skipped` 可能隐藏行为变更；默认 Store 可能改变写入根；直接覆盖内部参考可能丢失插件硬门禁。
