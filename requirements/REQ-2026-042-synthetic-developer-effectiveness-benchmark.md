## 背景与目标

仓库已经具备工程门禁、真实项目识别和工作流生命周期验证，但尚不能用可重复数据回答插件是否降低返工、缩短交付时间或提高一次验收通过率。现有历史需求缺少完整起止时间、澄清次数和返工记录，不能据此补造效果数据。

本需求建立一套受控的合成基准：从三个真实前端项目的已提交 Git 基线生成六个模拟需求，在相同基线、相同模型配置和相同验收标准下分别运行插件组与不使用插件的对照组，自动采集十二次隔离执行的数据和证据。结果只用于评价模拟任务中的相对表现和校验采集链路，不替代真实开发者研究。

## 范围

### 包含

- 提供通用、可重复执行的基准编排入口，运行时接收项目路径，不把开发机绝对路径写入仓库代码、配置、文档或持久证据。
- 固定并校验项目 ID、分支、40 位提交、任务 ID、模型配置、时间预算、运行顺序和每组执行模式。
- 从只读业务仓库的已提交基线创建隔离工作区，并在运行前后证明源仓库状态未变化。
- 为每个项目生成两个可实现、可自动验收且不依赖真实账号的模拟需求，整体覆盖小型、中型和大型任务。
- 为插件组准备工作流基线，并把初始化时间与单任务交付时间分开记录。
- 以非交互子进程运行插件组和对照组，保存经过脱敏和限长的结构化事件、退出状态、提交差异和验收结果。
- 生成稳定 JSON 汇总、逐次运行清单以及可导入现有开发者指标工作簿的数据文件。
- 支持预览、显式写入、失败恢复、有界清理和重复运行保护。
- 为跨平台路径、子进程失败、超时、信号中断、敏感输出和不完整样本建立确定性回归。

### 不包含

- 不修改、提交、推送或创建业务仓库的分支和工作树内容。
- 不把模拟数据解释为真实开发者数据，不进行个人排名或绩效评价。
- 不在第一轮自动购买额度、扩展 Codex 权限、连接第三方账号或触发远程 CI。
- 不承诺自动判断所有语义性误阻断；无确定性反证的情况保留人工复核。
- 不在第一轮覆盖 Monorepo、多前端递归编排、生产接口或真实设备验收。
- 不把运行产生的业务源码副本、依赖、日志或凭据提交进 Git。

## 当前行为

- `real-project-validation.mjs` 能固定真实项目 Git 基线、建立隔离副本并证明业务源目录未变化，但它只验证识别、工作流生命周期和项目原生命令，不运行成对的需求实现实验。
- `outputs/developer-metrics-pilot/developer-effectiveness-pilot.xlsx` 已定义指标和样本门槛，但目前两个历史条目因数据不完整被正确标记为无效样本。
- 仓库没有模拟需求清单、插件与对照组编排入口、统一运行事件协议或从运行证据生成指标记录的机制。

## 期望行为

### 场景：预览第一轮基准

- 前置条件：传入三个可读取的 Git 项目路径，项目存在 `package.json` 且能够解析当前分支和提交。
- 当：使用默认预览模式启动基准。
- 则：输出经过校验的项目别名、提交、预计任务数、预计运行数、输出相对位置、模型参数和风险提示。
- 并且：不创建工作区、不调用 Codex、不改变业务项目或已有输出。
- 异常或边界：项目路径危险、不是独立 Git 根、提交或工作区状态摘要在运行期间漂移、配置不完整时，以稳定错误码失败关闭；运行前已经存在但始终不变的未提交内容只记录为被排除事实。

### 场景：生成并冻结六个模拟需求

- 前置条件：预览通过，并显式要求写入；三个源项目在生成期间保持已记录基线。
- 当：基准生成器为每个项目创建两个候选需求并完成可执行性预检。
- 则：得到六个包含公开需求、复杂度、允许验证命令、受控初始补丁和独立验收入口的冻结用例。
- 并且：执行代理看不到隐藏验收实现和另一组结果；不满足自动验收条件的候选必须被替换或以稳定状态阻断整轮运行。
- 异常或边界：零用例、重复任务 ID、验收命令越界或需求依赖外部账号时不得进入执行组。

### 场景：成对执行插件组与对照组

- 前置条件：六个冻结用例通过预检，每个配对运行能从同一提交与同一受控初始补丁建立独立工作区。
- 当：编排器按清单逐项运行十二次任务。
- 则：插件组明确记录实际走快速通道或完整通道，对照组记录为 `baseline`，两组共享模型、推理强度、时间预算和验收器。
- 并且：任一运行不能读取另一运行的工作区、日志、差异或结果；一次失败不覆盖已完成证据。
- 异常或边界：启动失败、超时、非零退出、零改动、敏感输出、磁盘不足或用户中断均以独立状态保存，并进入安全清理路径。

### 场景：自动验收并生成指标

- 前置条件：某次执行进程结束并保存结构化事件。
- 当：独立验收器在执行工作区运行。
- 则：系统记录首次交付时长、总周期、澄清、返工、阻断、误阻断候选、首次验收、最终验收、改动统计和证据摘要。
- 并且：缺少必填字段、验收未完成或证据不完整时标记为无效样本，不补零、不推断通过。
- 异常或边界：验收器自身启动失败必须与业务断言失败分开分类。

### 场景：汇总合成基准

- 前置条件：整轮十二次运行均已结束、阻断或被安全中断。
- 当：生成本轮汇总。
- 则：按项目、复杂度和执行组输出有效样本、一次验收通过率、平均首次交付时长、平均总周期、平均返工、澄清和误阻断候选率。
- 并且：报告显著标记为合成基准，列出无效样本和限制，并生成可导入现有工作簿的稳定数据文件。
- 异常或边界：有效配对不足时只报告采集状态，不给出插件优劣结论。

## 页面与交互

- 入口与操作路径：命令行预览；显式 `--write` 后依次执行生成、预检、配对运行、验收、汇总和清理。
- 字段、文案与默认值：机器字段使用稳定英文；错误信息和人类摘要使用中文；默认只预览、默认不保留工作区。
- 加载态、空态、错误态、禁用态：长任务持续输出结构化阶段事件；空项目、空用例和无效配置失败关闭；运行失败不阻止其他已安全隔离的运行留下证据。
- 权限与角色差异：没有角色权限差异；调用 Codex 所需账号和额度沿用当前用户环境，不自动提升权限。
- 设计稿链接：不适用，当前变更没有图形界面。

## 接口与数据

- 接口文档链接：不适用；本需求新增本地命令行和 JSON schema。
- 请求方法与路径：命令行接收项目路径、运行 ID、模型、推理强度、时间预算和输出根；持久清单只保存项目别名、分支、提交和仓库相对证据路径。

## 兼容性与风险

- 受影响页面、公共组件、路由、权限或接口：不影响业务页面；新增仓库开发工具入口、子进程执行链、证据 schema 和测试分组。
- 历史数据与兼容策略：现有工作簿和真实项目矩阵保持可读；模拟运行使用独立 schema 与输出目录，不重写历史条目。
- 上线与回滚注意事项：新入口默认只预览且不进入普通 `npm test` 的真实代理运行；删除新增入口和独立输出即可回滚，业务项目不需要回滚。
- 跨平台高风险：是。
- 命中项：CI、路径、临时目录、子进程、环境变量、机器可读诊断。
- 受影响平台：darwin-arm64、darwin-x64、linux-x64、linux-arm64、win32-x64。
- 对应回归：复用 `tests/developer-effectiveness-benchmark.test.mjs`，覆盖双侧路径规范化、LF/CRLF 源码语义、非 shell 子进程、空格与非 ASCII 路径、环境隔离、退出码、超时、敏感输出、恢复和清理。
- 外部证据：提交 `87433d4bced36109de03ecb8470fce91e59d4208` 的五平台 CI 已运行，但 win32-x64 因 TC-02 将 CRLF 与 LF 直接严格比较而失败；本机模拟结果不能替代修复提交的矩阵复跑证据。
- 主要偏差风险：需求生成器与执行代理可能来自同类模型；报告必须保留此限制，不能把结果推广到人类开发者。
