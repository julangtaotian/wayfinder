## 背景与目标

OpenSpec 历史和 outputs 已完成轻量化治理，但根 `AGENTS.md`、`README.md`、`.gitignore`、项目级 UI Review 配置及各顶层目录的职责尚未形成一份完整、一致、可回归的仓库合同。当前 `.gitignore` 仍按旧 outputs 主题维护多条规则，根 `.frontend-ui-review/config.json` 还引用已经不存在的 `outputs/lanhu-design-spec/...` 页面与设计证据。

本需求要求建立单一、可维护的仓库职责地图，删除已失效且不可复现的根项目配置，统一 outputs 退役边界，并用自动测试防止职责说明、忽略规则和实际结构再次漂移。

## 范围

### 包含

- 梳理并调整根 `README.md`、`AGENTS.md`、`.gitignore`。
- 覆盖 `.agents`、`.github`、`.workflow-history`、`design`、`openspec`、`plugins`、`requirements`、`scripts`、`tests`、本地 `dist`、`outputs` 和 `.frontend-ai-workflow` 的职责、生命周期与必要性。
- 删除引用已退役 outputs 路径的根 UI Review 配置和适配器。
- 更新仓库卫生自动测试，验证统一 outputs 忽略、职责地图完整性和失效项目配置退役。
- 为仓库卫生规格增加对应增量合同。

### 不包含

- 删除本地被忽略的 outputs、dist、缓存、截图或用户未跟踪文件。
- 重写插件各 Skill、reference、正式规格或设计规范的正文。
- 改变插件公开命令、业务项目 UI Review 流程、OpenSpec 运行时或平台打包实现。
- 本轮直接合并主分支、提交代码或触发远端五平台 CI。

## 当前行为

- 根 `README.md` 详细说明插件能力和使用方式，但没有覆盖仓库自身全部顶层目录及必要性的维护地图。
- `AGENTS.md` 只列出部分结构职责，未明确根文件、项目级配置、测试与本地成品边界。
- `.gitignore` 为多个旧 outputs 主题维护单独规则，没有统一 `/outputs/` 退役规则。
- 根 UI Review 配置引用的页面、源码和图片已经不存在，克隆后的仓库无法执行这些场景。
- 仓库卫生测试仍把该失效配置列为必须跟踪的关键交付文件。

## 期望行为

### 场景：维护者定位文件和目录职责

- 前置条件：维护者打开根 `README.md` 或 AI 读取根 `AGENTS.md`。
- 当：需要判断一个目录放什么、是否长期保留、应从哪里修改或验证。
- 则：能够从单一职责地图得到明确答案。
- 并且：README 与 AGENTS 分工清楚，不复制大段相同内容。
- 异常或边界：本地临时目录和退役目录必须标为不进入 Git，而不是被误认为仓库正式源码。

### 场景：运行内容写入旧 outputs

- 前置条件：本地工具或旧流程在根 `outputs/` 下生成任意文件。
- 当：Git 计算候选提交。
- 则：整个根 outputs 目录被统一忽略。
- 并且：体积门禁继续以零上限拒绝强制加入 Git 的 outputs 文件。
- 异常或边界：`design/`、`.workflow-history/` 和 `openspec/specs/` 不得被该规则误忽略。

### 场景：仓库没有可复现的根 UI Review 项目

- 前置条件：根 UI Review 配置的页面与设计输入均已退役。
- 当：维护者检出仓库或运行仓库治理检查。
- 则：仓库不再携带指向缺失文件的项目配置和适配器。
- 并且：插件内的 UI Review 模板、脚本和测试 fixture 保持完整。
- 异常或边界：未来新增真实项目级 UI Review 时，应基于当前模板和有效项目事实重新创建配置。

## 兼容性与风险

- 受影响页面、公共组件、路由、权限或接口：无业务页面和公开接口变化；影响仓库维护者、Git 候选提交和项目级 UI Review 默认配置。
