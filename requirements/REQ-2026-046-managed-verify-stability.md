# REQ-2026-046：受管 Verify 一次通过与语义绑定稳定性

## 基本信息

- 状态：实施中
- 提出人：用户
- 负责人：Codex
- 目标版本：0.18.x
- 关联页面或模块：`frontend-test`、受管 Verify、机器证据语义绑定、测试方案完成门禁
- 关联变更：`stabilize-managed-verify`

## 背景与目标

当前版本的受管 Verify 可以在最终阶段形成有效机器证据并通过完成门禁，但 2026-09-10 的真实行为复验再次出现首轮 `stale_semantic_evidence`：证据生成后，模型把命令、定位命中和运行统计补入需求验证记录的“执行内容或环境”列，现有语义指纹把这类运行说明也视为不可变测试语义，导致完成校验拒绝证据。模型随后读取三个校验器实现文件、恢复该列并再次校验才通过。

本需求要求把“验证目标语义”和“执行结果说明”分离：新的本地证据绑定只保护决策、验收、断言、测试用例、聚焦命令和需求修订等会改变验证含义的字段；测试成功后补充日期、结果、证据路径、验收勾选、用例结果和运行说明不应使同一次证据过期。旧版绑定继续按原算法复算，不能因升级而批量失效。正常受管 Verify 应在不读取校验器源码的情况下完成一次执行、一次记录更新和一次完成校验。

## 范围

### 包含

- 为语义快照增加可版本化字段选择，使 v2 排除验证后的运行结果说明。
- 在证据校验时按清单记录的绑定版本复算，兼容 v1 并拒绝未知版本。
- 更新受管 Verify 指南，明确验证后可改字段、不可改字段和一次完成校验路径。
- 增加真实顺序回归：生成证据、补写验证结果和说明、一次 complete 校验通过。
- 增加 v1 兼容、v2 真语义漂移和结构化诊断回归。

### 不包含

- 不改变退出码、定位命中、工作区指纹、日志和证据文件完整性门禁。
- 不让证据入口自动编辑需求或测试方案，也不合并 Verify 与 Complete 阶段。
- 不自动迁移、重写或重新执行历史证据。
- 不修改业务项目测试、安装测试依赖或扩大 Vue 3 + Vite + Vitest 以外的认证范围。
- 不替代真实五平台 CI；本地模拟只证明确定性逻辑。

## 当前行为

- `computeVerificationSemanticBinding` 固定生成 `semanticSchemaVersion: 1`，并把验证记录的“执行内容或环境”纳入哈希。
- 机器证据在测试执行前计算绑定，执行成功后将该绑定写入清单。
- 受管 Verify 指南允许把命令摘要和定位次数写入“执行内容或环境”，同时又要求证据生成后才能把 V-* 和 TC-* 标为通过。
- 因此模型按指南补充运行事实后，complete 校验会认为证据语义已变化；恢复依赖理解内部哈希字段，真实复验中导致源码回读和第二次校验。

## 期望行为

### 场景：成功执行后补写验证结果

- 前置条件：活动变更启用严格机器证据，需求、测试方案和聚焦命令已通过 implement 门禁。
- 当：证据入口成功执行聚焦命令并生成 v2 清单，随后更新 V-* 日期、结果、证据路径、运行说明、验收勾选和 TC-* 状态、结果、证据。
- 则：语义绑定保持新鲜，第一次 complete 校验通过。
- 并且：清单中的真实 argv、退出码、定位命中、日志和工作区指纹仍被完整复算。
- 异常或边界：运行说明不能代替清单字段，也不能把失败命令写成通过。

### 场景：验证目标发生真实变化

- 前置条件：已经生成 v2 通过证据。
- 当：修改关联决策、验收文本、映射断言、测试操作、目标测试、定位、聚焦命令、关联关系或新增需求修订。
- 则：证据校验返回 `stale_semantic_evidence`，`fresh: false`、`semanticFresh: false`，完成门禁失败。
- 并且：不得自动复用旧证据或通过修改结果说明绕过失败。
- 异常或边界：只改变 Markdown 排版或独立复验说明时不应误报真实语义变化。

### 场景：读取历史 v1 证据

- 前置条件：仓库存在按旧字段集合生成的合法 v1 语义绑定。
- 当：当前校验器读取并复算该清单。
- 则：使用 v1 算法验证，包括原来的“执行内容或环境”字段；内容未变时保持有效。
- 并且：该兼容不改变清单，不生成 v2 替代品。
- 异常或边界：v1 对应字段变化仍判旧，未知绑定版本返回稳定失败。

### 场景：Verify 路径遇到已知诊断

- 前置条件：CLI 返回带 `code`、`status`、`target` 和绑定版本的结构化诊断。
- 当：模型处理正常通过或已知语义过期结果。
- 则：依据公开工作流合同和结构化字段完成记录或报告阻断，不读取校验器实现源码。
- 并且：只有结构字段缺失、互相矛盾或出现未知故障时才进入实现级诊断。
- 异常或边界：禁止通过忽略完成门禁、直接篡改清单或重复运行无关测试来恢复。

## 兼容性与风险

- 受影响页面、公共组件、路由、权限或接口：不影响业务 UI；影响所有严格受管 Verify 的证据生成与完成校验。
- 历史数据与兼容策略：v1 按旧算法复算，v2 按新稳定字段集合复算；不改写归档 JSON。
- 上线与回滚注意事项：生成器和校验器必须同时发布。回滚代码后，新 v2 绑定会成为未知版本，因此发布前必须完成兼容校验；不能只回滚一侧。
- 跨平台高风险：是；命中子进程、路径、临时 outputs、机器可读诊断和 CI。受影响平台为仓库真实矩阵的 Linux x64/ARM64、Windows x64、macOS Intel/ARM64。
- 主要风险：排除字段过多会放松真实语义保护；版本分派错误会让旧证据失效；通过明确字段白名单、v1/v2 双路径回归和真实语义负例控制。
- 外部证据：真实五平台矩阵尚未运行，V-04 保持计划；本地通过不能替代同一提交矩阵。
