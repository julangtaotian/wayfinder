# REQ-2026-032：仓库持续瘦身与生命周期治理

## 基本信息

- 状态：实施中
- 提出人：用户
- 负责人：Codex
- 目标版本：0.18.0
- 关联页面或模块：仓库验证、需求完成归档、Playwright 平台运行时、历史蓝湖验收资产、测试组织与 CI
- 关联变更：`sustainable-repository-footprint`

## 背景与目标

上一轮已经通过精简健康检查、限定 AI 默认读取范围和清理可重建内容降低了上下文成本，但仓库仍保留约 1.3GB Playwright 五平台资产、约 1.2GB 本地 Git LFS 对象、67MB/1661 个跟踪文件的蓝湖设计验收目录，以及 31 份已经验收但仍位于活跃需求入口的完整历史需求。部分综合测试和脚本也接近或超过 900～2100 行。

用户要求现在实施前述优化，并要求后续通过规划、生命周期动作和自动门禁阻止同类膨胀再次积累，不再依赖定期人工发起仓库瘦身。

## 范围

### 包含

- 退役蓝湖历史验证工程、图片证据和仓库专用 UI Review 原型，保留精简 AI 规范。
- 分层归档既有已验收需求，并让后续完成流程自动维护存根和目录索引。
- 增加仓库体积预算、退役路径和文件规模自动门禁，并接入本地统一验证与 CI。
- 拆分超大测试和脚本，增加可直接运行的聚焦测试入口。
- 将 CI 改为按矩阵平台拉取对应 Git LFS 资产，并补充轻量开发克隆说明。
- 同步受影响需求、主规格、README、AGENTS、版本和回归测试。

### 不包含

- 重写既有 Git 提交历史或从远端 Git LFS 删除当前发布资产。
- 新建或迁移到未经用户选择的 Release、对象存储或其他外部制品服务。
- 把本地模拟结果写成五平台真实 CI 已通过。
- 删除 `outputs/lanhu-ai-ui-spec/` 中仍作为最终 AI 输入的 Markdown 规范。
- 修改插件面向业务项目的 UI Review 功能语义。

## 当前行为

- `outputs/lanhu-design-spec/` 占用约 67MB，包含 1513 张 PNG，并被仓库专用测试和蓝湖主规格引用；插件正式运行代码不引用它。
- 31 份需求均已验收，但完整正文仍位于 `requirements/` 根目录；健康审计读取 31 份需求和 155 条验证记录。
- `.github/workflows/validate.yml` 使用 `lfs: true`，五个矩阵任务都会检出全部平台资产，再只构建一个目标平台。
- `tests/workflow.test.mjs` 为 2116 行，`tests/lanhu-ui-reconstruction.test.mjs` 为 2036 行；两个核心脚本接近千行。
- 仓库没有阻止 tracked outputs、完整历史需求和大文件重新增长的统一体积门禁。

## 期望行为

### 场景：完成一次需求

- 前置条件：需求和受管变更已通过完成门禁。
- 当：完成流程同步并归档变更。
- 则：完整需求被迁移到按年份分层的历史目录，根入口替换为轻量存根，目录索引同步刷新。
- 并且：归档后审计使用真实归档需求正文，恢复执行保持幂等。
- 异常或边界：任一写入或审计失败返回稳定部分失败状态和恢复参数，不产生第二份正文。

### 场景：AI 或检查器执行日常检查

- 前置条件：仓库存在历史需求、归档规划和持久证据。
- 当：执行默认精简检查或普通源码任务。
- 则：只读取活跃需求和轻量存根，不递归读取历史正文、蓝湖历史资产或无关平台二进制。
- 并且：显式历史审计仍可按 code 和分页定位归档内容。

### 场景：仓库重新出现膨胀

- 前置条件：新增受跟踪 outputs、退役路径、大型源码/测试或过多活跃完整需求。
- 当：运行聚焦体积审计或统一验证。
- 则：命令以非零状态失败并返回稳定 code、target、status、实际值和预算值。
- 并且：合理调整预算必须作为显式规划变更，不允许静默扩大阈值。

### 场景：五平台 CI 验证

- 前置条件：矩阵任务已经确定目标平台。
- 当：检出仓库并准备 Git LFS 资产。
- 则：只拉取该矩阵平台目录，完整性、冒烟和平台包仍使用真实文件执行。
- 并且：缺失文件、LFS 指针或平台不匹配必须失败。

## 页面与交互

- 入口与操作路径：仓库 CLI、需求完成流程、`npm` 验证脚本和 GitHub Actions；不涉及业务页面。
- 字段、文案与默认值：机器输出使用稳定英文 code/字段，中文消息用于人类诊断；默认只读，显式完成写入沿用现有 `--write`。
- 加载态、空态、错误态、禁用态：一次性 CLI 无加载界面；空仓库返回零计数；预算、路径、LFS 和归档错误失败关闭。
- 权限与角色差异：不新增权限模型；远端 CI 和 LFS 只使用仓库既有权限。
- 设计稿链接：不适用。

## 接口与数据

- 仓库体积审计返回版本化 JSON，至少包含 `schemaVersion`、`status`、`counts`、`budgets` 和 `diagnostics[]`；诊断包含 `code`、`status`、`target`、`actual`、`limit`。
- 需求目录索引记录稳定需求 ID、状态、根存根路径、归档正文路径、关联变更和内容指纹，不包含绝对路径或生成时间戳。
- 根需求存根保留标题、`已验收` 状态、规范化归档路径和关联变更，不复制完整决策、验证记录或证据正文。
- 历史审计使用显式参数启用，默认结果不得递归展开 `requirements/archive/`。
- CI 使用 Git LFS include/exclude 语义按 `matrix.platform` 取得 `plugins/frontend-ai-workflow/runtime/playwright/platform-assets/<platform>/`。

## 兼容性与风险

- 受影响链包含完成流程、需求路径、历史审计、统一验证、CI、平台资产准备和插件打包，属于共享工具链与发布级变更。
- 历史需求正文移动后必须保留根存根和稳定索引；旧文本引用保持可定位，不能用批量删除破坏追溯。
- 蓝湖重资产由 Git 历史可恢复；删除前必须先移除活动测试和主规格依赖，保留最终 AI 规范。
- CI 按平台拉取属于真实五平台高风险变更；本地只能提供确定性回归和当前平台证据，外部矩阵必须在精确提交上另行确认。
- Git LFS 当前对象不通过自动脚本从用户缓存删除；需要回收时只提供明确、可恢复的人工命令和影响说明。
