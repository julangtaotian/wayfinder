# REQ-2026-021：OpenSpec 1.8.0 受控升级

## 基本信息

- 状态：已验收
- 提出人：用户
- 负责人：Codex
- 目标版本：0.13.0
- 关联页面或模块：内置 OpenSpec 运行时、规划状态、内部工作流参考、完成门禁、结构校验与发布说明
- 关联变更：`upgrade-openspec-1-8`

## 背景与目标

插件当前固定内置 OpenSpec 1.7.0。OpenSpec 1.8.0 新增通用 `agents`、Rovo Dev 和 MiniMax Code 工具目标，迁移 Codex Skills 到 `.agents/skills/`，区分规划完成与整体进度，并增强多语言需求校验、嵌套任务统计、非交互归档提示、能力退役、工作流指引和文件安全边界。

本需求在保持插件内置运行时、默认只读、需求事实源、严格完成门禁和不覆盖业务内容的前提下升级到 1.8.0。插件不向业务项目生成上游 OpenSpec Skills，但必须显式理解上游状态字段与行为变化，避免只替换版本后产生静默兼容偏差。

## 范围

### 包含

- 替换插件内置 OpenSpec 1.7.0 为精确固定的 1.8.0 生产运行时。
- 更新固定版本、完整性清单、第三方声明、README、插件版本和相关测试。
- 让完成检查优先消费 `isPlanningComplete`，并兼容 1.7.0 风格响应。
- 为包装器补充遥测禁用环境变量。
- 三方合并 1.8.0 内部工作流参考，保留需求治理、Store 边界和完成硬门禁。
- 回归缩进子任务、多语言普通校验、严格校验、MODIFIED Scenario 完整性、非交互归档和能力退役行为。

### 不包含

- 调用全局 OpenSpec、运行全局 `openspec update` 或自动升级用户机器上的工具。
- 在业务项目生成 OpenSpec 自带的 `.agents/skills`、`.codex/skills`、Slash Commands 或 Copilot 云端代理文件。
- 自动修改历史需求、历史变更、历史规格或用户自定义工作流文件。
- 放宽未完成任务、未通过验收、无证据、非法 Store 或严格校验失败时的归档阻断。
- 新增 React、Angular、Svelte、Windows 或特定 Monorepo 专项适配。

## 当前行为

- 内置运行时、包装器常量、内部参考和说明固定为 OpenSpec 1.7.0。
- 完成检查依赖 `status.isComplete`，尚未优先识别 1.8.0 的 `isPlanningComplete`。
- 包装器关闭版本检查，但没有显式设置 `OPENSPEC_TELEMETRY=0`。
- 现有测试尚未覆盖 1.8.0 的缩进子任务、非英文普通校验和规划完成新字段。

## 期望行为

### 场景：安全替换内置运行时

- 前置条件：现有 1.7.0 运行时与仓库规划数据保持可恢复。
- 当：从官方 npm 包组装并核验 1.8.0 候选后执行替换。
- 则：插件只调用内置 1.8.0，版本、入口、生产依赖、许可证和完整性清单一致。
- 并且：当前需求、变更和规格能够通过 1.8.0 严格校验。
- 异常或边界：任一候选核验失败时停止替换，不留下混合版本运行时。

### 场景：区分规划完成与实施完成

- 前置条件：OpenSpec 1.8.0 状态响应包含 `isPlanningComplete` 和 artifact 列表。
- 当：插件执行检查、实施或完成预览。
- 则：插件以 `isPlanningComplete` 判断规划产物是否齐备，并继续独立检查任务、验收、验证证据和 artifact 状态。
- 并且：兼容测试替身或历史响应仅提供 `isComplete` 的情况。
- 异常或边界：规划未完成、artifact 状态未知或未授权跳过时必须在写入和归档前阻断。

### 场景：执行 1.8.0 校验与任务进度

- 前置条件：需求可能使用中文规范词，任务可能包含缩进子任务，MODIFIED Requirement 继承既有 Scenario。
- 当：执行普通校验、严格校验、状态查询和 apply instructions。
- 则：普通模式接受非英文规范词，严格模式继续执行仓库英文关键词规范，缩进子任务进入总数和待办列表。
- 并且：MODIFIED 遗漏既有 Scenario 时在归档前的校验阶段明确失败。
- 异常或边界：示例复选框可能被上游计数的已知行为必须在参考说明或测试中保持可见，不能伪报任务完成。

### 场景：保持离线和项目文件边界

- 前置条件：插件从本地项目调用内置规划引擎，项目可能包含旧 Codex 目录、Store 或符号链接目录。
- 当：执行版本、状态、指令、校验或归档。
- 则：版本检查和匿名遥测均被关闭，规划根继续经过插件边界校验，业务项目不被自动写入上游工具 Skills。
- 并且：用户自定义文件和未受管内容保持不变。
- 异常或边界：路径越界、未授权 `global_default` Store 或自定义文件冲突时继续失败关闭。

## 兼容性与风险

- 受影响页面、公共组件、路由、权限或接口：不涉及业务页面；影响所有使用插件规划、检查、同步、归档和升级的项目。
- 历史数据与兼容策略：使用候选 1.8.0 对当前仓库执行影子严格校验，保留 `isComplete` 响应兼容，不自动迁移历史内容。
- 上线与回滚注意事项：候选验证通过后才替换；发布前保留 1.7.0 临时备份，失败即恢复。
- 主要风险：Codex Skills 上游路径迁移可能误触业务项目文件；任务数量可能因缩进子任务增加；严格校验可能提前暴露已有 MODIFIED Scenario 缺失。
