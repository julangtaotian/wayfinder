# REQ-2026-035：平台运行时轻量交付

## 基本信息

- 状态：实施中
- 提出人：用户
- 负责人：Codex
- 目标版本：0.18.x
- 关联页面或模块：Playwright 内置运行时、平台插件打包、Codex 市场源安装、Git LFS 与五平台 CI
- 关联变更：`deliver-platform-runtime-on-install`

## 背景与目标

当前仓库在 `plugins/frontend-ai-workflow/runtime/playwright/platform-assets/` 直接保存 macOS ARM64/x64、Linux ARM64/x64、Windows x64 五套浏览器资产，工作区逻辑体积约 1.3GB，共 659 个受跟踪文件，其中 639 个由 Git LFS 管理。普通源码阅读已经通过路由规则避开这些二进制，但克隆、索引、磁盘占用、LFS 配额和插件源码安装仍承担五个平台资产的交付成本。

前一阶段已证明五个平台可以在 CI 中使用仓库固定的 Playwright 1.62.1 CLI 从官方源重建目标资产，并生成只包含当前平台、可离线运行的插件成品。本阶段计划把“规范源码”和“大型平台运行时”彻底解耦：源码仓库只保留共享运行时、固定版本、平台元数据、构建与校验合同；平台资产在有界暂存目录中按当前原生平台生成，安装或发布得到的插件成品仍只包含一个平台且使用阶段不联网。

Codex 当前市场源命令支持本地路径或 Git 仓库/ref，现有项目与官方公开资料没有提供按操作系统自动选择插件源的稳定合同。因此，本需求采用安装期准备方案：安装或升级时允许访问一次 Playwright 官方下载源，生成内置当前平台运行时的本地 marketplace 成品；安装完成后继续离线运行。在新链路完成五平台成品安装验证之前，不删除仓库 HEAD 中的 LFS 平台资产。

## 范围

### 包含

- 把 Playwright 平台资产构建目标从插件源码目录改为显式的外部暂存运行时，构建过程不再依赖源码树中已有 LFS 指针或真实平台文件。
- 形成一个平台准备总入口：识别当前 `process.platform/process.arch`、生成唯一平台运行时、校验固定版本与许可、构建本地 marketplace 成品并输出稳定报告。
- 保持平台成品内的 `distribution.json`、共享/平台完整性清单、体积预算、真实 Chromium 冒烟和结构校验。
- 为安装/升级提供可复制的本地 marketplace 命令和失败恢复说明；准备入口本身不得静默执行插件安装、提交、推送或发布。
- 普通 push/PR CI 使用同一外部暂存构建核心验证五个平台，但只上传报告，避免引入五份大型 CI artifact 的存储和下载成本。
- 提供默认预览、显式 `--write` 的安装证据入口；仅在人工触发的证据收集运行中复用原五平台矩阵，安装固定 Codex CLI 并输出小型安装报告，不读取登录态、不调用模型、不上传完整成品。
- 在第一阶段验证完成后，从仓库 HEAD 删除 `runtime/playwright/platform-assets/` 的五平台二进制、退役 LFS 规则及只服务占位替换的代码路径，更新结构、完整性、卫生、体积和文档合同。
- 增加确定性体积验收，证明仓库 HEAD 不再跟踪平台二进制，并记录迁移前后受跟踪文件数与逻辑体积。

### 不包含

- 不改写 Git 历史，不执行 `git lfs migrate`，不自动删除 GitHub LFS 历史对象或购买配额。
- 不把 Chromium 改为使用阶段按需下载，不回退用户系统 Chrome，也不允许业务项目安装 Playwright。
- 不增加受支持平台，不改变 Playwright 版本，不在本阶段升级 Chromium、OpenSpec 或 Node.js。
- 不新增 npm 依赖、第三方下载器、第三方发布 action、缓存服务、数据库或独立管理平台。
- 平台准备入口不自动执行 `codex plugin marketplace add`、`codex plugin add`、Git 提交、推送或外部发布；安装证据入口只有用户显式 `--write` 或人工 CI 开关才在隔离目录执行 Codex 安装检查。
- 不增加 schedule、定时构建、定时清理、定时复验或费用监控。
- 不在交付方式确认前删除现有平台 LFS 资产。

## 当前行为

- 源码工作区同时包含五个平台浏览器资产，`platform-assets/` 约 1.3GB；开发者当前平台只使用其中一套。
- `.gitattributes` 对整个 `platform-assets/**` 启用 Git LFS，仓库 HEAD 仍跟踪 659 个平台文件。
- CI 已经不再下载 LFS，而是先把 checkout 中的目标 LFS 指针目录安全替换为官方 Playwright 下载结果，再执行平台验证和打包。
- `package-plugin-platform.mjs` 从源码运行时复制目标平台资产，因此平台成品构建仍以源码树存在对应目录为前置条件。
- Codex marketplace manifest 只有一个本地插件路径，没有稳定的 OS/arch 条件分流字段；直接从精简源码市场安装将缺少平台浏览器。

## 期望行为

### 场景：预览当前平台交付计划

- 前置条件：开发者在受支持的原生平台执行平台准备入口，未传入写入参数。
- 当：入口解析当前平台、固定 Playwright 版本、输出根和预计成品。
- 则：返回稳定 `status=planned`、`code`、`platformKey`、`playwrightVersion`、`output`、`downloadsAtRuntime=false` 和预计步骤。
- 并且：不创建目录、不下载资产、不修改源码、不运行 Codex 安装命令。
- 异常或边界：未知架构、交叉平台写入、危险输出路径或已存在目标以稳定机器字段失败。

### 场景：准备唯一平台的本地 marketplace 成品

- 前置条件：用户已接受 D-05，当前平台受支持，显式传入 `--write`，官方固定版本下载源可访问。
- 当：准备入口在有界暂存目录下载并组装目标平台运行时。
- 则：成品只包含当前平台资产和元数据，生成共享/平台完整性、许可、体积和真实 Chromium 冒烟报告。
- 并且：输出可以作为 Codex 本地 marketplace 路径安装；插件使用阶段不联网。
- 异常或边界：下载、许可、摘要、结构、体积或冒烟任一失败时不发布半成品，并清理本次暂存目录。

### 场景：重复准备与受控升级

- 前置条件：同平台已有一个通过校验的旧版本本地成品。
- 当：用户预览或显式准备相同版本、或以后按正式需求升级固定版本。
- 则：相同版本预览报告可复用状态但不静默覆盖；显式更新使用独占暂存与原子替换，失败保留旧成品。
- 并且：版本、平台、完整性和分发描述不匹配时阻止安装指引输出。
- 异常或边界：Windows 目录句柄短暂占用按有界策略重试，重试耗尽返回稳定清理诊断。

### 场景：普通 CI 验证五个平台交付核心

- 前置条件：共享任务成功，五个平台矩阵分别运行在原生 runner。
- 当：平台任务在外部暂存目录构建目标运行时和插件成品。
- 则：每个平台执行完整性、真实 Chromium 冒烟、结构和体积检查，并上传小型 `package-report.json`。
- 并且：工作流不执行 `git lfs pull`，不要求源码树存在 LFS 指针，不上传完整大型平台包，不增加 cache 或 schedule。
- 异常或边界：任一平台失败时精确提交不得报告跨平台交付通过。

### 场景：人工收集五平台真实安装证据

- 前置条件：用户手动触发 Validate 并开启安装证据开关，五个平台各自已生成当前原生成品。
- 当：平台任务下载固定 Codex CLI 到 `outputs/`，把完整 marketplace 复制到离线暂存，从本地副本安装插件并渲染新会话模型可见输入。
- 则：报告确认插件 `installed/enabled`、`frontend-ai-workflow:frontend-ui-review` 来自隔离安装缓存，并在不可达代理环境从该缓存真实启动 Chromium 截图。
- 并且：不读取用户 Codex 配置、登录态或 API 密钥，不调用模型，不新增矩阵、cache、schedule、大型 artifact 或写权限；普通 push/PR 不执行该步骤。
- 异常或边界：CLI 版本、平台、安装目录、加载技能、离线冒烟或清理任一不匹配时返回稳定字段且不生成通过报告，LFS 删除门禁保持关闭。

### 场景：第二阶段移除源码平台资产

- 前置条件：D-05 已确认；五个平台成品的准备、安装、插件加载、UI Review 冒烟、失败回退和精确提交 CI 全部通过。
- 当：迁移任务删除仓库 HEAD 中的平台资产和旧 LFS 跟踪合同。
- 则：源码仓库不再跟踪 `platform-assets/` 二进制，完整性和结构校验以共享源码或实际平台成品为各自边界。
- 并且：README 明确新的安装/升级步骤、一次联网边界、离线使用合同与回退方式。
- 异常或边界：任何平台证据缺失时保持第一阶段状态，不允许提前删除 LFS 资产。

## 页面与交互

- 入口与操作路径：Node.js 平台准备 CLI、GitHub Actions、Codex marketplace 安装命令；不涉及业务页面。
- 字段、文案与默认值：默认预览；写入必须显式 `--write`；平台键与机器字段使用稳定英文，人类诊断使用中文。
- 加载态、空态、错误态、禁用态：下载过程输出阶段进度；零资产、缺许可、缺摘要、平台不支持和网络失败均失败关闭；未确认 D-05 时不进入实现与删除阶段。
- 权限与角色差异：普通 CI 保持 `contents: read`；准备入口不需要 GitHub 写权限或密钥，不自动修改 Codex 配置。
- 设计稿链接：不适用。

## 接口与数据

- 推荐新增一个稳定平台准备入口，预览结果至少包含 `ok`、`status`、`code`、`platformKey`、`playwrightVersion`、`output`、`downloadsAtRuntime`、`steps`。
- 写入成功结果至少包含平台成品路径、marketplace manifest 路径、插件根路径、完整性摘要、许可来源、逻辑体积、预算余量、冒烟结果和报告路径。
- 失败结果优先包含稳定 `status=failed`、`code`、`target`、清理结果和中文 `message`；不得只依赖人类文案判断。
- `package-plugin-platform.mjs` 的默认预览、安全输出、唯一平台、体积预算和成品结构保持兼容；实现可通过注入外部运行时源解耦源码平台目录。
- `build-playwright-platform.mjs` 的固定版本、主机映射、许可补齐和完整性生成逻辑继续复用；旧 `--replace-lfs-pointers` 只在第一阶段作为回退，第二阶段随 LFS 资产合同一起退役。
- Codex marketplace 安装继续使用官方 CLI 支持的本地路径；不假设 manifest 能自动按 OS/arch 分流。
- 安装证据报告至少包含 `status`、`code`、`platformKey`、固定 Codex 版本、marketplace 名称、插件版本、安装/启用状态、新会话技能可见状态、离线 Chromium 冒烟和清理状态；不得包含绝对缓存路径、代理值或凭据。

## 兼容性与风险

- 安装体验会从“源码中已经存在浏览器”调整为“安装或升级阶段准备当前平台成品”；网络较差时准备可能变慢或失败，但不得影响已经安装的旧插件。
- 官方下载最多三次、单次最多十分钟；继承用户现有代理环境但不得把代理地址中的凭据写入日志、报告或错误证据，也不得自动切换未经确认的镜像。
- 对完全离线环境，使用另一台同平台机器生成并验证 marketplace 成品后可复制安装；复用前必须重新核验插件版本、平台、完整性和许可，不能复用不匹配或来源不明的目录。
- 官方 Playwright 下载源不可用会阻塞新安装，但不能影响已经安装且完整的旧成品；失败不得降级为使用阶段联网或系统浏览器。
- 源码平台资产移除后，本地根级完整性校验不能继续要求五个平台真实文件同时存在；必须明确区分共享源码校验、当前平台成品校验和真实五平台 CI，避免虚假通过。
- Codex marketplace 没有已确认的 OS/arch 自动分流合同，因此准备入口只生成当前平台的本地 marketplace，不修改官方 manifest 语义或假装支持自动选择。
- Git HEAD 删除 LFS 文件不会回收历史 LFS 对象或历史账单；历史清理需要单独的破坏性迁移需求和明确授权。
- Windows 路径、可执行权限、目录句柄、macOS 架构识别、Linux ARM64 许可补齐和环境变量继承必须分别回归；单平台 fixture 不能替代五平台真实证据。
- 大型完整平台包若在每次 push/PR 上传会重新产生 artifact 存储与下载成本，因此普通 CI 只保留小型报告；正式发布机制必须由人工显式触发。
- 删除 LFS 前必须保留可恢复提交或旧安装成品；不能通过删除测试、放宽完整性、跳过冒烟或扩大体积预算达成迁移。
