# REQ-2026-024：OpenSpec 1.9.0 受控升级

## 基本信息

- 状态：已验收
- 提出人：用户
- 负责人：Codex
- 目标版本：0.14.0
- 关联页面或模块：内置 OpenSpec 运行时、实施指导、归档校验、统一验证、内部工作流参考和插件发布
- 关联变更：`upgrade-openspec-1-9`

## 背景与目标

插件当前固定内置 OpenSpec 1.8.0。OpenSpec 1.9.0 新增归档任务检查，修复批量校验在错误目录静默通过、非交互归档输出失控、非标准 Scenario 丢失和规格空白漂移，并要求实施代理在发现规格外范围时主动报告而不是静默缩减工作。

本需求在保持内置离线运行时、默认只读、需求事实源、严格完成门禁和不覆盖业务内容的前提下升级到 1.9.0。统一验证应采用新的归档检查，同时对根目录、任务编号、场景保护和非交互行为建立显式回归，避免只替换版本文件而遗漏行为变化。

## 范围

### 包含

- 将插件内置 OpenSpec 1.8.0 整体替换为精确固定的 1.9.0 生产运行时。
- 更新固定版本、生产包完整性清单、第三方声明、README、受管工作流版本和插件 cachebuster。
- 将 `validate --archived` 纳入统一只读验证，并验证失败阶段可定位。
- 回归错误根目录批量校验、任务编号警告、非标准四级 Scenario、无 TTY archive 和规格空白稳定性。
- 合并 1.9.0 apply 的范围报告约束，同时保留需求台账、规划根和完成硬门禁。

### 不包含

- 调用或升级全局 OpenSpec。
- 在业务项目生成 Command Code、OpenSpec 上游 Skills、Slash Commands 或 Copilot 云端代理文件。
- 自动修复历史归档变更的未完成任务、任务编号或用户规格格式。
- 放宽未完成任务、验收、证据、严格校验、Store 或规格同步失败时的阻断。
- 修改 Playwright 平台运行时、UI Review 业务逻辑或其他活动变更范围。

## 当前行为

- 内置运行时、包装器常量、内部参考和说明固定为 OpenSpec 1.8.0。
- `npm run verify` 只严格校验活动变更和主规格，不检查归档任务是否全部完成。
- apply 内部参考没有明确要求报告意外范围。
- 聚焦测试没有覆盖错误目录批量命令、模糊任务编号、非标准 Scenario 和无 ANSI archive 输出。

## 期望行为

### 场景：安全替换内置运行时

- 前置条件：现有 1.8.0 运行时和规划数据保持可恢复。
- 当：从官方 npm 包组装并核验 1.9.0 候选后执行替换。
- 则：插件只调用内置 1.9.0，版本、入口、生产依赖、许可证和完整性清单一致。
- 并且：现有需求、活动变更、归档变更和主规格继续通过对应校验。
- 异常或边界：候选任一核验失败时停止替换，不留下混合版本运行时。

### 场景：统一检查归档任务

- 前置条件：仓库可能存在历史归档变更。
- 当：执行 `npm run verify`。
- 则：活动变更与主规格继续严格校验，并独立运行 `validate --archived` 检查归档任务。
- 并且：任一归档任务未完成时以稳定阶段标识返回非零。
- 异常或边界：归档检查不得应用 delta 或重写主规格。

### 场景：采用 1.9.0 校验和归档语义

- 前置条件：命令可能在错误目录执行，任务编号可能歧义，Scenario 可能使用自定义四级标题，archive 可能没有 TTY。
- 当：执行批量校验、列表、变更校验或归档。
- 则：缺少 OpenSpec 根时批量命令失败，任务编号问题保持可见，遗漏任意四级 Scenario 的 MODIFIED 变更失败。
- 并且：非交互归档输出为有限纯文本，不包含 ANSI 光标控制。
- 异常或边界：这些上游约束不得被包装器改写为成功或吞掉诊断。

### 场景：实施发现规格外范围

- 前置条件：实现任务时发现完成需求需要规划中未声明的额外行为。
- 当：内部 apply 工作流处理该任务。
- 则：代理暂停并报告新增范围，建议更新规划 artifact 后继续。
- 并且：不能以缩减、延后或静默简化替代规格规定行为，也不能提前勾选任务完成。
- 异常或边界：纯实现细节且不改变范围时仍可按现有自主执行规则继续。

## 兼容性与风险

- 受影响页面、公共组件、路由、权限或接口：不涉及业务页面；影响所有规划、检查、同步、归档和仓库验证入口。
- 历史数据与兼容策略：先用候选 1.9.0 对现有活动与归档数据执行影子校验，不自动修改历史内容。
- 上线与回滚注意事项：候选验证通过后才整体替换；替换期间保留 1.8.0 可恢复副本，失败立即恢复。
- 主要风险：新版归档检查可能暴露历史未完成任务；任务编号警告可能增加；运行时依赖闭包和插件体积可能变化。
