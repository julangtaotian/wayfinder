# REQ-2026-029：动态框架与第三方依赖上下文

## 基本信息

- 状态：待验证
- 提出人：用户
- 负责人：Codex
- 目标版本：0.17.0
- 关联页面或模块：项目识别、初始化与升级、Wayfinder 项目事实、OpenSpec 项目上下文、AI 深度分析指导
- 关联变更：`add-dynamic-dependency-context`

## 背景与目标

插件当前通过 `inspect-project.mjs` 内的固定包名列表生成 `techStack`，并通过有限框架集合形成项目预设和平台画像。这些规则适合表达插件已经验证过的兼容信号，却无法完整覆盖项目真实声明的框架、私有包和普通第三方依赖；当依赖不在固定列表中时，初始化资料可能直接省略它，AI 也容易把“插件未识别”误写成“项目不存在”。

本需求把“事实采集”和“语义识别”拆开：确定性脚本从目标根 `package.json` 动态、完整、稳定地收集直接依赖声明和来源分组，不使用框架百科式白名单生成完整结论；AI 再结合这份清单、真实配置和相关源码总结框架、工具职责、关键依赖及不确定项。现有预设、终端画像和平台画像继续作为有限的兼容/安全信号，但必须明确它们不是完整技术栈证明。

## 范围

### 包含

- 动态收集四类直接依赖，保留同一包跨分组声明和原始版本范围。
- 输出有版本、可排序、可诊断的 `dependencyProfile` 机器合同。
- 用动态依赖摘要替换模板中的固定技术栈白名单结论。
- 在 AGENTS、Wayfinder、OpenSpec 和分析规则中明确 AI 的依赖总结步骤与证据边界。
- 保留并重新定位现有 preset、终端画像和平台画像为有限兼容信号。
- 覆盖未知框架、私有作用域包、重复分组、可选/对等依赖、空依赖、非法声明、截断摘要和重复执行。
- 完成聚焦测试、本地统一验证、官方 validators 和最终提交五平台 CI。

### 不包含

- 自动联网查询 npm registry、漏洞库、许可证库、下载量或最新版本。
- 安装或执行目标项目依赖，读取 `node_modules` 推断职责，或解析完整传递依赖树。
- Workspace/Monorepo 子包发现、多前端应用编排和跨包影响分析。
- 根据包名自动断言业务用途、安全性、可维护性、是否正在使用或是否兼容。
- 删除现有 Vue/React 预设、终端画像、平台画像或改变其已验证兼容范围。
- 新增框架专用命令、适配器、第三方依赖或远程服务。

## 当前行为

- `inspect-project.mjs` 使用固定 `TECH_PACKAGES` 数组生成 `techStack`，未列出的 Angular、Svelte、Astro、私有包和普通依赖不会出现在初始化技术栈中。
- 依赖合并只覆盖 `dependencies`、`devDependencies` 和 `peerDependencies`，不保留来源分组，也未纳入 `optionalDependencies`。
- 模板将固定列表结果直接写成“技术栈”，容易让有限命中被理解为完整结论。
- 深度分析虽然要求 AI 依据源码负责语义，但没有稳定的完整直接依赖清单作为输入，也没有明确禁止把兼容画像当成完整框架判断。

## 期望行为

### 场景：项目包含插件从未预置的框架和私有依赖

- 前置条件：根 `package.json` 声明任意合法包名、作用域私有包和版本范围，它们不在插件既有固定规则中。
- 当：执行项目检查、初始化预览或升级预览。
- 则：`dependencyProfile` 完整返回这些直接依赖、版本声明和来源分组，顺序稳定。
- 并且：受管上下文显示动态摘要并指向完整事实，不把未知包省略或写成“不存在”。
- 异常或边界：AI 无法从配置和源码确认包职责时必须保留待确认，不得根据名称编造用途。

### 场景：同一依赖出现在多个声明分组

- 前置条件：同一包同时出现在 production、development、peer 或 optional 声明中，且版本范围可能不同。
- 当：收集依赖事实。
- 则：完整包清单只保留一个稳定条目，并记录全部来源分组和每组原始版本声明，不使用无来源的覆盖顺序丢失信息。
- 并且：分组计数和唯一包总数语义不同且可审计。
- 异常或边界：空分组和空字符串不生成虚假依赖。

### 场景：依赖声明为空或不合法

- 前置条件：四类依赖均缺失，或者某个分组/版本声明不是合法对象和非空字符串。
- 当：执行项目识别。
- 则：空项目返回明确的零计数、空清单和“未声明直接依赖”摘要；无效项返回稳定 code、status、target 诊断并被排除。
- 并且：工具不崩溃、不把无效值字符串化成可信版本，也不回退到目录名猜测。
- 异常或边界：`package.json` 本身无法解析时沿用现有失败行为，不伪造部分成功。

### 场景：大型依赖清单生成可读上下文

- 前置条件：直接依赖数量超过受管模板的可读展示上限。
- 当：初始化或升级生成受管上下文。
- 则：机器清单仍包含全部合法直接依赖；人类摘要标明总数、已展示数量和剩余数量。
- 并且：AI 分析必须读取完整机器事实或原始 `package.json` 后再给出语义结论，不能只分析被截断的摘要。
- 异常或边界：排序和截断不得依赖当前操作系统、文件路径或对象插入顺序。

### 场景：兼容画像与动态事实同时存在

- 前置条件：项目包含 Vue/React、小程序或终端 UI 依赖，也可能同时包含未预置框架。
- 当：执行识别并生成项目上下文。
- 则：既有 preset、终端和平台画像保持兼容；动态依赖清单独立包含全部直接依赖。
- 并且：文档明确画像只是有限兼容信号，AI 不得用其空值否定动态事实。
- 异常或边界：冲突画像继续报告冲突，不由动态摘要自动选择框架或发布目标。

## 页面与交互

- 入口与操作路径：现有项目检查、初始化预览/写入、升级预览/写入及 AI 深度项目分析；不新增 GUI 或公共命令。
- 字段、文案与默认值：机器字段使用稳定英文；人类摘要使用中文，明确“直接依赖声明”“有限兼容信号”和“待 AI 结合源码总结”。
- 加载态、空态、错误态、禁用态：一次性本地读取无加载态；空依赖输出真实零值；非法声明输出诊断；只读能力不涉及禁用控件。
- 权限与角色差异：不涉及业务角色；默认预览与显式写入权限保持不变。
- 设计稿链接：不适用。

## 兼容性与风险

- 受影响页面、公共组件、路由、权限或接口：不影响业务页面；影响共享项目检查结果、初始化/升级模板和 AI 项目上下文。
- 历史数据与兼容策略：保留现有 `preset`、`techStack`、`targetProfile` 和公共入口；新增字段采用增量合同，旧受管文件仅在用户显式升级时更新。
- 上线与回滚注意事项：动态收集器独立封装，模板变量单独接入；出现问题可回滚新字段和模板消费，不修改目标项目 package 声明。
- 跨平台高风险：是；命中路径、包管理器入口和机器可读诊断。结构化输出不包含平台绝对路径，路径使用 Node.js API；真实交付以 Linux x64/ARM64、Windows x64、macOS Intel/ARM64 同一提交矩阵为准。
- 剩余风险：包声明不能证明依赖已安装、被源码使用、运行时启用、安全或兼容；AI 总结仍可能受缺失配置、动态加载和上下文范围影响，必须保留证据与待确认项。
