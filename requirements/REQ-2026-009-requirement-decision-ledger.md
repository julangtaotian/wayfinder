# REQ-2026-009：需求决策台账与确定性校验

## 基本信息

- 状态：已验收
- 提出人：用户
- 负责人：Codex
- 目标版本：0.10.0（历史能力治理闭环）
- 关联页面或模块：需求模板、需求规则、需求校验器、变更规划与实施
- 关联变更：`stabilize-requirement-decisions`

## 背景与目标

自然语言需求中的空白可能在不同运行中被补成不同默认值，造成需求、规格、任务和实现漂移。本需求使用同一份需求文档内的稳定决策 ID 和验收证据映射作为事实源，并通过确定性校验阻止未确认内容进入实施。

## 决策台账

| ID | 决策项 | 状态 | 取值 | 来源 |
| --- | --- | --- | --- | --- |
| D-01 | 决策事实源 | 已确认 | 每份受管需求在同一 `REQ-*.md` 中维护唯一 `D-*` 决策台账，记录状态、取值和来源 | 用户要求稳定需求整理与变更；现有台账实现 |
| D-02 | 可实施状态 | 已确认 | 只有“已确认”或有来源的“项目默认”决策可进入规格、设计和任务；暂定、待确认和未知 ID 必须阻断 | 现有需求规则和校验器 |
| D-03 | 验收证据 | 已确认 | 每条 `A-*` 验收与决策、验证方式、证据位置、断言结果及 `V-*` 记录一一映射 | 现有需求模板与完成门禁 |
| D-04 | 校验边界 | 项目默认 | 校验器仅使用 Node.js 标准库，验证结构和引用，不替代用户对业务语义的确认 | 根目录实现约束和校验器设计 |

## 范围

### 包含

- 决策台账、验收标准和证据映射结构。
- 规格、设计、任务对可实施决策和验收的引用。
- 稳定 JSON 及中文错误的确定性校验器。
- 需求编写、规划和实施前的校验调用。

### 不包含

- 自动替用户决定未知业务规则。
- 自动迁移或补造历史需求事实。
- 使用规则脚本判断自然语言业务语义是否正确。

## 当前行为

- 决策台账、校验器、技能和回归测试已实现，但关联能力仍位于活动变更中。

## 期望行为

### 场景：需求包含未确认业务边界

- 前置条件：原始描述没有说明权限、接口、关闭语义或兼容边界。
- 当：整理需求或生成变更计划。
- 则：该项保持待确认或有来源的暂定状态。
- 并且：校验器阻止它进入规格、设计、任务和实施。

### 场景：完成结构化需求校验

- 前置条件：需求包含合法台账、验收映射和关联任务。
- 当：运行计划或实施阶段校验。
- 则：返回稳定的决策、验收和任务引用统计。
- 并且：缺失、未知或不可实施的引用得到明确中文错误。

## 页面与交互

- 入口与操作路径：需求编写、规划、实施和完成检查。
- 字段、文案与默认值：`D-*`、`A-*`、`V-*` ID 稳定，状态和错误使用中文。
- 加载态、空态、错误态、禁用态：缺表、空来源、重复 ID 和未知引用均阻断。
- 权限与角色差异：不涉及业务角色。
- 设计稿链接：不适用。

## 接口与数据

- 接口文档链接：不涉及网络接口。
- 请求方法与路径：读取 `requirements/REQ-*.md` 和可选变更目录。
- 请求字段及空值语义：缺失表、空来源和空映射分别报告。
- 响应字段及状态码：合法结构退出 0，无效结构退出非零并输出稳定 JSON。
- 鉴权、加解密或敏感信息要求：不上传需求内容。
