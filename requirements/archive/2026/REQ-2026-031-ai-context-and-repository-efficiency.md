# REQ-2026-031：AI 上下文与仓库研发效率优化

## 基本信息

- 状态：已验收
- 提出人：用户
- 负责人：Codex
- 目标版本：0.17.1
- 关联页面或模块：项目健康检查、工作流检查 Skill、根 AGENTS、单平台插件发布与本地安装
- 关联变更：`reduce-ai-context-cost`

## 背景与目标

仓库增长后，历史验证诊断、持久验收资产、五平台浏览器运行时和重复插件安装同时增加了文件搜索噪声、机器输出长度与本地磁盘占用。现有 `check-project.mjs` 会在普通健康检查中输出全部历史诊断；当前仓库一次结果达到 1056 行、46444 字节，其中绝大部分是已经归档的历史证据提醒。

本需求在不删除受跟踪运行时、历史需求、OpenSpec 归档或持久验收资产的前提下，清理 Git 已忽略的可重建内容，为健康检查增加精简输出与按诊断码查询，明确 AI 默认读取范围，并用当前平台成品替代多平台源码安装副本。

## 期望行为

### 场景：普通 AI 健康检查

- 当：Skill 对目标项目运行健康检查。
- 则：先读取精简 JSON，保留完整直接依赖事实和当前工作流状态，但不展开全部历史诊断。
- 并且：精简结果提供稳定模式、历史计数、观察总数和遗漏数量。

### 场景：定位一种历史诊断

- 当：精简结果报告某个历史诊断 code 且需要精确目标。
- 则：调用方按该 code 查询，只得到匹配诊断。
- 异常或边界：未知 code 返回零项及可用 code，不退化为全量输出。

### 场景：旧调用方继续消费完整结果

- 当：调用方不传 `--summary` 或 `--diagnostic-code`。
- 则：CLI 继续返回原完整 JSON，`checkProject()` 导出结果不变。

### 场景：AI 搜索仓库

- 当：任务没有明确涉及运行时、发布资产、历史验收或归档。
- 则：AI 优先搜索插件源码、技能、参考、模板和测试，不枚举大体积运行时与历史输出。

## 接口与数据

- `--summary`：布尔参数，返回 `schemaVersion=1.0.0`、`mode=summary` 的精简结果。
- `--diagnostic-code <code>`：值参数，返回 `schemaVersion=1.0.0`、`mode=diagnostics`、查询 code、分页 count、totalCount、nextOffset、availableCodes 和 diagnostics。
- `--diagnostic-offset <n>` 与 `--diagnostic-limit <n>`：只能与 diagnostic-code 一起使用；offset 为非负整数，limit 为 1～100，默认 20。
- 两个模式互斥；冲突时在读取目标项目之前失败。
- 机器断言优先使用 `schemaVersion`、`mode`、`code`、`count`、`totalObservations`、`omittedObservations` 和退出状态。
