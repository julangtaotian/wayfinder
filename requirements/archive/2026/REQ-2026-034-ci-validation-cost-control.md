# REQ-2026-034：CI 验证成本分层与在途任务治理

## 基本信息

- 状态：已验收
- 提出人：用户
- 负责人：Codex
- 目标版本：0.18.x
- 关联页面或模块：统一验证入口、GitHub Actions 五平台矩阵、平台运行时与插件打包
- 关联变更：`reduce-ci-validation-cost`

## 背景与目标

当前 `push` 与 `pull_request` 均会触发五平台矩阵，每个平台都重复执行完整九阶段 `npm run verify`，并重复准备只被共享工作流测试使用的 Vitest 临时运行时。平台差异验证、目标平台 Playwright 资产拉取、浏览器冒烟和平台插件打包确实需要五个平台分别执行，但仓库体积、共享 Node 测试、结构、OpenSpec 与内置运行时校验没有必要在同一提交上重复五次。

本阶段在不削弱五平台发布证据的前提下，把 CI 分为一次共享验证和五个平台专属验证，并取消同一工作流、同一引用上已经过时的在途运行。根级 `npm run verify` 仍保持本地完整验证语义；文档、需求和规格变更仍触发验证；不建立定时优化或定时清理任务，也不在首阶段引入缓存和不透明的费用估算。

## 范围

### 包含

- 为 `scripts/verify.mjs` 增加完整、共享、平台三个确定性作用域，保持完整作用域为根级默认行为。
- 共享作用域运行仓库体积、除平台专属文件外的全部共享测试、结构、全部与归档 OpenSpec、内置 OpenSpec 版本和完整性校验，并只准备一次 Vitest 临时运行时。
- 平台作用域运行 `tests/ui-review-automation.test.mjs`、`tests/ui-review-platform-runtime.test.mjs`、目标平台 Playwright 完整性与浏览器冒烟，不准备 Vitest 临时运行时。
- 调整 `.github/workflows/validate.yml` 为一个 Linux x64 共享任务和一个依赖它的五平台矩阵任务；每个平台从固定 Playwright 官方源重建自己的目标资产、构建插件并上传报告。
- 为平台构建器增加显式 LFS 占位替换模式、稳定机器诊断和失败回滚；普通本地模式继续拒绝覆盖真实资产。
- 增加同一工作流与同一引用的并发取消规则，取消被更新提交替代的在途运行。
- 扩展现有手写测试，验证作用域的阶段集合、失败短路、临时运行时生命周期、CI 依赖、矩阵和并发合同。

### 不包含

- 删除任何平台、减少同一精确提交的五平台发布证据或用本地模拟替代真实矩阵。
- 修改 `push`、`pull_request` 事件范围或忽略文档、需求、规格和测试文件变更。
- 引入 GitHub Actions cache、缓存 Git LFS 平台资产、增加第三方 action 或新增 npm 依赖。
- 修改 Playwright 平台运行时的 Git LFS 存储格式、发布格式、插件仓库识别或业务工作流行为。
- 承诺具体费用金额、修改 GitHub 套餐或建立定时优化、定时清理与监控任务。

## 当前行为

- 五个平台分别执行完整九阶段 `npm run verify`，因此共享验证每个提交重复五次。
- 每个平台都准备和清理 `outputs/frontend-test-runtime/`，即使平台专属测试本身不使用 Vitest。
- 五个平台完成统一验证后分别打包并上传报告，共享校验失败也要等待其他平台上的重复执行。
- 工作流没有 concurrency 规则，同一分支连续推送时旧运行可能继续占用 runner。

## 期望行为

### 场景：本地执行完整统一验证

- 前置条件：开发者在完整仓库执行根级 `npm run verify`。
- 当：未传入 CI 专用作用域。
- 则：仍按现有九阶段顺序运行全部测试和校验，任一阶段失败立即返回真实非零状态。
- 并且：Vitest 临时运行时只由最外层完整验证准备和回收，临时文件仍限定在 `outputs/`。

### 场景：CI 执行共享验证

- 前置条件：push 或 pull request 触发 Validate 工作流。
- 当：共享 Linux x64 任务开始执行。
- 则：只执行一次共享作用域，覆盖除平台专属测试和 Playwright 平台检查外的完整共享链。
- 并且：共享任务失败时五平台任务不得开始，失败阶段和退出状态可定位。

### 场景：CI 重建平台资产、验证与打包

- 前置条件：同一运行的共享任务成功。
- 当：五平台矩阵分别用固定 Playwright CLI 安全替换 checkout 中的目标 LFS 占位并执行平台作用域。
- 则：每个平台从官方源得到唯一目标资产，再运行专属测试、目标平台完整性、真实浏览器冒烟、平台打包和报告上传。
- 并且：macOS ARM64/x64、Linux ARM64/x64、Windows x64 五项必须属于同一精确提交，任一失败均不得宣称跨平台发布通过。

### 场景：平台资产不能安全重建

- 前置条件：目标目录混入真实非空文件/链接，或官方下载、许可补齐、完整性生成任一失败。
- 当：平台构建器尝试显式替换 LFS 占位目录。
- 则：以稳定 `code`、`status`、`target` 和非零状态失败关闭，恢复原占位目录并清理本次暂存目录。
- 并且：不得继续平台验证、打包或上传；普通本地构建不得覆盖已存在的真实平台资产。

### 场景：同一引用出现更新提交

- 前置条件：同一工作流、同一 Git 引用已有等待或运行中的验证。
- 当：新的 push 或 pull request 同引用运行进入队列。
- 则：旧的等待或在途运行被取消，最新运行继续。
- 并且：push 与 pull request 的不同引用不被合并为同一取消组，取消的旧提交不能作为最终发布证据。

### 场景：作用域参数无效或没有测试

- 前置条件：调用方传入未知作用域，或分组漂移导致共享/平台作用域没有发现测试。
- 当：统一验证解析并准备执行。
- 则：命令以稳定错误 code、scope、status 和非零退出状态失败关闭。
- 并且：不得以零测试、回退完整作用域或静默跳过报告成功。

## 页面与交互

- 入口与操作路径：根级 npm 脚本和 GitHub Actions；不涉及业务页面。
- 字段、文案与默认值：本地默认作用域为完整验证；CI 作用域名和机器字段使用稳定英文，人类诊断保持中文。

- 权限与角色差异：工作流继续只授予 `contents: read`，不新增写权限、密钥或外部连接。
- 设计稿链接：不适用。

## 兼容性与风险

- 本变更修改发布级 CI、子进程、临时目录、环境变量和包管理器入口，属于跨平台高风险；本地确定性测试不能替代真实五平台证据。
- 分区错误可能漏跑测试。共享集合必须是全部受跟踪测试减去平台专属文件，平台集合必须非空，并用测试断言两者无遗漏、无意外重叠且并集等于完整集合。
- 平台矩阵必须显式依赖共享任务，避免共享失败后继续消耗昂贵平台 runner；同时 `fail-fast: false` 继续让已开始的五平台结果完整可见。
- concurrency 只取消同一工作流、同一引用的旧运行；不同事件引用不合并，避免 PR 必需检查因 push 运行互相取消。
- 首阶段不使用路径过滤和缓存，减少隐藏的触发缺口、缓存污染、跨架构键错误与额外存储成本。
- CI 官方下载存在外部可用性风险，但比账户 LFS 额度具有更直接的固定版本语义；任何下载失败都必须保留原占位目录并失败关闭，不能跳过完整性或冒烟。
- LFS 占位替换是精确目录的受控破坏性操作：必须显式开启、验证整棵目标树只有合法指针/零字节占位、原子备份并在失败时恢复；不得作用于运行时根或真实资产目录。

## 验收标准

- [x] [A-01] `npm run verify` 保持完整九阶段、稳定顺序、失败短路、真实退出状态和有界清理；未知或空作用域失败关闭。
- [x] [A-02] CI 每次运行只执行一次共享验证，覆盖完整共享测试与治理链；共享失败时五平台任务不启动。
- [x] [A-03] 平台矩阵仍覆盖 macOS ARM64/x64、Linux ARM64/x64、Windows x64，并在每个平台执行非空平台测试、目标完整性、真实冒烟、打包和报告上传。
- [x] [A-04] 同一工作流、同一 Git 引用的新运行取消旧在途运行；不同引用不合并，且没有新增定时任务。
- [x] [A-05] 聚焦、全量、结构、统一验证、官方 validators、Vue 3 + Vite fixture 和同一精确提交的共享+五平台 CI 全部通过。
- [x] [A-06] 保留 push/PR 触发与文档验证，不增加路径忽略、缓存、依赖、权限或具体费用承诺；静态合同证明共享验证次数由五次降为一次、平台验证仍为五次。
- [x] [A-07] 五平台 CI 不依赖 Git LFS 下载额度；只用固定 Playwright CLI 安全重建目标资产，拒绝覆盖真实文件，失败恢复占位目录并清理暂存；发布包继续运行期离线且包含许可。
