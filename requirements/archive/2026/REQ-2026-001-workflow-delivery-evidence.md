# REQ-2026-001：工作流交付证据与命令语义强化

## 基本信息

- 状态：已验收

- 关联变更：`enforce-delivery-evidence`

## 背景与目标

四个真实项目的试运行表明，插件已能生成需求、规划和测试策略，但仍可能把非 lint 脚本识别为 lint、把默认构建误作交付构建，或在缺少真实命令与视觉证据时将需求标记为完成。

本需求使插件以可兼容、可预览和可审计的方式识别命令语义，并在变更完成前核验状态、验收、测试策略和验证证据的一致性。可观察目标是：检查报告不再误导交付命令或 lint 能力；未完成验证的变更不能完成或归档；需求文件可以明确说明实际验证记录与人工视觉证据。

## 范围

### 包含

- 为项目检查报告增加默认构建、交付构建与 lint 语义状态。
- 为需求决策校验器增加规划/实施/完成阶段的兼容校验能力。
- 更新需求模板、需求规则、变更技能和受管 AGENTS 中的状态、验证记录、人工证据与测试基线规则。
- 为命令语义、完成门槛、验证证据、测试基线和旧格式兼容补充端到端测试。

### 不包含

- 自动执行目标项目的构建、测试、浏览器操作或截图。
- 自动判断自然语言业务设计是否正确，或自动生成、伪造验证证据。
- 自动改写已初始化项目中的旧需求、任务或业务代码。
- 改变 Wayfinder 迁移的预览优先和不覆盖业务项目内容的安全策略。

## 当前行为

- 项目识别按固定脚本别名选择第一个构建和 lint 脚本，无法区分默认构建、生产构建或非 lint 命令。
- 需求校验器验证决策、验收和引用的结构，但不验证需求状态、勾选进度或真实验证记录。
- 需求模板只记录测试策略和计划命令；人工检查与实际命令输出没有结构化记录。
- 测试文件策略依赖技能提示，无法根据 Git 基线验证“复用”的真实性。

## 期望行为

### 场景：检查具有多种构建脚本的项目

- 前置条件：项目同时定义 `build` 与显式生产构建脚本。
- 当：用户运行项目检查。
- 则：报告同时展示默认构建和交付构建候选，且保留现有 `commands.build` 字段。
- 并且：后续需求验证记录能够写明实际使用的交付命令与环境，检查器不擅自宣称默认构建就是生产构建。

### 场景：检查名为 lint 但不执行静态检查的脚本

- 前置条件：项目存在名为 `lint` 的脚本，但脚本内容不是已识别的静态检查工具。
- 当：用户运行项目检查。
- 则：报告 lint 命令和“语义未验证”状态，并给出中文警告。
- 并且：检查器不得将该脚本描述为已配置的有效 lint 能力。

### 场景：尝试完成缺少验证证据的变更

- 前置条件：需求、任务或验证记录中至少有一项未完成、失败或阻断。
- 当：用户要求完成或归档变更。
- 则：完成阶段校验失败并逐项指出缺少的状态、验收、任务或验证记录。
- 并且：插件不得同步规格或归档该变更。

### 场景：完成包含人工视觉验收的变更

- 前置条件：验收项包含人工视觉或自动+人工验证。
- 当：用户要求完成变更。
- 则：该验收映射必须关联通过的验证记录，其中包含视口或设备环境、检查项和截图或录屏位置。
- 并且：任一信息缺失时，完成阶段校验失败。

### 场景：计划中选择复用测试文件

- 前置条件：需求的测试文件策略标记为“复用”。
- 当：插件在规划或实施前校验需求。
- 则：在 Git 基线可用时确认目标文件已受版本控制；否则报告无法确认基线。
- 并且：目标不存在或明确为新文件时，要求修订为“新建”而非默认为复用。

## 兼容性与风险

- 受影响模块：插件检查器、需求校验器、需求模板、工作流规则、变更技能与端到端测试。
- 兼容策略：保留 `commands.build` 等现有字段；旧格式需求在默认校验中继续可读，只有完成阶段要求补充新版完成证据。
- 风险：静态脚本分析无法证明任意自定义 lint 包装器的实际行为；对此报告“语义未验证”，并允许项目规则提供可追溯说明。
- 上线与回滚注意事项：所有新增校验先通过预览或 JSON 报告暴露问题；不自动写入业务项目文件，回滚可移除新增字段与完成阶段调用。
