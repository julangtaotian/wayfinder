# REQ-2026-039：独立前端快速修改通道

## 基本信息

- 状态：待验证
- 提出人：用户
- 负责人：Codex
- 目标版本：0.18.x
- 关联页面或模块：`frontend-fast-change` Skill、`frontend-change` Skill、受管 `AGENTS.md` 模板、需求边界说明、README、公开 Skill 清单与路由合同测试
- 关联变更：add-fast-change-route

## 背景与目标

当前完整的 `frontend-change` 能力适合承载需求探索、规划、实现、规格同步和完成归档，但把已决定结果的局部修复也装入同一 Skill，会增加不必要的上下文和流程成本，并使“快速”与“受管”两套规则相互干扰。

本需求把快速通道收敛为独立的 `frontend-fast-change` Skill：它只处理用户明确要求实施、结果已经决定、影响可以界定在局部调用链且能够聚焦验证的前端改动；不创建需求或 OpenSpec 产物。匹配活动变更、需要业务决定或出现实质共享契约与工程风险时，只交接一次给原有 `frontend-change`，并携带已经发现的事实，避免重复调查。原 `frontend-change` 的完整生命周期和默认行为保持不变。

## 范围

### 包含

- 新建 `frontend-fast-change` Skill 和隐式选择元数据。
- 从 `frontend-change` 移除嵌入式快速通道，恢复原有完整受管生命周期。
- 在受管 `AGENTS.md` 模板、需求边界说明和 README 中提供简洁、单一事实来源的路由说明。
- 把新 Skill 加入公开能力清单，并重写专用合同测试，锁定准入、实质升级、单次交接和兼容边界。

### 不包含

- 不修改 OpenSpec 内置运行时、变更状态机、完成归档门禁或需求校验器。
- 不新增运行时分类器、依赖或按文件路径关键词做硬编码分流。
- 不扩大提交、推送、创建 PR、发布或外部系统写入权限。
- 不把尚未决定的新功能、实质共享契约或工程基础设施变化纳入快速通道。
- 不宣称未实际运行的多平台 CI 结果。

## 当前行为

- 快速通道规则嵌在 `frontend-change` 内，公开描述同时承担快速修复与完整受管变更，渐进披露边界不清楚。
- `frontend-change` 的默认 Plan 规则已被快速分支改写，存在影响原完整生命周期的风险。
- 受管模板和 README 重复了较长的准入清单，但没有独立、可被直接选择的快速能力。

## 期望行为

### 场景：明确局部修改由独立快速 Skill 直接完成

- 前置条件：用户明确要求实施；预期结果已经决定；相关源码和必要调用方能把影响界定为同一局部行为；存在聚焦验证；没有匹配活动变更和 D-03 的实质风险。
- 当：系统根据 Skill 描述选择工作流。
- 则：加载 `frontend-fast-change`，不加载完整需求/变更流程，不创建需求或 OpenSpec 产物。
- 并且：完成必要修改和聚焦验证，报告实际改动、实际验证和实质剩余风险。
- 异常或边界：同一局部调用链需要多个文件不自动升级；文件少或改动行数少也不自动准入。

### 场景：发现实质边界时单次交接完整流程

- 前置条件：初始检查或实施中发现匹配活动变更、未决产品决定、无法界定影响或 D-03 的实质风险。
- 当：快速 Skill 重新核对任务边界。
- 则：停止继续扩张，保留用户拥有的改动和已完成的安全工作，只交接一次给 `frontend-change`。
- 并且：交接内容包含触发原因、已定位文件、事实证据、已完成修改和验证，使完整流程从现状继续而不是重复开始。
- 异常或边界：匹配活动变更必须继续原变更，不能创建重复变更。

### 场景：原完整能力保持独立和完整

- 前置条件：任务直接选择 `frontend-change`，或由快速 Skill 交接。
- 当：完整流程判断当前阶段。
- 则：仍按原有 Plan、Revise、Implement、Complete 生命周期工作，保留原活动变更选择、需求同步和完成门禁。
- 并且：`frontend-change` 内不再包含快速通道分支或小修复描述。

## 页面与交互

- 入口与操作路径：自然语言中的明确局部实施请求可以隐式选择 `frontend-fast-change`；完整功能、活动变更或实质风险选择 `frontend-change`。
- 字段、文案与默认值：快速 Skill 开始时只说明采用快速通道的理由、预计影响区域和验证方式；结束时只报告实际文件、实际验证和实质剩余风险。
- 加载态、空态、错误态、禁用态：影响无法界定、事实冲突或验证不可成立时触发单次交接，不在快速 Skill 中继续扩张。
- 权限与角色差异：不增加文件、Git、外部系统或发布权限。
- 设计稿链接：不适用，本需求不涉及 UI。

## 兼容性与风险

- 受影响页面、公共组件、路由、权限或接口：不修改业务页面和接口；影响插件公开 Skill 选择与受管项目路由说明。
- 历史数据与兼容策略：已有需求、活动变更和归档资料保持不变；匹配活动变更继续由原 `frontend-change` 承载。
- 上线与回滚注意事项：新 Skill、元数据、公共清单、模板、文档和测试必须作为同一变更同步；不得只删除路由说明而遗留不可达 Skill。
- 主要风险：两个 Skill 描述重叠会导致误选；交接规则过宽会失去速度，过窄会绕过风险。通过互斥描述、实质风险语义、单次交接和原能力回归测试控制。
- 跨平台高风险：否。本变更不修改 CI、路径、临时目录、子进程、包管理器入口、环境变量或机器诊断；影响为 Skill 路由与文档合同。
