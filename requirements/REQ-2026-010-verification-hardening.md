# REQ-2026-010：统一验证、多框架覆盖与运行时完整性

## 基本信息

- 状态：已验收
- 提出人：用户
- 负责人：Codex
- 目标版本：0.11.0
- 关联页面或模块：仓库验证命令、GitHub Actions、多框架 fixture、OpenSpec 内置运行时、插件发布
- 关联变更：`harden-verification-and-runtime-integrity`

## 背景与目标

仓库已经具备项目识别、初始化、升级、检查、需求治理和 OpenSpec 1.7.0 内置运行时，但验证入口仍分散，多框架能力缺少完整工作流回归，内置运行时也缺少可重复核验的生产依赖、许可证和 SHA-256 清单。本需求建立可回退的 Git 基线，并用统一门禁完成三轮增强，使本地与 CI 使用同一套验证语义。

## 范围

### 包含

- 建立可回退的 Git 初始基线和独立实施分支。
- 新增统一 `verify` 命令并让 CI 调用同一入口。
- 增加四类框架/构建组合及三类包管理器 fixture。
- 生成并校验 OpenSpec 1.7.0 生产运行时完整性清单。
- 更新结构校验、自动测试、说明文档和插件版本。

### 不包含

- Monorepo workspace、多个 package 或多个前端应用的专项识别与编排。
- 安装或执行 fixture 的真实第三方构建依赖。
- 自动联网查询许可证或修改第三方运行时文件。
- 改写业务项目中没有受管标记的 AGENTS、OpenSpec 或 Wayfinder 内容。

## 当前行为

- Git 仓库没有历史提交，无法验证测试文件和工作流的历史归属。
- `npm test`、`npm run validate`、OpenSpec 严格校验和运行时版本检查需要分别执行。
- CI 只执行测试和结构校验。
- 项目识别器声称支持 Vue 2、Vue 3、React、Vite 和 Webpack，但完整工作流只在 Vue 3 + Vite 上回归。
- 内置运行时保留版本和许可证，但没有可核验的生产包与 SHA-256 清单。

## 期望行为

### 场景：开发者执行统一验证

- 前置条件：仓库文件与内置运行时完整。
- 当：执行 `npm run verify`。
- 则：测试、结构、OpenSpec、运行时版本和完整性校验按稳定顺序全部通过。
- 并且：任一子检查失败时命令立即以非零状态结束并指出失败阶段。

### 场景：验证多框架项目

- 前置条件：临时项目使用受支持的框架、构建工具和包管理器组合。
- 当：执行识别、初始化、重复执行、升级与检查关键路径。
- 则：预设、包管理器、真实项目命令和受管文件结果保持正确。
- 并且：测试不联网、不安装 fixture 依赖，也不把目录名当作识别依据。

### 场景：运行时内容发生漂移

- 前置条件：内置 OpenSpec 的版本、入口、生产包元数据、许可证或文件内容与清单不一致。
- 当：执行完整性校验或统一验证。
- 则：验证返回非零并定位缺失、增加或摘要变化的包。
- 并且：只有显式 `--write` 才可在确认升级后重建清单。

## 页面与交互

- 入口与操作路径：本地 `npm run verify`、GitHub Actions、运行时完整性脚本。
- 字段、文案与默认值：机器字段和命令参数使用稳定英文；面向开发者的失败信息使用中文。
- 加载态、空态、错误态、禁用态：命令行无加载态；缺少变更、规格、清单或运行时均明确失败；默认校验模式禁止写入。
- 权限与角色差异：不涉及业务角色；CI 使用只读仓库权限。
- 设计稿链接：不适用。

## 接口与数据

- 接口文档链接：不涉及网络接口。
- 请求方法与路径：读取根仓库、`openspec/specs`、插件 manifest、技能和 `runtime/openspec`；完整性清单写入插件运行时相邻固定路径。
- 请求字段及空值语义：缺少版本、入口、许可证、包名或摘要均视为无效。
- 响应字段及状态码：全部通过退出 0；失败退出非零；完整性清单使用稳定 JSON 字段和排序。
- 鉴权、加解密或敏感信息要求：不联网、不读取用户凭据；SHA-256 仅用于完整性核验，不用于签名。
