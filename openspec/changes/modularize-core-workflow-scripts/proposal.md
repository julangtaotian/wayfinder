## Why

三个共享工作流入口已分别达到 785、743 和 712 行，继续维护会增加 AI 读取成本并很快触发 800 行仓库预算。现在按 `REQ-2026-033` 的第一阶段先做纯模块化，让后续修改落在更小、更明确的职责边界内。

## What Changes

- 将完成归档入口中的恢复、归档后审计或协作职责下沉到内部模块，保留公开导出和 CLI 行为。
- 将需求决策校验入口中的 Markdown 解析与交付阶段校验职责下沉，保持四阶段结果兼容。
- 将验证证据入口中的清单、证据文件和记录校验职责下沉，保持 schema v2、稳定诊断和信任边界兼容。
- 复用现有手写测试覆盖公开导入、正常/失败/空态、重复恢复、Windows/POSIX 路径与子进程退出码。
- 三个原入口均降到 600 行以内，不新增依赖，不调整 800 行仓库预算。

## Capabilities

### New Capabilities

- 无。本变更不引入新的可观察能力。

### Modified Capabilities

- 无。`REQ-2026-033` 的 D-02 明确授权纯内部重构并设置 `skip_specs: true`，现有规格行为保持不变。

## Impact

- 受影响源码：`plugins/frontend-ai-workflow/scripts/finalize-change.mjs`、`validate-requirement-decisions.mjs`、`verification-evidence.mjs` 及新增内部模块。
- 受影响测试：完成归档、需求决策、验证证据和信任边界的现有手写测试。
- 兼容边界：公开导入路径、CLI 参数、JSON 字段、稳定错误码、退出码和中文诊断语义不变。
- 跨平台：命中路径、临时目录、子进程、环境变量和机器诊断，最终需要现有五平台矩阵证明精确提交。
- 不影响：CI 定义、Git LFS、平台运行时存储、检查器仓库类型识别和第三方依赖。
