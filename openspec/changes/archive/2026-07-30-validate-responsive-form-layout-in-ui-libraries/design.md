## Context

现有两套验收工程已分别运行 Vue 3 + Element Plus 与 Vue 2 + Element UI，并通过查询参数和 hash 支持组件证据模式。响应式表单是基础布局能力，不计入 183 条组件场景，也不应改变现有 manifest、导航与 A-05 证据入口。具体行为以 `specs/lanhu-design-spec-contract/spec.md` 为准。

本设计仅实现 `D-20`，全部验证结果必须能够映射到 `A-10`。

## Goals / Non-Goals

**Goals:**

- 在两套工程中增加相同结构、可独立打开的真实后台页面。
- 让页面布局直接响应实际浏览器视口，而不是通过缩放截图或固定宽度容器模拟。
- 暴露稳定的数据属性，便于浏览器读取组件库、列数、工作区和越界结果。
- 保持原有 26 个组件视图、183 条场景及证据 URL 不变。

**Non-Goals:**

- 不新增生产业务路由、接口、鉴权或服务端数据。
- 不把双组件库实现细节回写为通用设计事实。
- 不重新执行与本页无关的 183 条 A-05 视觉矩阵。

## Decisions

1. **使用专用查询参数入口。** 两套 `App.vue` 读取 `?layout=responsive-form`，命中时渲染独立 `ResponsiveFormLayout.vue`，否则保持现有组件验收页。相比修改 manifest，这不会伪增组件视图或场景计数。
2. **页面壳层使用固定几何闭合。** 顶栏高 `32px`、左侧导航宽 `108px`，工作区使用 `left:124px; top:48px; right:16px; bottom:16px`，在 `1024 × 768` 下自然得到 `884 × 704px`，避免仅为单一画板写死工作区宽高。
3. **字段使用 CSS Grid 和真实媒体查询。** 默认 3 列，在 `1440px` 与 `1920px` 切换为 4/6 列，列间距固定 `8px`；操作组是一个不可拆分的栅格项。相比组件库栅格，CSS Grid 可以在两套库中保持同一可测几何。
4. **组件本体由组件库提供。** 两套页面均使用 `el-form`、`el-form-item`、`el-input`、`el-select`、`el-option`、`el-date-picker` 和 `el-button`，只用局部 CSS 覆盖宽度和布局，不复制组件内部 DOM。
5. **浏览器证据同时包含截图和测量 JSON。** 每档读取视口、计算列数、列宽、列间距、工作区矩形、颜色、圆角、操作组矩形、组件标签、运行时版本和横向溢出量。截图供人工复核，JSON 供聚焦测试复现断言。

## Risks / Trade-offs

- [浏览器窗口无法精确改变 CSS 视口] → 优先使用浏览器提供的视口控制；若只能改变外部窗口，读取 `window.innerWidth` 并仅保存实际达到目标宽度的样本。
- [两个组件库日期控件内部宽度默认值不同] → 只覆盖字段容器内 `width:100%`，不修改组件内部视觉结构。
- [全局验收页 `min-width:1180px` 影响 1024 档] → 响应式专页挂载期间给根节点增加专用类，并在局部样式中覆盖为 `1024px`；普通验收页保持原值。
- [操作组在不同字段数量下位置变化] → 使用固定的收起/展开字段集和单个不可拆分 action item，通过展开前后两次测量验证。

## Migration Plan

1. 增加两套响应式页面组件和专用入口，不修改现有 manifest。
2. 扩展聚焦测试并完成两套生产构建。
3. 启动两套页面，采集五档截图和测量 JSON。
4. 验证通过后同步主规范并归档；回滚时删除专用组件与入口即可，原有组件验收页不受影响。
