## Purpose

为插件所有目标项目写入提供统一、可测试的真实路径安全边界，防止初始化、升级、迁移、取证或归档经项目内符号链接修改项目外内容，同时保持既有预览与受管写入兼容性。

## ADDED Requirements

### Requirement: 目标项目写入必须受真实项目根约束
系统 MUST 在创建、覆盖、移动、归档或删除目标项目内容前确定唯一真实项目根，并 MUST 检查目标及根以下每一级既有祖先。根以下的目标或祖先为符号链接、真实落点越出项目根或路径无法安全判定时，系统 MUST 失败关闭且不得读取或修改链接外内容。（D-02、D-03，A-01）

#### Scenario: 项目内祖先指向项目外
- **WHEN** 任一受管目标的根以下既有祖先是指向项目外目录的符号链接
- **THEN** 预览和显式写入均返回稳定的安全路径诊断，链接外哨兵内容保持不变

#### Scenario: 既有目标文件本身是符号链接
- **WHEN** 待覆盖、移动或删除的项目内词法目标是符号链接
- **THEN** 系统拒绝操作，不跟随链接读取、替换或删除真实落点

#### Scenario: 调用方通过符号链接选择项目根
- **WHEN** 调用方提供的项目根路径本身是指向一个普通项目目录的符号链接
- **THEN** 系统以该目录的唯一真实路径作为项目边界，并继续拒绝真实根以下的任何受管符号链接

#### Scenario: 普通目标尚不存在
- **WHEN** 目标及部分祖先尚不存在，但最近既有祖先是项目真实根以下的普通目录
- **THEN** 系统允许按原合同预览或创建该目标，且最终落点仍位于真实项目根内

### Requirement: 预览和正式写入必须使用同一安全判定
系统 SHALL 在 dry-run 与显式写入阶段对相同目标使用一致的真实根、范围和符号链接规则。未显式写入时 MUST 保持零修改；显式写入过程中任一目标不安全或原子操作失败时 MUST 保留原始文件和原始错误，不得通过部分成功扩大修改范围。（D-03、D-11，A-01、A-02）

#### Scenario: 安全项目先预览后写入
- **WHEN** 普通项目中的全部受管目标安全，用户先预览再显式写入
- **THEN** 两个阶段报告相同目标集合，预览不修改文件，正式写入只修改计划内目标

#### Scenario: 相同安全状态重复执行
- **WHEN** 同一受管写入在项目状态未变化时重复预览或重复显式执行
- **THEN** 系统保持稳定计划并将既有正确内容报告为 unchanged 或等价幂等结果

#### Scenario: 写入前路径状态变为不安全
- **WHEN** 预览后、正式写入安全检查前，目标祖先被替换为符号链接
- **THEN** 正式写入重新判定并失败关闭，不依赖旧预览结果，也不修改链接外内容

#### Scenario: 既有内容不受管理
- **WHEN** 安全路径上的既有文件缺少该入口要求的受管标记
- **THEN** 系统保留既有冲突保护，不因新增路径安全能力而覆盖该文件

### Requirement: 安全路径诊断必须跨平台可定位
系统 MUST 为路径越界、符号链接目标、符号链接祖先和无法解析的真实根返回稳定的机器字段，至少包含 `code`、`status` 和 `target`；平台相关路径 MUST 规范化后比较，且中文说明 MAY 保留平台实际展示形式。（D-09、D-10，A-06、A-07）

#### Scenario: POSIX 与 Windows 路径诊断
- **WHEN** 等价的危险目标以 POSIX 或 Windows 路径语义进入受支持入口
- **THEN** 系统以相同错误类别和非通过状态拒绝，测试不依赖完整平台路径文案
