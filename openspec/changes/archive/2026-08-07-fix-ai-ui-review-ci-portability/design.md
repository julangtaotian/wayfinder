## Context

参见 `proposal.md`。当前失败发生在 `tests/ai-ui-review.test.mjs` 的测试输入准备阶段：辅助函数调用固定的 `/opt/homebrew/bin/ffmpeg`，Linux 上 `spawnSync` 返回 `status: null`，三个用例在被测生成器逻辑之前失败。正式生成器本身已经支持从候选命令解析 FFmpeg，并要求存在中文字体。

## Goals / Non-Goals

**Goals:**

- 让同一份手写专用测试在 macOS 与 Linux CI 上得到一致结果。
- 保留 PNG 尺寸解析和产物生成所需的有效图片格式。
- 将产物编排测试与运行机器的 FFmpeg、字体安装状态隔离。

**Non-Goals:**

- 不改变正式生成器的 FFmpeg、字体探测与失败语义。
- 不给根项目或业务项目增加图片、字体或测试框架依赖。
- 不用测试工具替身替代既有真实验收和人工视觉证据。

## Decisions

### 使用 Node.js 标准库生成有效 PNG 测试输入

测试辅助函数使用 `Buffer`、`node:zlib` 和 PNG 标准块结构生成指定尺寸的纯白 RGBA 图片。这样既能覆盖真实 IHDR 尺寸解析，也能为后续产物流程提供有效输入，并落实不增加项目依赖的跨平台边界。（D-08、D-10）

备选方案是把 Base64 图片写死在测试中，但它难以审查尺寸来源且不支持辅助函数已有的宽高参数；调用系统 `ffmpeg` 仍会把测试结果绑定到 Runner 镜像。

### 产物编排测试使用临时 FFmpeg 工具替身

需要生成标注产物的用例在临时目录创建可执行 Node 脚本：版本探测时返回成功，生成时将输入 PNG 复制到声明的输出路径。测试同时提供临时字体占位文件，使生成器继续经过工具和字体参数解析，但不要求操作系统预装特定字体。（D-02、D-03、D-08、D-10）

工具替身只存在于测试临时目录，正式代码不接收特殊测试分支。真实绘制效果继续由既有双项目验收证据覆盖。

### 继续复用同功能的手写专用测试

所有回归场景保留在 `tests/ai-ui-review.test.mjs`，因为失败用例与修复辅助逻辑都属于 AI UI 验收产物生成，不创建第二个职责重叠的测试文件。

## Risks / Trade-offs

- [工具替身不验证 FFmpeg 绘制滤镜的真实渲染] → 保留正式生成器门禁和既有真实双项目视觉证据；本次测试只声明验证跨平台编排及产物合同。
- [手写 PNG 块实现可能产生格式错误] → 聚焦测试同时使用生成器尺寸解析与工具替身消费该文件，完整验证再覆盖所有现有断言。

## Migration Plan

1. 先替换测试输入和产物工具准备逻辑，不修改正式生成器。
2. 运行专用测试，再运行 GitHub Actions 同入口 `npm run verify`。
3. 若回归，回滚专用测试辅助逻辑即可；没有运行时数据或业务项目迁移。
