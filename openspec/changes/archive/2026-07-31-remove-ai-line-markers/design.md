## Context

本次变更横跨插件源码、测试、GitHub Actions、模板和历史验证产物，但目标行具有稳定的完整注释格式。参见 `proposal.md`。实现必须保留当前工作区中尚未提交的 CLI 安全加固改动，并遵守“不覆盖业务内容”的项目原则。

## Goals / Non-Goals

**Goals:**

- 用严格的整行匹配删除 259 行既有统计注释。
- 让根项目规则成为后续生成行为的事实源。
- 用独立测试扫描整个项目文本文件，防止同类注释回归。
- 通过差异检查和完整门禁证明删除没有改变代码行为。

**Non-Goals:**

- 不根据统计数字重新切分或格式化原代码。
- 不修改其他维护注释、Markdown 规划记录或依赖文件。
- 不刷新项目外安装缓存，不提交或推送工作区。

## Decisions

### 决策一：只删除匹配完整格式的独立注释行

清理器只接受 JavaScript、YAML、CSS 和 HTML 常见注释语法，并要求整行只包含统计标记及空白。这样可以覆盖盘点出的 259 行，同时避免删除字符串、文档说明或相邻代码。

备选方案是按关键词删除整行，但会误伤规则和需求文档；逐文件手工编辑则容易漏项且难以核对数量。

### 决策二：根规则明确禁止，专用测试提供机器门禁

`AGENTS.md` 增加适用于整个仓库的禁止规则，保留必要中文维护注释要求。专用测试递归扫描项目文本文件，排除 `.git` 和依赖目录；测试使用完整注释结构识别目标，因此允许规则文档以普通文本准确描述禁令。

仅写规则无法阻止未来工具遗漏；把检查混入大型综合测试又会削弱职责边界，因此采用独立测试。

### 决策三：旧验证材料改为服从当前根规则

两份历史验证材料中的生成和核对要求改写为不生成统计注释，避免执行旧隔离流程时重新引入已清理内容。其他历史证据不做语义重写。

### 决策四：不产生 delta specs

本次只改变仓库维护规则、注释和测试门禁，不改变插件或目标项目的可观察运行行为。需求 D-04 已明确授权 `skip_specs: true`，因此 specs artifact 保持 `skipped`。

## Risks / Trade-offs

- [整行匹配遗漏变体] → 清理前后同时使用递归扫描和专用测试，并核对 259 行基线。
- [删除注释导致语法拼接] → 每个标记原本独占一行；删除后运行差异检查、Node 测试和完整统一门禁。
- [扫描二进制或依赖造成误报和性能问题] → 排除 `.git` 与 `node_modules`，检测二进制内容后跳过，其他项目文件均纳入。
- [覆盖现有未提交改动] → 机械处理只删除目标完整注释行，随后按文件和差异类型复核，不重写其他内容。

## Migration Plan

1. 增加根规则和专用策略测试。
2. 按完整注释格式机械删除既有标记，并改写两份冲突说明。
3. 核对删除数量、剩余文本和差异格式。
4. 运行聚焦测试与完整统一门禁。
5. 若验证失败，只回退本次规则、测试和注释清理；不触碰此前 CLI 安全加固改动。
