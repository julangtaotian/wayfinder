## Context

见 `proposal.md`。当前插件把完整 OpenSpec 1.7.0 生产依赖闭包纳入发布物，通过包装器固定入口和版本，并用包树摘要检查漂移；检查器和完成器把 `status.isComplete` 当作规划完成门槛。1.8.0 保留兼容字段，但新增更准确的 `isPlanningComplete`，同时更改生成式工作流指引、任务解析和归档行为。

## Goals / Non-Goals

**Goals:**

- 在替换工作区运行时前完成官方候选包、严格规划数据和关键 1.8.0 场景验证。（D-01、D-02；A-01）
- 以一个兼容归一值消费规划完成状态，不让新字段替代任务、验收、证据或 artifact 门禁。（D-04；A-02）
- 使内部参考吸收 1.8.0 的安全修复，同时继续执行插件需求治理、Store 和写入边界。（D-03、D-06、D-08；A-04、A-05）
- 让仓库元数据、说明和自动测试能够证明实际发布的是 0.13.0 / OpenSpec 1.8.0。（D-09、D-10；A-06）

**Non-Goals:**

- 不把 OpenSpec 自身工具适配器作为插件公共 Skills 发布。
- 不修改业务项目已有 `.agents`、`.codex`、Copilot 或规划数据。
- 不通过兼容代码隐藏 1.8.0 新增的严格校验失败。

## Decisions

### 候选运行时在临时目录完成闭包验证后整体替换

使用精确版本、生产依赖和禁用生命周期脚本的 npm 安装构建候选；先运行版本、当前仓库严格校验和专用兼容 fixture，再用可恢复备份替换固定目录并重建完整性清单。（D-01、D-02；A-01）

替代方案是在现有 `runtime/openspec` 中直接执行 npm 更新。该方案可能遗留 1.7.0 已删除文件或半更新依赖，无法满足混合版本失败关闭要求，因此不采用。

### 使用显式的规划完成兼容归一值

检查器计算 `isPlanningComplete = status.isPlanningComplete ?? status.isComplete`，错误信息和结构化报告公开新字段，同时保留 `isComplete` 兼容输出。artifact 逐项状态和插件自己的任务解析继续独立执行。（D-04、D-05；A-02、A-03）

替代方案是继续只读别名 `isComplete`。虽然 1.8.0 暂时兼容，但会继续把规划完成误称为整体完成，无法体现本次升级语义，因此不采用。

### 从 1.8.0 临时生成物对照合并内部参考

在临时 fixture 使用候选运行时生成 `agents` Skills，只对照六个内部参考的上游差异，手工保留插件的需求台账、根目录边界和完成硬门禁。业务项目初始化和升级脚本不调用上游 `init` 或 `update`。（D-03、D-08；A-05）

替代方案是直接覆盖内部参考。它会丢失插件治理规则并可能重新引入全局命令或绕过路径，因此不采用。

### 包装器双重关闭联网相关行为

所有内置运行时调用同时设置 `OPENSPEC_NO_UPDATE_CHECK=1` 和 `OPENSPEC_TELEMETRY=0`，测试直接捕获传给子进程的环境契约并验证运行时版本。（D-07；A-05）

### 发布版本按共享能力提升为 0.13.0

同步根 package、工作流常量、插件 manifest cachebuster、README 和受管项目版本断言。升级仍只更新带受管标记的内容。（D-09；A-06）

## Risks / Trade-offs

- [风险] 1.8.0 依赖闭包或包内容变化导致完整性清单大范围更新 → 在候选目录先核验每个直接依赖和 LICENSE，再整体替换并重复计算清单。（D-02；A-01）
- [风险] `isPlanningComplete` 与旧测试替身不一致 → 使用空值回退而不是逻辑或，分别测试新字段优先和旧字段兼容。（D-04；A-02）
- [风险] 缩进任务计数上升使旧变更不再显示完成 → 保留该更严格行为，测试未完成子任务阻断，并在说明中记录示例复选框的已知上游限制。（D-05；A-03）
- [风险] 上游参考合并覆盖插件自有安全规则 → 仅人工选择性合并并运行官方 validator、结构校验和关键禁用路径断言。（D-03、D-10；A-05、A-06）

## Migration Plan

1. 构建并验证临时 1.8.0 候选，不修改现有运行时。（D-01、D-02；A-01）
2. 更新状态兼容、遥测环境、版本常量和聚焦测试。（D-04、D-05、D-07；A-02、A-03、A-05）
3. 备份并整体替换运行时，重建完整性清单，三方合并内部参考。（D-02、D-03；A-01、A-05）
4. 同步 0.13.0 发布元数据和说明，运行聚焦、全量、严格、结构、完整性与官方 validators。（D-09、D-10；A-06）
5. 任一步失败时保留或恢复 1.7.0 运行时，并保持变更未完成状态。
