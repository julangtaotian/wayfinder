## Context

插件把完整 OpenSpec 1.8.0 生产依赖闭包纳入发布物，通过包装器固定入口和离线环境，并用包树摘要检查漂移。1.9.0 保持现有 CLI 主接口，但新增归档任务范围并收紧批量根目录、任务编号、Scenario 识别、非交互 archive 和 apply 指导语义。

## Goals / Non-Goals

**Goals:**

- 在替换工作区运行时前完成官方候选包、现有规划数据和关键 1.9.0 场景验证。（D-01、D-02；A-01、A-03）
- 将归档任务检查加入统一只读门禁，并保留活动变更与主规格严格校验。（D-04；A-02）
- 使内部 apply 参考吸收意外范围报告要求，同时继续执行插件需求治理和完成硬门禁。（D-03、D-08；A-04、A-05）
- 让仓库元数据、测试和已安装缓存证明实际发布 0.14.0 / OpenSpec 1.9.0。（D-09、D-10；A-06）

**Non-Goals:**

- 不把 Command Code 或其他 OpenSpec 工具适配器作为插件公共 Skills 发布。
- 不修改业务项目已有 `.agents`、`.codex`、规划数据或归档任务。
- 不把归档任务检查合并进活动变更严格校验，也不通过警告掩盖非零失败。

## Decisions

### 候选运行时在临时目录核验后整体替换

使用精确版本、生产依赖和禁用生命周期脚本的 npm 安装构建候选；先运行版本、入口、生产依赖、许可证、当前仓库严格校验、归档校验和专用 fixture，再整体替换固定目录并重建完整性清单。（D-01、D-02；A-01）

不在现有运行时目录执行增量 npm update，避免残留 1.8.0 已删除文件或形成混合依赖闭包。

### 归档校验作为统一验证的独立阶段

在 `scripts/verify.mjs` 中新增稳定 id `openspec-archived`，调用 `validate --archived --no-interactive`。它位于活动/主规格严格校验之后、版本和完整性之前；失败立即停止并报告独立阶段。（D-04；A-02）

不使用 `--archived` 替换 `--all --strict`，因为上游明确将两者定义为独立范围，归档检查也不会重新应用 delta。

### 聚焦测试直接验证上游 1.9.0 行为

使用临时 OpenSpec 根和真实内置 CLI 覆盖：错误目录批量命令非零、归档未完成任务非零、模糊任务编号诊断、非标准四级 Scenario 丢失阻断、无 TTY archive 不含 ANSI 且输出有界。（D-04、D-05、D-06；A-02～A-04）

规格 LF、Requirements 空行和 schema fork 格式通过最小 fixture 验证，避免依赖人工 diff。（D-07；A-03）

### apply 参考采用三方合并

以 1.9.0 上游 apply Skill 为对照，只合并“意外范围必须报告、不得静默缩减、完成任务必须完整实现”的语义；保留插件的需求台账、Store 选择、根目录和完成证据规则。（D-03、D-08；A-04、A-05）

### 发布版本提升为 0.14.0

同步根 package、`WORKFLOW_VERSION`、受管模板、升级 Skill、README 和插件 manifest；最后使用官方 cachebuster helper 只替换一个后缀，再通过已配置的本地 marketplace 重装。（D-09、D-10；A-06）

## Risks / Trade-offs

- [风险] `validate --archived` 暴露历史未完成任务 → 候选阶段先运行并定位；只修正规划事实错误，不自动勾选真实未完成工作。（D-04；A-02）
- [风险] 1.9.0 依赖闭包变化扩大插件体积 → 重建完整性后生成当前平台成品并继续执行既有体积预算。（D-02、D-10；A-01、A-06）
- [风险] 新任务编号警告影响现有活动变更 → 聚焦记录诊断并修复本次变更的歧义，不静默过滤上游 warnings。（D-05；A-03）
- [风险] 上游 apply 覆盖插件自有规则 → 只选择性合并新增语义并运行官方 Skill validator。（D-03、D-08；A-04、A-05）

## Migration Plan

1. 建立需求与完整规划 artifact，使用 1.8.0 严格验证规划。（D-01～D-10；A-01～A-06）
2. 在独立临时目录安装并核验官方 1.9.0 候选，不修改当前运行时。（D-01、D-02；A-01）
3. 先补聚焦失败测试，再整体替换运行时、更新版本和统一验证。（D-04～D-07；A-02～A-04）
4. 合并 apply 参考，更新 0.14.0 文档与 cachebuster，运行全量门禁和官方 validators。（D-03、D-08～D-10；A-04～A-06）
5. 生成并重装当前平台瘦身包；任一步失败时恢复 1.8.0 并保持变更未完成。（D-02、D-10；A-01、A-06）
