## Context

品牌前缀分散在两套 Markdown 规范、图标清单、验证证据说明、历史原生验证页、两套 Vue 验证页源码以及已经生成的静态资源中。只修改 README 会导致用户从其他入口仍看到旧文案，因此需要同时处理源文件与生成产物。

本变更依据 `D-18`，完成判定使用 `A-08`。

## Goals / Non-Goals

**Goals:**

- 所有交付入口和验证页面统一使用通用后台规范名称。
- 源码与重新生成的静态产物同时消除旧品牌前缀。
- 用聚焦测试固定零残留契约。

**Non-Goals:**

- 不修改组件样式、场景、交互、图标文件或设计数值。
- 不修改蓝湖链接、文件路径或组件库版本。
- 不重采既有视觉证据。

## Decisions

### 1. 将全部交付文案纳入同一清理范围

扫描范围覆盖 `outputs/lanhu-design-spec/`、`outputs/lanhu-ai-ui-spec/`、验证页源码和构建产物，而不只处理两个 README。这样可以保证从文档、历史验证页或双组件库页面进入时文案一致。

### 2. 生成产物通过正式构建更新

两套 Vue 验证页先修改 `src/App.vue`，再运行各自 `npm run build`。不直接手改压缩后的 JavaScript，避免产物与源码不一致。

### 3. 聚焦测试扫描文本类交付文件

在现有手写测试中扫描 Markdown、HTML、Vue、JavaScript 和 JSON 文本文件，并断言通用标题存在。测试中的禁用词使用 Unicode 转义表达，避免测试源码自身产生误报。

## Risks / Trade-offs

- [风险] 旧构建文件因哈希变化残留在 `dist/assets`。→ 使用 Vite 正式构建清理并重新生成目录，再对构建产物扫描。
- [风险] 过度替换误伤组件内容或路径。→ 只替换完整展示文案，测试继续验证 30/29/26/183 结构不变。
- [权衡] 不重新执行视觉截图。→ 本变更只修改文字标题，不改变组件区域视觉，聚焦契约测试与生产构建足以覆盖。
