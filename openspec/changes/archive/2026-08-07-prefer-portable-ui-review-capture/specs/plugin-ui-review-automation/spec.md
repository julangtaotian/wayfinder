## ADDED Requirements

### Requirement: UI 验收必须提供可移植采集计划和显式视觉兜底
系统 SHALL 为每个场景输出机器可读采集计划，计划 MUST 包含主采集器、可选兜底采集器、允许的采集顺序和项目 Playwright 的可移植性信息。项目 Playwright 作为主采集器时，配置 MUST 能够以参数数组声明项目命令和项目内结果路径；视觉采集器只能在场景已声明时作为显式兜底。没有新增字段的既有单采集器配置 MUST 保持原行为。（D-08、D-09，A-01、A-02、A-06）

#### Scenario: 其他 AI 工具读取项目 Playwright 主路径
- **WHEN** 场景以项目 Playwright 为主采集器并声明有效命令参数和结果路径
- **THEN** 采集计划输出可直接执行的参数数组、结果路径、`portable: true` 和已声明的视觉兜底，且不要求 Codex Browser

#### Scenario: 主采集器不可用时选择视觉兜底
- **WHEN** 项目 Playwright 无法产生完整证据且场景已声明 Browser 兜底
- **THEN** 调用方可以显式选择 Browser 开始验收，运行状态记录 Browser 为实际采集器

#### Scenario: 老配置没有兜底字段
- **WHEN** 场景只声明既有 `browser` 或 `project-playwright` 采集器
- **THEN** 采集计划只允许该采集器，不自动增加或切换到另一种采集器

#### Scenario: 采集计划包含非法命令或兜底
- **WHEN** Playwright 命令为空、结果路径越界、兜底与主采集器相同或调用方选择未声明采集器
- **THEN** 系统以中文错误拒绝配置或运行，不执行命令且不创建错误通过状态

## MODIFIED Requirements

### Requirement: 复验必须使用相同场景上下文
系统 SHALL 只允许使用与基线运行相同的场景指纹创建复验；复验 MUST 复用页面、视口、设计依据、目标节点、交互说明和基线实际采集器，并 MUST 按稳定问题指纹区分已关闭、未解决和新增问题。只有未解决与新增问题均为空时结果 SHALL 为通过。（D-06、D-09，A-04、A-06）

#### Scenario: 修复后问题全部关闭
- **WHEN** 复验场景指纹与基线一致，使用基线实际采集器，原问题全部消失且没有新增高置信度问题
- **THEN** 复验状态为通过，并列出已关闭问题

#### Scenario: 复验出现未解决或新增问题
- **WHEN** 复验仍包含原问题或出现新的稳定问题指纹
- **THEN** 复验状态为失败，并分别列出未解决和新增问题

#### Scenario: 复验上下文发生变化
- **WHEN** 当前配置计算出的场景指纹与基线运行不同，或者基线实际采集器已不在当前采集计划中
- **THEN** 系统拒绝直接复验并要求重新开始一次独立验收

### Requirement: 插件自动化不得静默扩大外部依赖与权限
系统 SHALL 优先使用目标项目已经声明的 Playwright 命令和机器可读证据；只有场景显式声明且当前环境提供能力时，才可使用 Codex Browser 或同类视觉能力作为兜底。系统不得静默安装浏览器、修改主分支、提交或推送代码、创建 PR、读取认证数据或绑定特定 AI 工具与代码托管服务。（D-01、D-03、D-07、D-08、D-09，A-03、A-05、A-06）

#### Scenario: 当前环境没有可用采集器
- **WHEN** 项目 Playwright 主路径不可执行或没有完整证据，且未声明视觉兜底或当前 AI 工具不提供该能力
- **THEN** UI 验收入口报告明确阻塞，不安装依赖，也不生成虚假通过结果

#### Scenario: 确定性主路径可用
- **WHEN** 项目 Playwright 命令成功产生配置要求的实际截图和结构化结果
- **THEN** 系统使用该证据完成验收，不再要求或自动调用视觉兜底
