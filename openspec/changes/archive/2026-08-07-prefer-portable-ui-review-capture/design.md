## Context

现有配置把 `capture` 固定为 `browser` 或 `project-playwright`，运行状态在创建时直接复制该值。工作流没有项目命令合同，也不能在同一场景中安全表达主采集器和兜底采集器。插件必须继续只使用 Node.js 标准库、拒绝危险路径、保持老配置语义，并让复验绑定首次实际使用的采集器。

## Goals / Non-Goals

**Goals:**

- 输出其他 AI 工具和 CI 可直接消费的确定性采集计划。
- 允许同一场景声明 Playwright 主路径和 Browser 视觉兜底。
- 把“配置的采集策略”和“运行实际使用的采集器”分开记录。
- 保持现有配置、状态版本和报告合同兼容。

**Non-Goals:**

- 不在插件核心中执行任意项目命令或安装 Playwright。
- 不新增图像识别依赖，也不替代项目自己的截图差异实现。
- 不让视觉兜底绕过高置信度、源码范围或复验门禁。

## Decisions

### 使用兼容字段扩展现有场景，而不升级配置版本

保留 `capture` 作为主采集器，新增可选 `captureFallback` 和 `projectPlaywright`。后者包含非空字符串参数数组 `command` 与安全的项目相对 `resultPath`。规范化后派生 `capturePlan`：主采集器、兜底、顺序、Playwright 命令和 `portable` 标记。（D-08、D-09，A-02、A-06）

老配置没有新增字段时，计划只包含原采集器。相比把 `capture` 改成对象，这种方式不会破坏现有配置解析器和场景事实；相比升级 `schemaVersion`，无需一次性迁移所有项目。

### 新增只读采集计划命令，插件不直接执行项目命令

工作流 CLI 增加 `capture-plan --scenario <id> --run-id <id>`，只输出经过校验的 JSON。项目命令以参数数组表示，并只允许使用 `{scenarioId}`、`{runId}`、`{runDirectory}`、`{actualScreenshot}`、`{reviewInput}`、`{designPath}` 和 `{url}` 占位符；计划输出时替换为经过校验的项目事实，不经过 Shell 拼接。调用方在目标项目已有权限边界内执行，插件不自动安装依赖，也不把任意命令执行权限藏进配置解析阶段。（D-07～D-09，A-01、A-02、A-06）

其他 AI 工具只需调用 `inspect`、`capture-plan`、`start-review`、报告生成和 `complete-review`，不需要 Codex 专用 Browser API。

### 开始验收时显式选择实际采集器

`start-review` 增加可选 `--capture`。省略时使用主采集器；传入值必须出现在场景 `capturePlan.order` 中。运行状态的 `capture` 保存实际选中值，场景指纹则覆盖整个采集策略、Playwright 命令、结果路径、页面、视口、设计依据、目标节点和交互。（D-09，A-02、A-06）

这样主路径失败后可以用新运行 ID 显式选择兜底，而不是在同一运行里静默改写状态。相比自动捕获命令失败并切换，这种方案保留清晰证据和可审计边界。

### 复验绑定基线实际采集器

创建复验时确认当前策略指纹等于基线指纹，并确认基线 `capture` 仍在当前计划中。复验运行直接继承该值，不接受重新选择采集器。主路径和兜底产生的截图渲染差异因此不会被错误比较。（D-06、D-09，A-04、A-06）

### Skill 采用确定性优先、视觉兜底的统一顺序

UI 验收 Skill 先读取 `capture-plan`：可移植 Playwright 主路径可用时执行项目已声明命令；命令失败、缺少完整产物或明确不可用时，只有已声明 Browser 兜底且当前工具提供能力才开始新的兜底运行。UI 复验 Skill 只执行状态记录的实际采集器。UI 修复 Skill 不改变写入门禁，但共享参考会明确采集来源不授予额外源码权限。

## Risks / Trade-offs

- [项目命令虽然已声明但在当前环境不可执行] → 计划仍标明声明事实；调用失败后保留输出并仅允许显式兜底。
- [其他 AI 工具不理解 Skill] → CLI、JSON 配置与结果合同独立存在，不要求读取 Codex Skill 才能执行。
- [视觉兜底和 Playwright 输出差异] → 每次运行记录实际采集器，复验禁止切换。
- [新增字段参与指纹导致配置修改后不能复验旧基线] → 这是预期安全行为；策略变化需要新验收，老配置本身不变时指纹保持稳定。

## Migration Plan

1. 扩展配置规范化、采集计划、运行创建和复验检查，保留旧输入测试。
2. 更新模板、三个 Skill、共享参考、README 和专用测试。
3. 运行聚焦与全量验证、官方 validators，再更新插件 cachebuster 并重装。
4. 如需回滚，删除新增字段和采集计划命令；既有单采集器配置与状态继续可读。
