## Context

见 `proposal.md` 的 Why。正文已保存 12 个唯一规范化名称，README 第 34～45 行仍按蓝湖源顺序列出旧名称；两处行顺序本来一致，可以通过逐行替换和契约对比完成同步。（D-21；A-11）

## Goals / Non-Goals

**Goals:**

- 让 README 与响应式正文提供同一组、同一顺序的 12 个可读名称。
- 保持 README 共 45 行画板映射及既有链接不变。
- 通过测试防止正文和目录名称再次漂移。

**Non-Goals:**

- 不修改响应式正文中的布局规则或画板 ID。
- 不重排 README 其他 33 张画板。
- 不修改蓝湖源画板名称、验证页面或构建产物。

## Decisions

1. **README 直接复用正文名称，不创建第二套简称。** 目录中保留“后台适配规范 / ”前缀，后半部分完整使用正文的“尺寸｜列数｜状态/用途”，避免模型维护两套映射。
2. **保持现有源顺序。** README 第 34～45 行与正文映射当前使用同一顺序，只替换显示文本，不改变行号和链接。
3. **测试比较有序数组。** 从正文第一列和 README 第 34～45 行分别提取名称，使用深度相等断言；另检查 README 响应式索引片段无 `copy`。

## Risks / Trade-offs

- [目录文字变长，窄窗口换行] → Markdown 表格允许自然换行，名称仍优先保证语义完整。
- [人工只改一处导致再次漂移] → 聚焦测试直接比较两处有序名称数组。

## Migration Plan

1. 替换 README 第 34～45 行的展示文案。
2. 扩展既有响应式规范测试并运行聚焦验证。
3. 完成需求校验、规格同步和归档。
