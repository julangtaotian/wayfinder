## Context

现有 Wayfinder 只有 `meta`、`scope` 和 `analysis` 三个受管区块，项目概览与目录职责位于区块之间。升级逻辑只替换已声明区块，因此新识别结果进入 meta，却无法刷新对应的人类可读事实。深度初始化还只允许 AGENTS 和 Wayfinder 更新，导致已有 OpenSpec 配置继续保留旧画像。检查器只验证标记结构和范围指纹，没有复用升级渲染结果判断内容漂移。范围收集器则通过固定文本扩展集合决定读取边界，当前缺少微信小程序三类文本源码。参见 `proposal.md` 与三个增量规格。（D-01～D-07；A-01～A-03）

## Goals / Non-Goals

**Goals:**

- 让所有可重复生成的项目事实拥有明确受管边界，并兼容既有 0.11.0 Wayfinder。
- 让深度刷新、显式升级和只读检查复用同一套渲染语义，避免各入口自行拼接比较规则。
- 扩大微信小程序文本覆盖时保持现有安全、预算和稳定排序契约。

**Non-Goals:**

- 不让范围脚本自动解释 WXML/WXSS/WXS 业务语义。
- 不改变 AI 深度分析正文、项目自定义规则、平台识别或命令执行边界。
- 不把内容漂移升级为结构错误或自动修复授权。

## Decisions

### 1. 新增 Wayfinder `facts` 受管区块

模板将项目概览、平台验证边界和目录职责整体包在 `frontend-ai-workflow:facts:start/end` 之间，Wayfinder 描述符按 `meta → facts → scope` 顺序刷新。相比把这些内容塞入 meta，独立区块保留机器字段与人类导航的职责分离；相比接管整个 Wayfinder，它不会覆盖 analysis 和文档维护区。（D-02、D-07；A-01）

### 2. 通过稳定标题边界一次性迁移旧 facts

替换前若既有 Wayfinder 缺少 facts 标记，逻辑只接受从唯一的 `## 项目概览` 到 `scope` 起始标记之间的连续区域，并用新渲染的完整 facts 区块替换。标题缺失、重复或顺序异常时返回 conflict。迁移后沿用通用受管区块替换流程，避免为旧版长期维护第二套渲染逻辑。（D-02、D-07；A-01）

考虑过仅按若干行正则替换字段，但这种做法会遗漏后续新增字段且容易修改项目自定义文本，因此不采用。

### 3. 深度刷新同步 OpenSpec，检查器复用升级预览

OpenSpec 描述符增加 `updateWhenDeep`，使深度初始化对已有合法受管配置生成更新计划。项目检查调用普通升级的只读预览，并把 action 为 `update` 的文件映射为 `managedContentFreshness`；冲突继续由既有结构检查处理。复用升级预览能保证“检查认为过期”和“升级实际会修改”的定义一致，并保留 scope 快照。（D-03、D-04、D-07；A-01、A-02）

考虑过在检查器内逐字段解析三种文档，但会复制模板语义并随模板演进漂移，因此不采用。

### 4. 扩展文本类型并升级范围版本

在现有 `TEXT_EXTENSIONS` 中加入 `.wxml`、`.wxss`、`.wxs`，范围版本改为 `2.1.0`。文件仍先经过敏感路径、Git 忽略、大小、总量和空字节检测，分类规则沿用 pages/components 目录优先级。新增文件自然进入内容摘要和指纹，无需另建小程序扫描器。（D-05、D-06、D-07；A-03）

## Risks / Trade-offs

- [旧 Wayfinder 的标题被项目手工改写，无法自动迁移] → 只返回 conflict，并保留原文件让用户决定，不扩大模糊匹配。
- [加入小程序文件后大项目更容易达到 20 MiB 总量] → 保留源码优先和稳定超限原因，在目标项目复核实际纳入/排除统计。
- [检查器调用升级预览增加一次渲染与项目识别] → 预览不做深度扫描、不写文件，复用结果优先于维护重复比较逻辑。
- [内容漂移警告被误解为检查失败] → 输出独立 freshness 对象并保持非阻断 warning，与结构 errors 分离。

## Migration Plan

1. 发布新版模板与迁移逻辑，先用 fixture 验证无 facts 标记的旧 Wayfinder 预览与写入。
2. 更新范围版本后，对既有深度项目运行检查时自然产生快照过期警告；只有显式深度写入才刷新范围与分析。
3. 通过缓存版本更新重装本地插件，对目标微信小程序执行只读升级预览和检查。
4. 如需回滚，恢复插件版本；目标项目所有写入均可通过 Git 恢复，未提交文件可在确认后重新生成。
