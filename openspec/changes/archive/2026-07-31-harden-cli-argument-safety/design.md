## Context

现有严格入口已经对缺值和未知参数抛出中文错误，但五个早期入口仍各自维护宽松循环。安全加固需要覆盖多个脚本，同时避免把新的解析行为散落复制。参见 `proposal.md` 和 `specs/cli-argument-safety/spec.md`。

## Goals / Non-Goals

**Goals:**

- 使用一个仅依赖 Node.js 标准语义的共享解析器统一值型和布尔型选项。
- 在调用任何项目函数前完成全部参数校验。
- 维持各入口现有默认值、合法参数和 JSON 输出。
- 用独立测试从真实子进程入口验证退出状态、错误信息和零副作用。

**Non-Goals:**

- 不改变内部 OpenSpec 透传参数、项目识别规则或受管文件内容。
- 不重构已经严格且包含专用业务校验的完成、变更检查和需求校验入口。
- 不增加参数缩写、`--target=<path>`、帮助页面或第三方解析依赖。

## Decisions

### 决策一：使用声明式共享解析器

新增内部参数解析模块，调用方提供默认值、值型选项映射和布尔型选项映射。解析器复制默认值，顺序处理参数，遇到未知选项或无效值立即抛出中文错误。

选择该方案是为了让五个入口共享完全相同的边界。逐文件补条件虽然改动更少，但以后容易再次出现行为漂移；引入第三方参数库则违反当前零依赖约束。

### 决策二：`--` 开头的后继令牌不能充当值

值型选项只接受非空且不以 `--` 开头的字符串。这样 `--target --write` 会稳定报告目标缺值，不会吞掉写入选项或把错误路径传给文件系统。单横线开头的合法路径仍保持可用。

### 决策三：从子进程验证 CLI 边界

新测试直接执行五个脚本，而不是只测试解析函数。这样可以同时证明 stderr、退出码、入口调用顺序和写入型命令零副作用。合法调用也通过同一子进程路径验证，避免只覆盖失败分支。

## Risks / Trade-offs

- [历史调用依赖未知参数被忽略] → 这是错误用法，按需求改为明确失败，并保持所有声明参数兼容。
- [共享解析器影响五个入口] → 使用专用聚焦测试覆盖每个入口，再运行完整统一门禁。
- [目标路径确实以双横线开头] → 该路径将不再作为直接值支持；绝对路径不会命中此限制，且插件安全性优先于这一极少见相对路径。
- [解析器被误用于 OpenSpec 透传入口] → 本轮只接入 D-01 明确的五个入口，不修改透传包装器。

## Migration Plan

1. 增加共享解析器并接入五个入口。
2. 运行专用 CLI 安全测试和完整统一门禁。
3. 保持插件基础版本不变，仅按本地插件开发流程刷新 cachebuster。
4. 如出现合法调用兼容回归，回退五个入口的解析器接入即可；不涉及项目数据迁移。
