## Context

现有两套验证项目已经为场景卡片提供 `data-scenario-id`、`data-component-id` 和组件库标识，并保留组件规范与参考证据。新的交付形态需要把“AI 负责视觉判断”和“工具负责稳定生成文件”分离，同时遵守仓库仅使用 Node.js 标准库、错误信息中文和不增加验收文件的约束。设计承接 REQ-2026-019 的 D-01、D-02、D-03、D-04、D-05、D-06、D-07、D-08，详见 `proposal.md` 与 `specs/ai-ui-review-artifacts/spec.md`。

## Goals / Non-Goals

**Goals:**

- 让 AI 能在真实页面中关联设计规则、计算样式、DOM 选择器和截图坐标。
- 用一个确定性命令把 AI 结论转换成恰好两份交付文件。
- 保证问题过滤、坐标校验、编号映射、原子写入和零问题有限结论可自动测试。
- 用两套现有项目生成可直接查看的首轮结果。

**Non-Goals:**

- 不在 Node 工具内部调用远程模型、蓝湖或 Figma 服务。
- 不重做 183 场景历史证据系统，也不自动修改被验收源码。
- 不将像素差异算法当作 AI 视觉结论的唯一来源。

## Decisions

### 1. AI 判断与产物渲染分层

浏览器会话负责打开页面、等待渲染、读取 DOM 和计算样式，并由 AI 依据本地设计规范判断差异。生成器只接收当前截图和结构化结论，不自行声称理解设计。

选择该方案是因为节点语义与视觉判断需要页面上下文，而文件数量、编号和错误边界更适合确定性程序保证。备选方案是在生成器内接入远程模型，但会增加鉴权、成本、隐私和不稳定依赖，不适合本轮本地原型。

### 2. 中间输入只存在于临时目录

AI 采集的原始 PNG 与结构化 JSON 写入系统临时目录，生成器成功后只把最终 PNG 与 Markdown 原子移动到专属项目目录。输出目录如果存在未知文件则拒绝执行，不主动删除用户文件；已知两个结果可以安全替换。

该设计同时满足两文件交付和非破坏性约束。备选方案是把输入 JSON 放在结果目录供追溯，但会直接违反精简交付要求。

### 3. 统一输入合同

输入包含：

- `project`：名称、运行时、页面入口、设计依据和覆盖范围。
- `viewport`：宽、高、DPR 与缩放。
- `findings`：可选问题编号、稳定选择器、组件路径、节点文本、矩形坐标、类型、短标签、问题描述、当前值、目标值、修改要求、置信度和可选几何差值。

生成器只交付 `confidence=high` 的问题。尺寸或间距问题若 `differencePx < 2` 且没有 `exact=true` 则过滤；随后以选择器为键合并关联差异并限制为最多十个节点。显式重复编号、无选择器、无节点语义或越界矩形直接失败。

### 4. 使用 FFmpeg 在原始截图上绘制

生成器解析 PNG 头部获得像素尺寸，以数组参数调用 FFmpeg，在单一滤镜链中绘制红色节点框、编号、短标签和顶部结论；零问题使用绿色通过标签。中文文本通过系统字体与临时 `textfile` 输入，避免 shell 拼接和滤镜文本转义风险。

选择 FFmpeg 是因为仓库既有视觉工具已经依赖本机 `/opt/homebrew/bin/ffmpeg`，无需新增 npm 包。备选方案是增加 Canvas/Sharp，会引入新的二进制依赖；生成 SVG 则不满足最终 PNG 要求。

### 5. Markdown 作为唯一节点级机器可读交付

Markdown 顶部记录项目、页面、视口、设计依据、覆盖范围、问题数和过滤数。每个问题使用稳定标题编号，并固定输出选择器、组件路径、节点文本、截图坐标、类型、问题、当前值、目标值、修改要求与置信度。零问题时仍列出实际检查节点与有限结论，不额外交付 JSON。

### 6. 测试策略

新建 `tests/ai-ui-review.test.mjs`，导入生成器的纯校验和 Markdown 函数，并使用临时 PNG 与临时输出目录执行真实 FFmpeg 冒烟。测试覆盖有问题、零问题、过滤、上限、重复编号、越界、缺少节点、未知输出文件和重复生成。浏览器人工复核只用于确认真实页面节点与截图标注关系；两套项目生产构建确认现有页面可交付。

## Risks / Trade-offs

- [AI 视觉判断存在误报或漏报] → 只交付高置信度问题，保留 `2px` 默认容差、设计依据和有限覆盖范围。
- [系统字体或 FFmpeg 不可用] → 启动时显式探测并以中文错误失败，不生成通过报告。
- [DPR 导致 DOM CSS 坐标与图片像素不一致] → 输入同时记录 DPR，生成器按 DPR 换算并校验最终像素矩形；本轮固定 DPR 1。
- [标注遮挡组件内容] → 标签优先放在节点上方，空间不足时放到节点内部；详细描述只进入 Markdown。
- [两个项目历史上已经通过而没有问题可标] → 输出真实的零问题通过截图，不为演示伪造差异，并明确只覆盖本轮页面和视口。

## Migration Plan

1. 新增生成器与聚焦测试，不改动现有验证页面。
2. 在临时目录采集两套页面截图和节点证据，生成新的独立结果目录。
3. 运行聚焦测试、两套构建与视觉复核。
4. 回滚时删除新增生成器、专用测试和新结果目录；既有 183 场景证据不受影响。
