## Context

纯 AI 目录会主动移除正式规范中的验证元数据和外部设计链接，因此不能机械复制整个文件。现有同目录文档使用“绘制基准”替代验收口径，并通过 README 暴露可读取的规范集合。

## Goals / Non-Goals

**Goals:**

- 让只读取 `lanhu-ai-ui-spec` 的 AI 获得完整响应式表单规则。
- 保持 D-19 至 D-22 的所有可见 UI 值和边界不变。
- 让 README 的计数、目录树、读取顺序和入口与磁盘文件一致。

**Non-Goals:**

- 不复制验证报告、截图、浏览器测量或双组件库源码。
- 不修改正式设计规范、组件场景数量或已验收 UI 行为。

## Decisions

1. 以正式响应式文档为内容基线，按纯 AI 目录既有规则删除 `还原状态`、`设计源` 和验证过程说明，并把 `测量基准` 改为不含验收语义的 `绘制基准`。相比整文件复制，这能保持纯输入目录不依赖外部上下文。
2. README 同时更新文件计数、读取顺序、目录树和基础规范列表。只新增文件而不更新入口会使 AI 无法稳定发现新规范。
3. 在现有手写契约测试中增加专用场景，分别检查关键规则、纯净边界、README 计数与链接解析。该文件已经覆盖同一套规范结构和响应式布局，继续复用能避免重复基线。

## Risks / Trade-offs

- [正式版后续调整造成双目录漂移] → 测试逐项比较影响 UI 的关键规则，并要求两个目录都存在相同的 12 张画板名称和稳定 ID。
- [纯净化时误删可执行信息] → 仅删除元数据和验证过程语句，保留所有规范章节、数值表、画板映射和实现边界。
- [README 计数与磁盘不一致] → 自动扫描纯 AI 目录的 Markdown 数量并断言 README 声明值。
