## Context

`outputs/lanhu-design-spec/` 原有 29 个 Markdown 文件：1 个索引、3 个基础规范和 25 个组件/表单/选择器规范，对应 29 张蓝湖画板和 159 条组件场景。蓝湖现新增 Table 基础规范及经典表格页 Small/Medium/Large 共 4 张画板，需要增加 1 份独立组件规范和 24 条规范场景，目标清单因此扩展为 30 个 Markdown、33 张画板、26 份组件类规范和 183 条场景。

本变更横跨文档整理、本地图标资产、隔离 AI 生成、本地 UI、自动检查和浏览器视觉证据。设计必须遵守 `requirements/REQ-2026-003-lanhu-ui-reconstruction-validation.md` 的 D-01 至 D-16，并且不能因为生成出了页面或复用了组件库就跳过 A-01 至 A-06 的门禁。

## Goals / Non-Goals

**Goals:**

- 将 30 个 Markdown 文件整理为人和 AI 都能稳定解析的设计规范契约。
- 用蓝湖标注或 `@1x` 画板补齐可确认值，并保持来源可信度可追溯。
- 对全部 183 条场景建立组件结构、视觉值、图标和必要状态映射。
- 下载或导出组件图标为本地资产，并使 AI 能从 Markdown 直接定位和使用。
- 使用全新、无蓝湖上下文的 AI 进程，仅凭 Markdown 与本地资产生成组件规范样例，技术栈和组件库不限。
- 对蓝湖中的组件本体和状态区域提供视觉证据，并形成不夸大的结论。
- 分别用 Vue 3 + Element Plus、Vue 2 + Element UI 验证同一份技术栈无关规范可以覆盖两代常用 PC 组件库。

**Non-Goals:**

- 实现可发布的生产组件库或接入真实业务接口。
- 规定业务项目必须使用 Element、Element Plus 或其他特定组件库。
- 复刻蓝湖规范展示页的页头、侧栏、导航、卡片和说明性画板布局。
- 定义与可见 UI 无关的业务请求、缓存、持久化和组件内部算法。
- 修改插件运行时、OpenSpec 运行时或现有工作流行为。
- 把研发补充伪装成蓝湖设计标注。
- 证明所有 AI 模型、任意提示词或未来新增页面都能同样还原。

## Decisions

### 1. 使用“索引清单 + 统一章节 + 行级来源”作为 Markdown 契约

每个详细规范保留现有文件路径，并统一提供以下信息：

- 蓝湖画板名称、画板数量、场景数量和还原状态。
- “组件结构”区块；描述组成区域、顺序、包含关系和可选区域。
- “尺寸与样式”区块；记录高度、宽度、内外间距、字体、颜色、边框、圆角、阴影和层级，每个关键值带“蓝湖标注 / 画板实测 / 研发补充”来源。
- “图标资产”区块；记录本地路径、语义、尺寸、颜色、适用状态和替换边界。
- “画板场景”区块；每条场景包含可见内容、初始状态、必要状态变化和实现边界。
- 适用时增加“研发补充”区块，只描述会影响可见 UI 的必要状态或蓝湖未表达的实现边界。
- 适用时增加“蓝湖未定义”说明，并明确它是否阻断完全还原。

`README.md` 继续作为唯一清单，明确 33 张画板到 29 份详细规范的映射，以及索引本身组成的 30 个 Markdown 文件总数。这样既不破坏已有链接，也避免另引入 AI 不可见的 JSON 事实源。

替代方案是为所有文档增加严格 YAML front matter。它更容易解析，但会给当前以表格为主的资料增加大量重复元数据；本次先使用稳定标题和表头，由聚焦测试验证结构。

### 2. 缺失值按“可确认、未定义、不适用”三路处理

- 可从蓝湖标注或画板几何确认的值直接补齐，并写来源。已确认的 `Input` 三种尺寸示例宽度均为 `240px`。
- 蓝湖源确实没有定义的值写“蓝湖未定义”，并指出缺的是视觉事实还是交互规则。
- 对该组件无意义的字段写“无/不适用：原因”，不再使用裸 `—`。

替代方案是根据相邻色阶或常见组件库推算缺失值。该方案会污染设计事实，因此拒绝。

### 3. 把必要 UI 状态与组件内部实现分离

Default、Hover、Focus、Active、Selected、Disabled、Loading、Empty、Error、展开/收起和值回填等可见状态进入规范。组件库内部键盘处理、请求取消、缓存、销毁和业务数据契约不进入通用视觉规范；目标项目可以继承所选组件库的内部行为，但其默认视觉不得覆盖显式规范。

`Select` 的自定义模板、筛选和远程搜索保留“蓝湖状态：未定义”，只补充选项结构、输入、加载、空结果、失败和已选值等可见 UI，不再把防抖时长、请求序号或卸载算法当作设计事实。

替代方案是直接删掉蓝湖“待定”场景。该方案会造成场景覆盖缺失，与 D-04 冲突。

### 4. 使用新进程和最小工作目录隔离 AI 输入

隔离运行目录只包含整理后的 Markdown 副本、Markdown 引用的本地资产、实现目标和空输出目录。新 AI 进程不接收蓝湖链接、参考画板、本任务历史或已有 UI 文件。运行记录保存：

- 输入文件清单和哈希。
- 使用的模型/命令、提示词和开始结束时间。
- 生成文件清单、退出状态和模型主动报告的歧义。

输出先生成在隔离目录，通过检查后再复制到 `outputs/lanhu-design-spec/validation-ui/`。如果本机无法启动独立 AI 进程，则 A-04 直接记为阻断，不能用当前已看过画板的上下文替代。

替代方案是由当前会话直接实现样例。当前会话已经读取蓝湖，会发生验证泄漏，因此只可用于修订规范和验证，不可作为 A-03 的隔离生成证据。

### 5. 规范不绑定技术栈，生成端自行选择复用方式

Markdown 不记录强制框架、组件名、属性名或主题变量。AI 应先检查目标项目已有技术栈：

- 已有合适组件库时优先复用，覆盖与规范冲突的默认尺寸、颜色、图标和状态样式。
- 没有合适组件时可以自行实现，但仍须满足同一视觉契约。
- 生成报告必须声明实现方式和未能满足的规范值，不能把组件库默认值当作设计事实。

隔离验证允许使用本地可用框架或组件库，也允许生成无依赖静态页面；验收只看最终组件 UI。替代方案是为 Element、Element Plus 等分别维护重复规范，该方案会把实现细节固化进视觉事实并造成多份文档漂移，因此拒绝。

### 6. 图标作为一等本地资产

组件图标统一保存到 `outputs/lanhu-design-spec/assets/icons/`，优先使用蓝湖可下载/导出的 SVG；没有矢量时保存最高可用清晰度 PNG。文件名使用稳定英文语义和状态后缀，例如 `select-chevron-down.svg`、`input-clear-default.svg`。

每个图标引用必须能回答：用于哪个组件/区域、默认尺寸、显示颜色、哪些状态替换或变色、是否允许由项目图标库替换。替换时要求语义、视口尺寸、线宽、颜色和对齐方式等效，不能只因名称相似就替换。

使用字体图标、Unicode 字符或外部 URL 作为唯一交付会增加环境差异，因此不采用。

### 7. 自动门禁与组件区域视觉核对分工

新建 `tests/lanhu-ui-reconstruction.test.mjs`，负责：

- 30 个 Markdown、29 份详细规范、26 份组件类规范和 183 条场景的清单及唯一性。
- 裸占位符、来源等级、必需章节、组件结构、链接、HEX 和尺寸格式。
- 本地图标存在性、文件格式、语义、尺寸、颜色、状态和替换说明。
- 全部组件实例、场景锚点、刷新入口和必要 UI 状态。
- 验证报告必须与各门禁结果一致。

Chrome 人工/半自动检查负责：

- 在蓝湖 Web `@1x` 中截取组件本体或状态区域，并在生成页截取对应区域。
- 显式尺寸和间距 `±2px`、显式 HEX、图标、文案、初始状态和场景数量一致。
- Hover、Focus、Active、Selected、Disabled、Loading、Empty、Error 与展开/收起等必要可见状态。
- 验证页页头、侧栏、导航、卡片容器和说明排版不进入差异。

不采用单一整体像素相似度作为结论，因为字体抗锯齿和截图环境可能让相似度掩盖明确的几何或颜色错误。

### 8. 验证报告采用逐门禁失败优先的结论

`validation-report.md` 固定列出 A-01 至 A-06、输入隔离证据、图标资产、组件与 183 场景检查结果、必要状态、组件区域视觉差异和最小补充清单。只有全部门禁通过时，结论才是“可用于 AI 还原本套 UI 规范”；其他情况统一是“尚不足以用于稳定还原”。

### 9. 本轮使用两套真实组件库实现交叉验收

通用 Markdown 仍然只描述最终 UI，不写 Element API；验收实现则固定拆为两个独立工程：

- `validation-element-plus/`：Vue 3 + Element Plus，使用 `app.use(ElementPlus)` 注册真实组件。
- `validation-element-ui/`：Vue 2 + Element UI，使用 `Vue.use(ElementUI)` 注册真实组件。
- 两套工程目标各自声明依赖、构建脚本、运行时版本证据和 26/183 清单，不共享原生控件实现；既有 25/159 产物只作为 Table 扩展前基线。
- 两套工程可以共享从 Markdown 机械提取的场景数据，但组件渲染、组件库注册、主题覆盖和运行时验证必须独立。
- 六个本地图标复制到各自公共资产目录，组件内通过图片或插槽使用；组件库自带图标只有满足文档替换边界时才可替换。
- 原 `validation-ui/` 和既有原生截图仅用于解释历史失败，不进入本轮通过率。

该设计验证的是“同一规范能否约束两种组件库的最终视觉”，而不是把组件库 API 变成规范事实。

### 10. A-05 使用逐场景三方证据矩阵

A-05 不再以代表性组件截图或页面场景计数作为全量通过证据。系统为每个 `SCN-*` 建立唯一证据行，并固定关联：

- 场景所属 Markdown、蓝湖画板和 `@1x` 组件区域参考裁图。
- Element Plus 与 Element UI 的稳定场景定位、固定视口组件区域实际裁图。
- 规范显式要求、浏览器实测几何、计算样式 HEX、可见文案、图标路径/显示尺寸和初始状态。
- 适用时的 Hover、Focus、Active、Selected、Disabled、Loading、Empty、Error、展开/收起和值回填操作及操作后截图。
- 两套子结论、失败原因、差异图和修复后复测记录。

批量截图前必须固定 Chrome 视口、设备像素比、100% 页面缩放和字体环境。像素差异图用于定位，不作为唯一结论；最终门禁仍以 D-09 的显式几何、HEX、图标、文案和状态为准。任一场景缺少参考裁图、任一套实际裁图或适用状态证据时，该场景和 A-05 均失败。

### 11. Table 四张画板合并为一份独立规范

新增 `components/table.md` 同时承载 Table 基础规范和经典表格页 Small/Medium/Large 三张页面画板。基础画板按可观察结构拆为 21 条非重复组件场景，三张页面画板各保留 1 条密度/布局场景，共形成 `SCN-TABLE-01` 至 `SCN-TABLE-24`。

源基础画板中“自定义索引”以相同示例重复出现。规范只建立 1 条可执行场景，并在来源说明中记录“源画板重复”，避免让 AI 将排版重复误解为两个不同组件状态。Table 画板只提供栅格中的排序、筛选、展开、日历和新增图标时，文档记录“蓝湖未提供独立资产”和可见替换边界，不伪造矢量文件。

经典表格页记录页面中会约束真实研发 UI 的侧栏、内容卡片、筛选区、操作区、表格、状态标签、进度条和分页组合关系及 Small/Medium/Large 密度；验证页自身的导航外壳仍不属于该业务页面规范。

### 12. Table 验收展示按可用宽度降级并正确合成透明画布

Table 基础场景保留规范要求的 `776px` 组件宽度。普通验收页只有在两张场景卡片都能完整容纳组件和卡片内边距时才允许双列；Table 视图固定使用单列。经典 Small/Medium/Large 是完整业务页面画布，普通预览按场景卡片的实际可用宽度等比缩小画布及占位高度，不出现横向滚动或裁切；证据模式仍按场景本体的原始逻辑像素尺寸渲染和截图，禁止把预览缩放带入 A-05。

经典页面三张源图包含透明工作区。源 WebP 工作区像素为约 `rgba(0, 0, 0, 0.16)`，证据基准以 `#F0F2F5` 承载底色合成后可见色约为 `#CACCCF`。参考裁图和两套实现都必须呈现该最终合成结果，再重新生成 Small、Medium、Large 的实际图、对照图和证据指纹。

### 13. 经典表格页按蓝湖信息架构重建

三张经典页面共享同一内容结构，只在控件高度、表头/行高、筛选列数、卡片高度和分页密度上变化。实现继续使用真实组件库的 Menu、Breadcrumb、Form、DatePicker、Input、Select、Button、Table、Tag、Progress 和 Pagination，但必须覆盖默认主题以得到以下可见结果：

- 侧栏不显示验收工程品牌字样，使用蓝湖菜单树并展开“列表页”，激活“基础表格”；顶部显示面包屑、标题“基础表格页”、说明文案及弱化的消息/账号区。
- 筛选项为日期双输入、姓名、状态、地址和完成进度双输入；Large 首行 4 组、次行地址与操作，Small/Medium 首行 3 组、次行地址/完成进度/操作。
- 表格不传入带边框模式，不显示纵向列线；9 行均使用日期 `2016-05-03`、姓名 `Tom`、地址 `No. 189, Grove St, Los Angeles` 和 `40%` 进度，状态按画板顺序分组。
- 操作按钮只借用组件库交互能力，外观重置为 `#FF6014` 无边框、无背景文字；三项等色，不使用危险红。分页总数 `6532`、当前页 `1`，不显示跳页输入。

这样保留双组件库真实性，同时不让组件库按钮、表格边框或分页默认值覆盖蓝湖视觉事实。

## Risks / Trade-offs

- [风险] 蓝湖是栅格画板，部分间距只能实测而非获得图层标注。→ 缓解：保留“画板实测”和 `±2px` 容差，不把约数升级为精确标注。
- [风险] 当前会话已看过蓝湖，直接生成会泄漏答案。→ 缓解：A-04 必须由新进程和最小输入目录完成；失败时明确阻断。
- [风险] 不同组件库 DOM 和默认主题不同。→ 缓解：规范只约束组件组成和最终可见值；验证截取组件区域，不断言框架 API 或 DOM 层级。
- [风险] 蓝湖只提供栅格中的图标，无法得到原始矢量。→ 缓解：优先使用蓝湖下载资源；确无矢量时保存高清 PNG，明确来源与替换边界，不伪造 SVG。
- [风险] 183 条场景全部做深层交互成本高且偏离视觉规范。→ 缓解：全部场景做结构和视觉映射，只对规范明确的必要可见状态做操作验证。
- [风险] Table 源画板把同一“自定义索引”示例重复排版。→ 缓解：保留来源重复说明，只建立一个规范场景，不伪造差异。
- [风险] 固定宽 Table 或经典完整页面画布放入验收卡片会越界，透明源图也可能被图像工具显示成黑色或被误当成纯 `#F0F2F5`。→ 缓解：Table 验收视图使用单列，经典页面仅在普通预览中随卡片宽度等比缩小且同步收敛占位高度；证据模式保持原尺寸，并按 `#F0F2F5` 承载底色与源画板 `rgba(0, 0, 0, 0.16)` 工作区层的最终合成色核对。
- [风险] 系统字体和抗锯齿造成像素噪声。→ 缓解：优先比较显式几何、HEX、文案和状态；非结构像素单独记录。
- [风险] 蓝湖“待定”使完美还原在逻辑上不可证明。→ 缓解：保留“蓝湖未定义”并提供研发补充；只要仍是阻断项，报告不得通过 D-08。
- [权衡] 技术栈无关规范不能保证每个组件库零成本套用。→ AI 可以覆盖默认主题或自行实现；报告只证明规范足以描述目标 UI，不证明所有库都天然兼容。
- [风险] Element UI 与 Element Plus 的属性、插槽、弹层挂载和默认尺寸不同。→ 缓解：分别实现适配层和主题覆盖，并以运行时组件实例及最终组件区域验收，不用一套原生 DOM 冒充两套库。

## Migration Plan

1. 建立基线清单并保存扩展后 30 个 Markdown 的哈希、场景计数和缺失项。
2. 建立图标清单，从蓝湖下载/导出本地资产并记录来源与替换边界。
3. 按蓝湖逐组件补齐组成结构、视觉值、必要状态和场景映射，保持原文件路径。
4. 运行聚焦文档与资产契约测试；失败时先修规范，不进入隔离生成。
5. 在最小工作目录启动新 AI 进程，允许其选择实现方式，生成组件规范样例并保存隔离证据。
6. 运行产物结构和必要状态测试，再用 Chrome 完成组件区域视觉检查。
7. 分别建立 Element Plus 与 Element UI 验收工程，运行聚焦测试和独立构建。
