## Why

当前蓝湖规范 Markdown 已覆盖主要画板和场景，但仍缺少部分组件结构、精确视觉值、本地图标资产和必要交互状态，且首次验证错误地要求 AI 用原生控件复刻整张规范展示页。需要把文档修正为面向 PC 端、技术栈无关的 UI 视觉规范，再验证 AI 能否在自由选择组件库或实现方式时稳定还原组件本体。

## What Changes

- 逐页核对蓝湖 33 张 Web `@1x` 画板，补齐可确认的颜色、尺寸、间距、圆角、边框、字体和布局值。
- 消除裸 `—` 和矛盾“未标注”说明，把设计未定义项明确区分为“蓝湖未定义”和“研发补充”。
- 为 30 份 Markdown 建立一致的机器读取结构，并把 26 份组件类文档的 183 条场景逐条映射到组件组成、尺寸、颜色、字体、间距、边框、圆角、阴影、图标和必要状态。
- 将 Table 基础规范、经典表格页 Small/Medium/Large 共 4 张新增画板合并为独立 `table.md`；源画板重复出现的“自定义索引”只建立 1 条规范场景，并记录源画板重复事实。
- 重新校准三张经典表格页的真实页面结构和颜色，特别是无纵向边框表格、统一品牌色且无按钮外观的“详情 / 编辑 / 删除”操作列，以及无跳页输入的右下分页。
- 从蓝湖下载或导出组件图标，保存为 Markdown 可直接引用的本地 SVG/PNG 资产，并记录语义、尺寸、颜色、状态和替换边界。
- 明确规范不绑定 Element、Element Plus 或其他组件库；AI 可以复用项目现有组件库或自行实现，但默认主题不得覆盖规范中的显式视觉值。
- 在不提供蓝湖、原画板、截图和既有实现的新 AI 上下文中，仅凭 Markdown 与本地资产生成组件规范样例。
- 本轮验收目标分别生成 Vue 3 + Element Plus、Vue 2 + Element UI 两套独立样例，真实使用对应组件库并覆盖 26 个组件视图和 183 条场景；既有 25/159 双组件库产物仅作为扩展前基线，原生静态样例只保留为历史基线。
- 为 183 条场景建立逐行 A-05 视觉矩阵；每行同时关联蓝湖 `@1x` 组件区域参考裁图、Element Plus 实际裁图、Element UI 实际裁图、显式几何/HEX/文案/图标和适用交互状态结果。
- 更新聚焦自动测试、组件区域视觉证据和还原验证报告；排除验证页外壳，任一规范门禁失败时禁止宣称可稳定还原。

## Capabilities

### New Capabilities

- `lanhu-design-spec-contract`: 定义蓝湖设计事实、画板实测值、组件视觉结构、本地图标资产、必要状态和技术栈无关实现边界的 Markdown 契约。
- `ai-ui-reconstruction-validation`: 定义隔离 AI 输入、自由实现方式、组件规范样例、组件区域视觉容差、必要状态证据和最终通过/失败判定。

### Modified Capabilities

- 无。

## Impact

- 修改 `outputs/lanhu-design-spec/` 下现有规范 Markdown，新增 `components/table.md`、4 张 Table 参考画板、`assets/` 本地图标、Element Plus 与 Element UI 两套组件规范样例、验证报告和截图证据。
- 新增 `tests/lanhu-ui-reconstruction.test.mjs`，聚焦检查文档契约、场景映射和还原产物。
- 不修改插件运行时、公共 API、生产业务组件、鉴权或服务端接口；规范不要求业务项目安装指定组件库。
