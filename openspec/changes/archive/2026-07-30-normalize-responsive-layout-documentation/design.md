## Context

见 `proposal.md` 的 Why。当前正式规范已经包含断点、工作区、间距、控件满列、操作组换行和防越界规则；真实项目报告另行记录了 `#FF6014` 主操作色修正。12 张画板有稳定 ID，但展示名仍使用蓝湖自动生成的 `copy / copy 2`，同尺寸画板的状态含义需要依赖“作用”列才能理解。（D-21；A-11）

## Goals / Non-Goals

**Goals:**

- 让正式 Markdown 单独包含 AI 还原响应式表单所需的通用可见约束。
- 让画板展示名在脱离蓝湖源文件名后仍能直接识别尺寸、列数和状态。
- 保持 12 个画板 ID、文档路径、断点和现有证据可追溯。

**Non-Goals:**

- 不修改两套组件库页面、构建产物或测量数据。
- 不把 Element Plus、Element UI、iframe 或测试截图写成通用规范前提。
- 不重命名蓝湖中的原始画板，也不改变 `<1024px` 未定义边界。

## Decisions

1. **画板展示名采用三段式语义。** 普通画板使用“`宽 × 高｜N 列｜状态`”；规则总览使用“`宽 × 高｜规则总览｜用途`”。相同尺寸和列数通过“基础、空数据、数据”继续区分。相比只写“1024｜3 列”，三段式能保持 12 行唯一；相比保留括号内源名称，不再把 `copy` 暴露给 AI。
2. **稳定追溯只依赖画板 ID。** 展示名是面向使用者的标签，画板 ID 才是源追溯键；因此只改名称和相关说明，不改 ID、数量和文档路径。
3. **将主色修正写成技术栈无关规则。** 正式规范记录“主操作色为 `#FF6014`，目标组件库默认主题不一致时必须覆盖”，不提 Element UI 的蓝色默认值或局部 CSS 类。
4. **测试追加到现有手写专用测试。** 在既有响应式规范测试中检查名称格式、唯一性、`copy` 零命中、ID 稳定和通用 UI 关键词，避免创建第二套重复测试。

## Risks / Trade-offs

- [展示名不是蓝湖原始名称，人工回查可能误认] → 保留原始画板 ID，并在表格前说明展示名是规范化名称。
- [只写尺寸与列数会导致同尺寸画板重名] → 强制第三段状态/用途，并由测试检查 12 个展示名唯一。
- [组件库默认主题未来变化] → 只约束最终主操作色，不写组件库版本或实现方式。

## Migration Plan

1. 更新正式规范元数据、参考画板说明、12 张映射和还原执行补充。
2. 增加契约断言并确认 12 个画板 ID 未变。
3. 运行聚焦测试、需求校验和 OpenSpec 严格校验；通过后同步主规范并归档变更。
