## Why

现有 AI UI 验收样例已经能生成节点标注截图和源码修复报告，但能力仍停留在仓库输出目录，无法随插件稳定复用，也没有把验收、受控修复和相同上下文复验串成项目自动化流程。现在需要把这套合同正式纳入 `frontend-ai-workflow`，让业务项目不依赖独立平台即可完成可追溯的 UI 验收闭环。（D-01、D-02）

## What Changes

- 新增 UI 验收、UI 修复和 UI 复验三个公共 Skill，分别负责采集与报告、受控源码修改以及相同上下文复验。（D-02、D-03、D-06，A-01、A-03、A-04）
- 新增项目级 UI 验收配置与机器可读运行状态合同，确定性校验场景、视口、设计依据、产物根目录、自动修复模式和场景指纹。（D-04～D-08，A-02）
- 默认仅生成修复建议；只有显式授权才允许在报告声明的源码文件和作用域内应用修改，修改后必须进入待复验状态。（D-03、D-05，A-03）
- 复验必须复用原始场景上下文，并区分已关闭、未解决和新增问题；不同上下文结果不得直接判定通过。（D-06，A-04）
- 更新插件结构校验、使用说明、专用测试和发布验证，保证新增公共资产随插件完整交付。（D-01、D-07、D-08，A-05）

## Capabilities

### New Capabilities

- `plugin-ui-review-automation`: 定义插件内 UI 验收、受控修复、相同上下文复验、配置与运行状态安全合同。

### Modified Capabilities

- 无。

## Impact

- 影响 `plugins/frontend-ai-workflow/skills/`、`scripts/`、模板与结构校验，以及根 README 和专用测试。
- 不新增独立服务、数据库或远程连接器，不修改业务项目页面，也不静默安装 Playwright 或其他依赖。
- 新增公共 Skill 会扩大插件触发面；必须通过描述边界、默认建议模式和路径校验避免误触发与越界修改。
