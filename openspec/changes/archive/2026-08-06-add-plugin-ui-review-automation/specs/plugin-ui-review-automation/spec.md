## Purpose

让安装 `frontend-ai-workflow` 的前端项目能够在没有独立管理平台的情况下执行可重复、可追溯且可安全自动修复的 UI 验收闭环。

## ADDED Requirements

### Requirement: 插件必须提供职责分离的 UI 验收闭环
插件 SHALL 提供 UI 验收、UI 修复和 UI 复验三个公共入口；三个入口 MUST 通过同一项目运行状态衔接，并且不得要求独立 PC 客户端、Web 管理服务或数据库。（D-01、D-02、D-07，A-01）

#### Scenario: 单独执行 UI 验收
- **WHEN** 用户在已安装插件的前端项目中请求验收一个已配置场景
- **THEN** UI 验收入口只负责校验配置、采集证据、形成问题结论和写入待处理运行状态，不直接修改源码

#### Scenario: 串联验收修复与复验
- **WHEN** 一次验收发现可修复问题且用户继续执行修复与复验
- **THEN** 三个入口通过原运行 ID、父运行 ID和场景指纹串联，最终结果能够区分通过、未解决与新增问题

### Requirement: 项目配置必须经过确定性安全校验
系统 SHALL 使用带版本号的项目配置定义产物根目录、自动修复模式和至少一个验收场景；每个场景 MUST 包含稳定 ID、HTTP(S) 页面、有效视口、仓库相对设计依据和至少一个目标节点。系统 MUST 拒绝未知版本、重复场景、危险路径、无效视口、缺失设计依据或空目标节点。（D-04、D-05、D-08，A-02）

#### Scenario: 有效配置生成稳定场景指纹
- **WHEN** 同一项目以相同页面、视口、设计内容、目标节点和交互说明重复读取配置
- **THEN** 系统输出相同规范化场景和 SHA-256 场景指纹

#### Scenario: 配置路径可能越出项目
- **WHEN** 配置、设计依据或产物根目录使用绝对路径、`..`、符号链接越界或项目根目录本身
- **THEN** 系统以中文错误拒绝且不创建运行目录

### Requirement: UI 验收运行必须保留有限且可恢复的状态
系统 SHALL 为每次场景验收创建独立运行 ID和版本化状态，记录阶段、状态、场景指纹、父运行、问题摘要和受控产物路径。运行未完成或失败时 MUST NOT 写成通过；重复运行 MUST NOT 覆盖其他运行或未知文件。（D-05、D-07、D-08，A-02、A-05）

#### Scenario: 零问题验收完成
- **WHEN** 验收在声明场景范围内提交零个高置信度问题和完整证据
- **THEN** 运行状态为有限范围通过并保留实际截图、标注截图和 Markdown 报告路径

#### Scenario: 运行目录存在未知内容
- **WHEN** 新运行目标目录已存在未知文件或不属于同一运行状态
- **THEN** 系统停止写入并保留既有内容

### Requirement: 自动修复必须默认关闭写入并执行完整门禁
系统 SHALL 将自动修复默认模式设为 `suggest`；`off` MUST 禁止修复，`suggest` MUST 在没有当前任务显式授权时只输出建议，`apply` MAY 允许进入修复。任何实际修复前 MUST 同时存在高置信度问题、仓库相对源码文件、稳定锚点、允许修改范围、禁止修改范围和至少一条复验断言；否则不得修改源码。（D-03、D-05、D-08，A-03）

#### Scenario: 默认建议模式没有授权
- **WHEN** 项目未设置自动修复模式或模式为 `suggest`，且用户没有在当前任务显式授权
- **THEN** 系统返回建议决策，不修改源码，并说明需要授权

#### Scenario: 应用模式缺少修复上下文
- **WHEN** 自动修复模式允许应用但任一问题缺少源码目标、稳定锚点、修改边界或复验断言
- **THEN** 系统拒绝应用且运行状态保持未修复

#### Scenario: 修复应用完成
- **WHEN** 修复获得授权并且只修改报告声明的安全范围
- **THEN** 系统将已应用问题记录为待复验，不得直接将验收状态改为通过

### Requirement: 复验必须使用相同场景上下文
系统 SHALL 只允许使用与基线运行相同的场景指纹创建复验；复验 MUST 复用页面、视口、设计依据、目标节点和交互说明，并 MUST 按稳定问题指纹区分已关闭、未解决和新增问题。只有未解决与新增问题均为空时结果 SHALL 为通过。（D-06，A-04）

#### Scenario: 修复后问题全部关闭
- **WHEN** 复验场景指纹与基线一致，原问题全部消失且没有新增高置信度问题
- **THEN** 复验状态为通过，并列出已关闭问题

#### Scenario: 复验出现未解决或新增问题
- **WHEN** 复验仍包含原问题或出现新的稳定问题指纹
- **THEN** 复验状态为失败，并分别列出未解决和新增问题

#### Scenario: 复验上下文发生变化
- **WHEN** 当前配置计算出的场景指纹与基线运行不同
- **THEN** 系统拒绝直接复验并要求重新开始一次独立验收

### Requirement: 插件自动化不得静默扩大外部依赖与权限
系统 SHALL 优先使用当前 Codex Browser 能力或目标项目已经声明的 Playwright 采集页面，不得静默安装浏览器、修改主分支、提交或推送代码、创建 PR、读取认证数据或绑定特定代码托管服务。（D-01、D-03、D-07、D-08，A-03、A-05）

#### Scenario: 当前环境没有可用采集器
- **WHEN** Codex Browser 不可用且目标项目没有已声明的 Playwright 入口
- **THEN** UI 验收入口报告明确阻塞，不安装依赖，也不生成虚假通过结果
