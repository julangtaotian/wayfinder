## Why

普通项目健康检查会把全部历史验证诊断直接展开，AI 为确认当前状态必须接收大量与当前修改无关的历史内容；仓库搜索也缺少针对运行时、验收输出和归档的默认读取边界。需要在保留完整兼容入口和持久资产的同时提供渐进读取合同。（D-01～D-08；A-01～A-05）

## What Changes

- 清理 Git 已忽略且可重建的验证依赖、临时目录、缓存、日志和本机元数据，不删除受跟踪资产。（D-01、D-08；A-01）
- 为 `check-project.mjs` 增加 `--summary` 和 `--diagnostic-code`，保留无参数完整输出与 `checkProject()` 内存合同。（D-02～D-04；A-02～A-04）
- 将工作流检查 Skill 改为先读精简结果、按 code 查询历史目标，只有缺少必要事实时才读取完整结果。（D-05；A-05）
- 精简根 AGENTS，并明确默认源码范围和大体积资产按任务读取规则。（D-06；A-05）
- 增加独立测试、同步 0.17.1，并只安装当前平台插件成品。（D-07、D-09～D-11；A-06～A-08）

## Capabilities

### New Capabilities

- `ai-context-efficiency`：定义健康检查渐进输出、稳定诊断查询、仓库按需读取与兼容边界。（D-02～D-06；A-02～A-06）

### Modified Capabilities

- 无。

## Impact

- 主要实现：`check-project.mjs`、新增精简输出模块、工作流检查 Skill、根 AGENTS。
- 测试：新增 `tests/ai-context-efficiency.test.mjs` 并扩展 CLI 参数安全回归。
- 发布：版本提升至 0.17.1，最终安装当前原生平台成品。
- 跨平台高风险：是；命中机器可读诊断和 CLI 参数，影响仓库声明的五个平台。（D-11；A-04、A-06、A-08）
- 不新增依赖，不改变目标项目文件，不删除受跟踪历史与运行时资产。
