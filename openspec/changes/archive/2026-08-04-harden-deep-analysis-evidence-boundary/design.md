## Context

范围收集器已经在安全过滤后读取文件并计算哈希，但它没有解析源码或调用任何框架工具。深度分析由技能根据范围结果和实际文件生成，健康检查则会重新收集范围判断指纹，因此证据边界需要同时进入范围 JSON、AI 技能约束和检查 JSON。详见 `proposal.md` 与两份 delta spec。（D-01、D-02；A-01）

## Goals / Non-Goals

**Goals:**

- 用稳定机器字段表达范围工具实际完成和未执行的验证能力。（D-02；A-01）
- 在不新增解析器或依赖的前提下，定位 WXML 属性结束引号与下一属性名粘连的可疑位置。（D-03、D-06；A-02）
- 让健康检查复用同一次当前范围结果，返回非阻断观察和证据边界。（D-04；A-02）

**Non-Goals:**

- 不实现 WXML AST、平台编译器或通用 Lint。
- 不判断静态观察一定会导致编译失败，也不自动修复目标源码。
- 不改变深度初始化的显式写入授权和 AI 分析正文保护策略。（D-06；A-03）

## Decisions

### 1. 范围结果公开 `validationEvidence`

范围清单返回固定对象，分别记录文件枚举、文本读取和 SHA-256 已执行，以及语法解析、平台编译、Lint、测试未执行。每项使用稳定英文 `status` 与 `executed`，说明使用中文。选择显式对象而不是单个 `validated` 布尔值，是为了避免下游再次把不同能力合并。（D-02；A-01）

替代方案是只修改技能文案，但旧分析或其他消费者仍可能误解范围 JSON，因此不采用。

### 2. 在安全内容读取阶段生成最小 WXML 观察

收集器只对已经通过路径、Git、大小、总量和空字节检查的 `.wxml` 文本逐行匹配：一个完整引号属性值后没有空白，立即出现下一属性名与等号。观察只保存 `code`、`severity`、相对 `path`、1 基 `line` 和通用说明，不保存源码片段或属性值。（D-03、D-06；A-02）

选择逐行启发式而不是 XML 解析器，可以保持零依赖和低成本；跨行或其他语法问题不在能力范围内。该局限必须体现在说明中，避免把观察写成确定错误。

### 3. 检查器复用当前范围并限量展示位置

深度地图启用时，检查器收集一次当前范围，同时计算新鲜度、返回 `validationEvidence` 与完整观察数组，并在存在 WXML 观察时追加中文警告。警告只展示前 5 个 `path:line`，保留总数并明确“静态观察、未执行平台编译”；观察不加入 `errors`，所以工作流结构健康时仍为 `ok: true`。（D-04；A-02）

替代方案是在检查器单独再次扫描 WXML，但会重复 IO 并可能与指纹快照不一致，因此不采用。

### 4. 范围版本升级到 2.2.0

证据对象与静态观察改变了深度分析输入合同，范围版本进入指纹，让旧地图自然变为 stale。普通升级继续保留 AI 分析正文；只有用户显式执行深度刷新时才生成新的证据边界分析。（D-05、D-06；A-01、A-03）

### 5. 技能只增加不可推断的核心约束

`frontend-workflow-bootstrap` 保留简洁步骤，在深度覆盖阶段加入“读取/哈希不等于解析/编译”的硬规则；详细状态和观察解释放在 `references/deep-project-analysis.md`。`frontend-workflow-check` 负责解释新增检查字段，避免复制完整规则。（D-02、D-04；A-01、A-02）

## Risks / Trade-offs

- [启发式可能漏掉跨行或其他 WXML 语法问题] → 输出始终标为静态观察并明确未执行平台编译，不声称完整覆盖。（D-03；A-02）
- [属性值内特殊文本可能误匹配] → 模式要求标准属性名、等号和成对同类引号；测试覆盖合法相邻属性和目标项目既有案例。（D-03、D-07；A-02）
- [范围版本升级使既有项目出现 stale 警告] → 这是预期迁移信号，检查保持只读，普通升级不覆盖分析正文。（D-05、D-06；A-01、A-03）
- [观察数量过多导致警告冗长] → JSON 保留完整结构化观察，中文警告只展示有限位置。（D-04；A-02）

## Migration Plan

1. 发布 2.2.0 范围合同与新增向后兼容字段。
2. 更新并校验公开技能、规格和测试。
3. 刷新插件缓存版本并重新安装本地副本。
4. 对目标微信小程序执行只读检查，确认旧地图 stale、既有观察可定位且未写目标项目；不把会随源码变化的总数固化为合同。
5. 后续由用户在新任务中显式深度刷新目标项目；回滚时恢复旧插件版本即可，目标文件不会被自动改写。（D-05、D-06、D-08；A-03）
