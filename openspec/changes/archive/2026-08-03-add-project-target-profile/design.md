## Context

现有项目识别在一个入口中合并依赖、选择 preset、命令和常见目录，初始化、升级和检查都复用该结果。受管模板通过变量渲染到 AGENTS、Wayfinder 和 OpenSpec 配置，因此终端画像可以沿现有数据流传递，无需新增命令或平行流程。参见 `proposal.md` 与 `specs/project-target-profile/spec.md`。

## Goals / Non-Goals

**Goals:**

- 用一个小型纯函数集中生成终端画像，避免识别规则散落。
- 只使用依赖事实，稳定区分桌面、移动、混合和未知。
- 让现有识别、初始化、升级和检查入口共享相同对象。
- 通过新增模板变量把终端事实传入后续需求与变更上下文。

**Non-Goals:**

- 不判断具体布局是否响应式，不读取 CSS 或 DOM 推断终端。
- 不识别小程序运行时、平台、页面配置或构建命令。
- 不增加配置覆盖、CLI 参数、适配器注册机制或第三方解析器。
- 不重构既有 preset、命令和目录识别。

## Decisions

### 决策一：终端画像由一个独立纯函数生成

新增单一内部模块，接收已经合并的依赖映射并返回：

- `formFactor`: `desktop | mobile | mixed | unknown`
- `source`: 有证据时为 `package-dependencies`，否则为 `unknown`
- `evidence`: 去重并按包名排序的公开依赖名

项目识别器负责调用该函数，其他入口只消费识别结果。这样后续增加运行时或平台字段时仍有单一扩展点，不必修改初始化、升级和检查主流程。（D-03、D-04、D-06）

备选方案是直接把条件写入 `inspect-project.mjs`；虽然少一个文件，但会让后续平台扩展继续膨胀核心识别器。配置驱动的动态适配器系统则超出第一轮规模，因此不采用。

### 决策二：第一轮只保留少量高信号依赖集合

桌面证据复用当前已识别的 Element Plus、Element UI、Ant Design 和 MUI；移动证据只加入 Vant、Ant Design Mobile 和 NutUI。集合保持在终端画像模块中，技术栈标签同步识别新增的三个移动包。

单类命中返回对应终端，两类同时命中返回 `mixed`，都未命中返回 `unknown`。`mixed` 只表达证据并存，不升级成响应式结论。（D-03；A-01、A-02）

不扫描 CSS、viewport、目录名或项目名，因为这些信号无法稳定证明项目交付终端；也不一次收录大量低频 UI 库，避免维护清单失控。

### 决策三：使用既有模板变量链路同步事实

初始化模板变量新增终端类型、来源和证据文本：

- AGENTS 在“项目事实”中提供终端画像，供任务开始前读取。
- Wayfinder meta 保存机器可读的类型和来源，项目概览展示证据边界。
- OpenSpec context 增加终端画像，使规划和实施读取同一事实。
- 项目检查直接返回 `inspection.targetProfile`。

升级继续使用现有受管区块替换逻辑，不新增文件，也不覆盖项目自定义内容。（D-05、D-06；A-03）

### 决策四：专用测试使用最小临时 fixture

新测试文件创建不安装依赖的最小 Vue fixture，直接覆盖纯识别规则，并通过真实初始化、依赖修改、显式升级和检查验证数据链路。误导性目录名 fixture 证明名称不会参与判断。（D-07、D-08；A-01～A-04）

因为改动影响共享识别和三个受管模板，聚焦测试通过后运行完整统一门禁；发布阶段再执行官方验证器与本地插件缓存验证。

## Risks / Trade-offs

- [未收录的终端 UI 库返回 unknown] → `unknown` 是安全结果，后续根据真实使用样本再小步扩展证据集合。
- [项目同时安装两类 UI 库但并非双端] → 返回 `mixed` 并保留包名证据，不宣称响应式或确定交付终端。
- [依赖存在但仅用于局部页面] → 画像只作为需求分析输入，需求仍须结合影响范围确认，不把它当成业务事实替代品。
- [模板字段增加影响旧项目升级] → 仅替换合法受管区块，并用自定义内容保留测试验证兼容性。
- [未来小程序字段增加] → 在同一画像对象中增量扩展运行时和平台字段，不创建框架专用命令或工作流副本。

## Migration Plan

1. 新增终端画像纯函数和专用测试，先固定行为契约。
2. 接入项目识别和检查的增量 JSON 字段。
3. 增加模板变量并验证初始化与升级受管边界。
4. 运行聚焦测试、完整门禁和官方插件验证。
5. 刷新单一 cachebuster 并重新安装本地插件；如出现兼容问题，回退新增对象和模板字段即可，不涉及业务项目数据迁移。
