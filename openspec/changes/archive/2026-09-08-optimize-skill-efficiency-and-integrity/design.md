## Context

见 proposal.md 和需求 REQ-2026-044。归档与结构校验已有稳定入口，技能已按阶段拆分，不能用重写运行时解决文档成本问题。

## Goals / Non-Goals

- D-01 / A-01：补齐既有归档链，复用部分失败和恢复协议。
- D-02 / A-02：校验 skills 与 references 的包内静态引用；不实现完整 Markdown 解析器，也不扫描 runtime。
- D-03、D-04 / A-03、A-04：调整模式和读取指令，不新增技能、依赖、缓存协议或运行时行为。
- D-05 / A-05：交付有限评测样例，不启动额外模型评测或承诺成本下降比例。

## Decisions

1. 归档迁移识别独立相对路径、行内代码和 Markdown 目标，保护 URL 与其他路径前缀；证据读取同步支持链接，不进行不受限制的全文替换。
2. 严格的本次完整性检查放在 postArchiveAudit：新归档与恢复共用，普通历史 complete 语义保持不变。
3. 包内引用只枚举 skills 和 references，行内代码仅显式相对路径及同目录文件名，Markdown 链接按源文件定位；占位符和项目根路径保持动态。使用标准路径 API 和稳定诊断。
4. 技能优化替换已有重复段落，少量增加当前决策必需规则，不制造所有技能都要读取的总说明。保留命令执行、UI 基线和写入门禁。
5. 新建专用行为测试；临时目录使用 outputs/skill-optimization 子目录并在测试清理；既有全量测试由受控临时目录环境执行。技能语义使用固定场景人工审阅，区别于额外模型实跑。

## Risks / Trade-offs

- 跨平台高风险：路径、机器诊断、fixture；影响五平台。覆盖中文/空格/CRLF、路径边界与失败清理；真实 CI 保持待执行。
- Markdown 写法复杂 → 只声明支持确定的静态文件引用，测试远程 URL、动态模板和相似路径；不为消除提示增加宽泛忽略。
- 文字精简可能削弱门禁 → 原有测试继续执行，人工逐项审阅原保护；保留 fast-change 的核心合同。
- 真实效率无法由静态体积证明 → 记录阅读量变化，真实 token 与时延评测明确未执行。

## Migration Plan

源文件增量更新，无业务项目迁移或发布操作。失败按原归档恢复协议处理；本轮不归档自身变更，直到精确修订的外部平台证据齐备。
