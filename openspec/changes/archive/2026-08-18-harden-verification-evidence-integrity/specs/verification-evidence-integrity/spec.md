## Purpose

为前端工作流提供可持久、可判旧且可随变更归档的机器验证证据，使自动通过结论能够追溯到真实命令、计划测试定位和对应工作区，同时明确历史与外部证据的信任边界。

## ADDED Requirements

### Requirement: 本地自动验证必须由受控入口形成机器证据
系统 SHALL 提供显式写入的受控入口，以无 shell 参数数组真实执行本地聚焦验证，并 MUST 在版本化证据中记录 V-*、命令、项目相对工作目录、时间、真实退出码、计划测试定位命中数、Git 来源、工作区指纹和日志摘要。只有命令退出码为零且计划定位至少命中一次时，证据状态才能为 `passed`。（D-02、D-03、D-13，A-01、A-08）

#### Scenario: 聚焦测试真实发现计划定位
- **WHEN** 用户显式执行证据写入，命令退出码为零且标准输出或标准错误至少一次包含声明的稳定测试定位
- **THEN** 系统在所选活动变更的 `evidence/<V-ID>.json` 原子写入 `local-command` passed 证据，并把完整临时日志限制在该项目的有界 outputs 子目录

#### Scenario: 命令成功但没有发现计划测试
- **WHEN** 命令退出码为零但计划测试定位命中数为零
- **THEN** 系统返回稳定的零测试错误、保留真实执行摘要且不得创建或覆盖 passed 证据

#### Scenario: 默认预览本地证据执行
- **WHEN** 调用方没有显式写入
- **THEN** 系统只返回规范化命令、证据目标和日志目标，不启动子进程、不创建 outputs 日志或持久证据

### Requirement: 机器证据必须安全、版本化且可判旧
系统 SHALL 只接受已知 schema 版本、同一 V-* 的证据 ID、受支持 kind 和安全项目相对路径，并 MUST 通过排除生命周期文档、证据目录和临时 outputs 后的项目工作区指纹判断证据是否仍对应当前实现与测试。路径 MUST 先规范化，符号链接、绝对路径、父级穿越和项目外目标 MUST 失败关闭。（D-04、D-05、D-09、D-13，A-02、A-03、A-08）

#### Scenario: 验证后业务或测试内容变化
- **WHEN** 当前可执行项目内容的工作区指纹与 passed 证据中记录的指纹不同
- **THEN** 完成校验输出 `stale_evidence` 和对应 V-*，不得把旧证据用于当前完成结论

#### Scenario: 证据只因生命周期文档迁移而变化
- **WHEN** 需求状态、测试方案结果、验证说明、机器证据自身或归档目录前缀变化，但被验证的实现、测试和项目命令内容没有变化
- **THEN** 工作区指纹保持一致，证据不因生命周期文档的正常同步被误判为过期

#### Scenario: 未知版本或危险证据路径
- **WHEN** JSON 使用未知 schema、ID 与 V-* 不一致、路径包含父级穿越或通过符号链接越出项目
- **THEN** 系统返回稳定错误 code、target 和 status，不读取项目外文件也不降级为 Markdown 通过

### Requirement: 新合同必须沿 TC V 与机器证据完成闭环
系统 SHALL 对显式启用机器证据合同的新变更逐项解析验证记录和验收映射中的多个证据路径，并 MUST 沿自动 TC-*、通过 V-* 与同 ID JSON 校验执行结果、定位命中和新鲜度。完成门禁 MUST 只消费持久证据，不得重跑测试、构建、浏览器或外部 CI。（D-05、D-07、D-09，A-02、A-03）

#### Scenario: Markdown 标记通过但缺少机器证据
- **WHEN** 新合同的自动 V-* 与 TC-* 均写为通过，但没有同 ID 的有效 JSON 证据
- **THEN** precomplete 和 complete 校验失败，机器输出保持项目命令 `executed: false`

#### Scenario: 单一记录引用多个证据文件
- **WHEN** 验证记录或验收映射以受支持分隔方式引用 Markdown 总结、JSON 清单和其他项目内证据
- **THEN** 系统逐项规范化、去重和检查所有路径，任一必需路径失效都不能被其他存在路径掩盖

#### Scenario: 人工验证没有本地命令证据
- **WHEN** V-* 明确为人工或视觉验证并引用对应持久产物
- **THEN** 系统按其声明类型验证证据，不要求或伪造 `local-command` 执行事实

### Requirement: 历史与外部证据必须保持显式信任边界
系统 SHALL 允许未声明机器证据合同的历史需求继续只读审计，并 MUST 将旧 Markdown 通过、失效活动路径和未联网复查的 `external-ci` 记录分别标记为历史或外部来源。兼容模式不得自动补造 JSON、改写历史事实或降低新合同门禁。（D-06、D-08，A-06、A-09）

#### Scenario: 历史已验收需求只有 Markdown 证据
- **WHEN** 旧需求在引入机器证据合同之前已经验收且只包含 Markdown 通过记录
- **THEN** 项目检查返回可定位迁移警告并保持内容不变，不以缺少 JSON 破坏历史可读性

#### Scenario: 外部 CI 引用尚未联网复查
- **WHEN** 证据记录包含运行 URL、精确提交和任务状态，但当前流程没有调用远程 API 复查
- **THEN** 系统保留 `external-ci` 来源和未远程验证标志，不把它描述为插件本地真实执行

### Requirement: 证据执行与诊断必须跨平台稳定
系统 SHALL 对路径、outputs 临时目录、子进程、包管理器入口和机器诊断执行跨平台保护；Windows MUST 不直接启动 `.cmd` 包装器，机器输出 MUST 优先提供稳定 code、status、target、evidenceId、locatorMatches 和 fresh 字段。聚焦、本地全量与真实 CI 矩阵 MUST 作为不同证据层级记录。（D-14，A-09）

#### Scenario: Windows 聚焦命令来自 npm 脚本
- **WHEN** Windows 环境需要执行 npm 聚焦脚本
- **THEN** 系统通过当前 Node 执行可追溯 npm JavaScript 入口，无法解析时明确阻断，不回退到直接启动 `npm.cmd` 或默认 shell

#### Scenario: 本地验证通过但矩阵尚未运行
- **WHEN** 聚焦回归和本地统一验证成功，但同一提交的仓库五平台矩阵没有完整结果
- **THEN** 外部跨平台证据保持计划或阻断，不得由本地证据替代为通过
