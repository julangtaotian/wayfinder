## Context

见 [proposal.md](./proposal.md)。本设计以 `D-22` 的左侧标签事实和 `A-12` 的双库五档验收为边界。当前两套 `ResponsiveFormLayout.vue` 显式设置顶部标签，并将字段高度按“24px 标签 + 32px 控件”计算；现有快照只记录字段外框，没有记录标签和控件的相对几何，因此错误实现仍能通过。

## Goals / Non-Goals

**Goals:**

- 用两套组件库都可稳定实现的单行弹性字段结构还原蓝湖左侧标签。
- 让正式规范、源码静态契约、浏览器几何测量和截图证据同时覆盖标签方向。
- 保留既有断点、壳层、操作组交互和组件库真实实例。

**Non-Goals:**

- 不修改 183 条组件场景、其他表单规范或组件库公共主题。
- 不把验证专用选择器、框架属性或浏览器设施写入通用 Markdown。
- 不把蓝湖未定义的 `<1024px` 行为纳入本次修正。

## Decisions

### 1. 字段使用单行弹性结构

每个字段组保持一个栅格单元，标签使用固有内容宽度且不可收缩，右侧控件容器使用剩余宽度并允许收缩。两套工程都显式声明左侧标签，同时用专页局部样式消除组件库版本之间的默认布局差异。

替代方案是设置统一 `label-width`。该方案会让“时间”等短标签产生不必要空白，并与蓝湖同一行中不同控件宽度不符，因此不采用。

### 2. 约 `12px` 间距由标签右侧留白实现

标签采用 `12px` 右侧留白，32px 行高并与控件垂直居中；控件宽度由字段剩余空间计算。该值作为 `@1x` 画板实测约值按 `±2px` 验收，不与字段列间距 `8px` 混用。

替代方案是复用组件库默认标签间距。两个组件库版本的内部结构和默认值可能漂移，无法形成稳定规范，因此采用专页局部覆盖。

### 3. 快照由字段外框扩展为逐字段内部几何

每个字段样本新增标签矩形、控件矩形、水平间距、垂直中心差、`labelLeftOfControl` 和 `singleLine`。测试同时断言所有字段，而不是只抽查首项；这样即使列数和外框不变，顶部标签也会直接失败。

### 4. 十张证据原路径覆盖更新

修正后沿用既有五档文件名重新采集，JSON 和报告同步更新，不新增第二套“修正版”命名。旧 V-21 保留为历史记录，V-24 成为字段内部结构的通过证据。

## Risks / Trade-offs

- [长标签压缩控件] → 字段和控件容器均允许收缩，标签不换行；若业务出现超长标签，必须使用项目级跨列方案，不能修改本规范断点。
- [Element UI 与 Element Plus DOM 不同] → 快照按稳定的表单项、标签和内容容器语义读取，并在两套运行时实际测量。
- [只改源码未刷新构建证据] → 两套工程必须重新生产构建，并由测试检查新静态产物和浏览器实际页面。
