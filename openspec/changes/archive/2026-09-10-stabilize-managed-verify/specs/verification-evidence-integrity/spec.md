## ADDED Requirements

### Requirement: 语义绑定版本必须兼容验证结果闭环

系统 MUST 为新生成的严格机器证据使用语义绑定 v2，并 MUST 只把会改变验证目标的决策、验收、映射断言、需求修订和测试用例定义纳入绑定。验证日期、结果、证据路径、验收复选状态、测试方案状态、用例结果和运行说明 MUST NOT 使 v2 证据过期。系统 MUST 按证据记录的绑定版本复算，保留 v1 原字段集合，不得猜测或接受未知版本。（D-01、D-02、D-03、D-05；A-01、A-02、A-03）

#### Scenario: 成功执行后补写完成事实

- **WHEN** v2 本地证据成功生成后，只更新对应 V-* 和 TC-* 的日期、结果、证据路径、状态、验收复选状态或独立运行说明
- **THEN** 语义绑定保持新鲜，完成门禁继续复算命令、定位、日志、工作区与 Git 来源，并在第一次校验通过

#### Scenario: 验证目标发生真实变化

- **WHEN** v2 证据生成后，关联 D/A、映射断言、最新 R-*、TC 操作、可观察断言、目标测试、定位、聚焦命令或关联关系发生变化
- **THEN** 系统返回 `stale_semantic_evidence`、`fresh: false` 和 `semanticFresh: false`，不得使用旧证据完成变更

#### Scenario: 读取已有 v1 绑定

- **WHEN** 清单记录语义绑定 v1
- **THEN** 系统按原字段集合和原算法复算，未变化时保持兼容，原 v1 字段变化时仍判旧，并且不改写该清单

#### Scenario: 读取未知绑定版本

- **WHEN** 清单缺少有效绑定版本或记录当前实现不支持的版本
- **THEN** 系统返回稳定的版本错误、对应 target 与 evidenceId，不回退到任一算法猜测通过
