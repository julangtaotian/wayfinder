## Why

开发者效果基准的主编排模块已达到 800 行，基础模块达到 776 行，继续维护会增加局部读取成本并触及仓库单文件预算。仓库同时缺少一个零依赖、能在统一验证早期发现 JavaScript 语法错误的静态入口。

## What Changes

- 将主编排模块的单次执行与整轮状态推进下沉到独立运行模块，保留原路径、导出和 CLI。
- 将基础模块的模拟用例校验、冻结与路线识别下沉到独立用例模块，保留原路径和导出。
- 为原入口和新增模块建立职责、单向依赖与更小的行数门禁。
- 新增仅扫描仓库自有 JavaScript 的零依赖语法检查，提供稳定机器结果和独立 package script。
- 将静态检查加入现有无 shell 统一验证步骤，并覆盖失败停止、路径与退出状态。
- 按 REQ-2026-047 的 D-01 声明纯内部重构与仓库工具变更，使用 `skip_specs: true`。

## Capabilities

### New Capabilities

无。本轮不新增插件或基准的可观察能力。

### Modified Capabilities

无。既有基准行为、公开 API、CLI、输出和错误语义保持不变；新增静态检查只服务当前仓库开发验证。

## Impact

- 需求依据：D-01～D-06；验收边界：A-01～A-04。
- 受影响源码：两个基准入口、新增内部模块、根静态检查脚本、统一验证步骤和 package scripts。
- 受影响测试：基准专用测试、统一验证测试与新增静态检查专用测试。
- 依赖与系统：仅使用 Node.js 标准库，不修改内置运行时、平台资产、业务项目或第三方依赖。
- 跨平台：命中 CI、路径、子进程、包管理器入口和机器诊断；本地回归与真实五平台 CI 分层记录。
