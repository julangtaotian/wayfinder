## Context

当前配置版本和状态版本均为 1；`interactions` 只接受字符串数组，模板适配器检测到非空交互就停止。适配器能够生成截图、节点坐标和计算样式，但默认结果保持 `analysisPending: true`，完成命令只根据高置信度问题数组决定状态。Playwright 运行时由一个 `platform.json` 和一个完整性清单描述，浏览器资产固定为 `darwin-arm64`；Linux CI 遇到不兼容会安全跳过浏览器冒烟。验收、报告、修复与复验已有细粒度脚本和状态门禁，但没有统一执行入口。详见 proposal.md 和本变更 delta spec。（D-01、D-03、D-06～D-14；A-08～A-12）

项目约束要求插件默认可预览、只在显式写入时修改项目，运行阶段不安装依赖，目标路径必须安全规范化，老配置保持兼容，并且自动修复不能扩大到主分支、未授权源码或远程操作。

## Goals / Non-Goals

**Goals:**

- 让默认适配器覆盖常见 DOM 型复杂交互，同时以严格允许列表和稳定执行记录防止配置变成任意自动化入口。
- 让不具备视觉模型的工具也能对明确的 DOM/样式与图片区域差异下结论，对无法可靠判断的输入统一使用 `inconclusive`。
- 在一个插件发布物中提供 Apple Silicon Mac 与 Linux x64 所需的匹配浏览器资产，业务项目保持零安装。
- 复用现有底层函数形成薄编排入口，不复制状态机、报告器或安全校验。

**Non-Goals:**

- 不实现通用 RPA、任意脚本、验证码、Canvas/WebGL 语义判断、多窗口或认证信息托管。
- 不承诺跨浏览器渲染像素完全一致，也不把 AI 视觉兜底改成强制依赖。
- 不支持 Windows、Intel Mac、Linux ARM，不在运行阶段下载缺失平台包。
- 不自动启动业务项目、修改源码、提交推送、创建 PR 或建设远程管理服务。

## Decisions

### 1. 配置版本 2 使用结构化步骤，版本 1 保持只读兼容

新模板写入 `schemaVersion: 2`。版本 2 的 `interactions` 只接受结构化对象；版本 1 继续接受字符串数组并保留现有规范化结果和指纹来源。加载器将两种版本转换为带 `interactionMode` 的内部模型，但不会把旧字符串转成动作。新结构化步骤、比较规则、掩码和阈值全部进入场景指纹。

允许动作保持封闭集合：`click`、`hover`、`fill`、`press`、`select-option`、`check`、`uncheck`、`wait-for`、`assert`、`capture`。每个动作拥有独立允许字段，目标动作要求选择器唯一命中；等待时间限制在 100～30000ms；填写值限制长度且配置不得保存凭据。`capture` 只接受安全名称，实际路径由运行目录和步骤索引生成，不接受用户路径。

交互执行器放在独立的确定性模块中，模板适配器只负责创建浏览器、调用执行器、采集目标和最终截图。执行结果记录步骤索引、动作、目标、耗时、结果和分段截图项目路径；不记录输入凭据、页面存储或模型推理。

选择严格结构化步骤而不是自然语言解释，是为了让其他 AI 工具和 CI 得到相同行为，也避免把配置扩展为隐式代码执行。特殊交互继续使用现有项目适配器。

### 2. 比较规则显式声明，三态结论与修复资格分离

版本 2 场景增加 `comparison`：

- `dom` 规则以目标选择器、计算样式属性或可观察属性、期望值和可选数值容差描述精确断言。
- `image` 规则以实际目标选择器、设计图矩形、可选成对忽略区域和固定阈值描述区域比较。全图比较只在设计图像素尺寸与实际截图完全一致时允许。
- `hybrid` 同时要求 DOM 与图片规则完成；任一必需规则不确定时整体为 `inconclusive`。

新增平台无关的图片比较运行时，直接固定 `pngjs` 与 `pixelmatch` 的版本、许可和完整性，不使用 Playwright 私有导出。依赖只存在于插件发布物，不写入业务项目。比较器输出差异像素、比例、阈值、区域坐标和差异图路径；图片损坏、尺寸或区域不能对齐时返回结构化不确定原因。

状态版本升级为 2，并将结论显式写入 `status`：验收使用 `passed`、`needs-fix` 或 `inconclusive`；复验继续使用 `passed`、`failed` 或 `inconclusive`。读取器兼容版本 1 历史状态，但不原地改写；新运行一律写版本 2。

确定性 `observations` 与可自动修复 `repairCandidates` 分离。DOM/样式差异只有在配置和目标节点同时提供稳定源码文件、锚点、目标值、修改边界和复验断言时才成为修复候选。图片差异可以明确形成 `needs-fix`，但缺少源码上下文时标记 `repairable: false`；现有修复门禁只接收完整候选。这样既不丢失视觉问题，也不会为自动修复伪造 CSS 定位。

采用三态而不是把中置信度过滤为空，是为了使 CI 的 `passed` 保持强语义。视觉 Skill 只在结果为 `inconclusive` 且配置已声明 Browser 兜底时介入；它补充结论后仍必须经过状态和报告校验。

### 3. 单一共享 Node 运行时携带两个逻辑平台包

Playwright 的 JavaScript 包跨平台复用，不复制整套 `node_modules`。现有运行时调整为：

```text
runtime/playwright/
├── package.json
├── node_modules/playwright*/
├── platforms/
│   ├── darwin-arm64.json
│   └── linux-x64.json
└── node_modules/playwright-core/.local-browsers/
    ├── ...mac-arm64/
    └── ...linux-x64/
runtime/playwright-integrity/
├── darwin-arm64.json
└── linux-x64.json
```

每个平台元数据显式列出浏览器、FFmpeg 和许可路径。完整性清单由共享 Playwright 文件与当前平台资产组成；检查器忽略其他平台资产但拒绝当前清单中的缺失、额外和摘要变化。运行器根据 `process.platform-process.arch` 选择唯一元数据，并将匹配的浏览器可执行路径显式传给 Chromium，禁止回退到用户缓存。

构建脚本只在仓库维护或发布阶段通过显式平台参数生成资产和清单；它不进入业务项目运行链路。Linux 资产使用 Playwright 固定版本支持的目标平台下载并由 Git LFS 跟踪。普通 `--check` 和 `--smoke` 永不下载。GitHub Actions 的 Linux 验证要求 `compatible=true`、`skipped=false` 和有效截图；Apple Silicon Mac 由本地聚焦验证证明。

选择共享 Node 运行时加双平台浏览器资产，是因为当前本地 marketplace 不提供可靠的按平台条件安装字段。它比复制两个完整运行时更小，同时仍满足一次安装和离线运行。目录继续保持可拆分，未来如果安装器支持平台定向发布，可以不改变运行时选择合同。

### 4. 统一入口复用状态函数并保持显式写入

新增 `ui-review-runner.mjs`，提供 `review` 和 `verify` 两种模式。默认只完成配置、平台、场景、交互和比较计划校验并输出预览；`--write` 执行以下固定流水线：

```text
加载配置 → 创建 review/verify 状态 → 执行 Playwright 适配器
→ 执行确定性比较 → 生成报告 → 完成状态 → 输出 JSON/退出码
```

`review` 只创建验收结果；`verify` 必须接收基线状态并复用场景指纹与实际采集器。统一入口通过导入现有模块函数工作，不通过 Shell 拼接或再次启动自身命令。兼容项目命令只继续由现有细粒度计划暴露；统一入口第一版只自动执行插件内置适配器，避免扩大任意命令权限。

如果结果为 `inconclusive` 且声明 Browser 兜底，入口输出 `fallbackRequired: true`、新运行要求和现有证据，不尝试直接控制某个 AI 工具。视觉 Skill 使用现有细粒度完成入口提交补充结果。这样统一入口对无视觉能力工具仍然稳定，也保留 Codex 视觉兜底。

退出码只由最终机器状态映射：0 为 `passed`，1 为 `needs-fix` 或复验 `failed`，2 为 `inconclusive`，3 为配置、页面、交互、平台或产物阻塞。预览成功返回 0 并明确 `write: false`，不能被描述成验收通过。

### 5. 测试按功能与平台发布职责拆分

`tests/ui-review-automation.test.mjs` 继续覆盖配置版本、结构化步骤、真实弹窗/下拉/表单执行、三态比较、状态迁移、统一入口、视觉兜底和旧配置兼容。测试使用内置 Chromium 加载确定性本地 HTML，不依赖外部网络。

新增 `tests/ui-review-platform-runtime.test.mjs`，只覆盖平台索引、共享/平台资产边界、独立完整性、缺包和混装失败、真实冒烟结果与 CI 禁止跳过。这样不会把平台发布资产职责继续堆入现有功能测试。

完成阶段先运行两个聚焦测试，再执行全量 `npm run verify`、需求与严格 OpenSpec 校验、三个 UI Skill 的官方 validator、Plugin validator、缓存安装后的双运行时检查和复杂场景人工验收。

## Risks / Trade-offs

- [跨操作系统字体与抗锯齿造成像素差异] → 图片阈值按平台固定，比较区域和忽略区域显式配置；无法可靠对齐时返回 `inconclusive`，不追求跨平台同一像素基线。
- [双平台浏览器资产增加插件体积和 Git LFS 压力] → 共享 Playwright Node 包，只增加 Linux 浏览器与 FFmpeg；每平台清单独立，保留未来平台定向发布的目录边界。
- [结构化交互动作持续膨胀为 RPA] → 动作允许列表由规格固定，特殊操作必须使用项目适配器；不增加脚本、循环、条件分支、变量或凭据注入。
- [新状态版本破坏历史复验] → 版本 1 只读兼容并保留指纹；新结论只写入独立版本 2 运行，不原地迁移历史状态。
- [明确图片差异不一定能安全自动修复] → 视觉问题与修复候选分离，缺少源码上下文时只报告，不进入修复门禁。
- [统一入口看似自动化但页面未启动] → 入口明确要求 URL 已可访问；项目启动继续由用户或 CI 独立负责，避免执行任意项目命令。

## Migration Plan

1. 先增加配置/状态双版本读取和新内部模型，保持所有版本 1 测试通过。
2. 增加结构化交互与确定性比较模块，新模板切换到版本 2；旧模板生成结果继续可读。
3. 调整 Playwright 平台索引与完整性格式，迁移现有 Mac 资产后再加入 Linux 资产；两个平台清单完成前不删除旧检查路径。
4. 增加统一入口并改造三个 UI Skill 与共享参考，细粒度命令继续保留。
5. 在本地 Mac 与 Linux CI 分别真实启动 Chromium，完成复杂交互和三态判断后再更新插件版本与缓存。

回滚时可以恢复版本 1 模板和细粒度入口；版本 2 运行目录保持只读证据，不删除业务项目产物。平台索引失败时必须阻塞，不能回退到用户缓存或下载路径。
