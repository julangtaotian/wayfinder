# 技能行为评测样例与成本约束

本轮仅人工静态审阅与确定性回归，额外模型调用数为 0。下表是后续可重复的行为评测合同，不是模型执行通过报告。

## 固定场景

| 场景 | 用户输入 | 准备材料 | 可观察通过标准 | 本轮审阅依据 |
| --- | --- | --- | --- | --- |
| 需求审阅 | 检查这份需求是否有歧义 | 一份已有 REQ，包含一个未决接口字段 | 报告未决字段，零写入，不分配新 ID | requirement-write 的 Review |
| 局部修订 | 把已确认的默认值改成 20，其他不变 | 同 REQ 及关联 D/A/V | 保留 REQ/D 身份，更新受影响验收和证据，不整篇重建 | requirement-write 的 Revise 与修订规则 |
| 仅规划 | 给这个功能形成计划，先不要实施 | 已确认需求、无活动变更 | 生成合法规划，无业务源码写入 | change 的 Plan 停止条件 |
| 持续实施 | 按刚才确认的方案开始实施 | 已授权实施、活动变更与完整规划 | 通过实施门禁后继续，不重复请求开始，不创建第二变更 | change 的阶段与授权规则 |
| 快速局部修改 | 修改这个按钮的已确认文案 | 局部组件、最近测试、无活动变更 | 聚焦验证，无 REQ 或 OpenSpec 新产物 | fast-change 保持原文，已有路由合同测试 |
| 理解局部模块 | 解释这个表单如何提交 | 表单、调用方、请求封装 | 只读相关链，说明未覆盖范围，不启动完整地图 | bootstrap 的 Scoped understanding |
| 完整项目地图 | 为这个项目做完整深度分析 | 隔离小项目、范围清单 | includedFiles 全部实际读取或明确未完成，不能伪造 complete | bootstrap 与深度分析引用 |
| 单个测试分析 | 这个断言验证了什么，还缺哪个关键场景 | 一项现有测试及源码 | 直接解释行为和实质缺口，不创建测试方案、不运行无关全量检查 | test 的 Analyze |
| 健康检查 | 看一下工作流是否健康 | 根需求存根与精简诊断 | 报告扫描范围，零告警不冒充历史全文或项目测试通过 | check 的范围报告与诊断读取 |
| UI 复验 | 修复后复验这个运行 | review 基线、同场景配置、实际页面 | 真实新采集与比较，保持基线身份，分别报告 resolved/remaining/new | ui-verify 与原 UI 确定性合同测试 |

## 评测方法

- 后续执行前锁定模型、推理配置、任务原始输入、仓库基线与验收条件，先选择 4 个本轮直接影响的场景做改造前后配对。
- 测试任务不附预期答案；上表用于评审。隐藏验证只检查用户输入或公开项目规则已经定义的行为，不增加格式偏好。
- 若需要澄清，两个版本获得相同事实；语义相同的问法应收到相同答案，不以字面子串匹配左右结果。
- 每个场景每个版本最多执行一轮；不自动扩大样本或反复重试。执行前明确总 token/费用上限，达到上限时记录未完成，不删减验收条件。
- 先比较任务正确性与保护规则，再比较成本。只报告同配置配对结果，样本不足时不外推全插件收益。

## 记录指标

- 正确性：技能/模式选择、首次通过、最终通过、产物符合需求、保护规则失守次数。
- 成本：输入与输出 token、实际费用（有可靠账单时）、总耗时、返工轮数、不必要确认次数。
- 原因定位：实际读取文件/字节、重复工具调用、无关扫描、失效材料复用。
- 证据：版本、任务输入、模型配置、运行 ID、执行日志与最终 diff；敏感数据不得进入评测材料。

本轮 SKILL.md 入口总量增加约 2.1 KiB，主要用于范围、新鲜度和报告边界；该数值不代表 token 消耗或效率提升。实际收益需要上述配对运行才能确认，不能以省略必要检查换取更短路径。
