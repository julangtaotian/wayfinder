## Context

参见 `proposal.md`。当前仓库已经使用 schema v2，Git 中没有 outputs、需求归档或 OpenSpec 归档，但根文档尚未形成完整职责地图；`.gitignore` 仍按旧主题维护 outputs 规则；根 UI Review 配置依赖的页面、设计图片和源码目标全部缺失。实现必须保留本地被忽略数据、插件发布模板和五平台路径语义。

## Goals / Non-Goals

**Goals:**

- 让维护者只读根 README 就能判断每个关键路径的职责、生命周期、必要性和修改入口。
- 让 AGENTS、README、`.gitignore`、正式规格和真实 Git 跟踪集合表达一致的 v2 存储模型。
- 用真实 Git 忽略语义和跟踪集合验证职责合同，防止失效项目配置和旧 outputs 规则回流。

**Non-Goals:**

- 不清理本地被忽略的 outputs、dist、缓存或用户数据。
- 不重构插件脚本、技能、运行时或业务项目 UI Review 能力。
- 不为每个普通目录新增 README，也不建立第二份仓库结构文档。

## Decisions

### 根 README 作为唯一职责地图

在现有“项目落地文件”之前新增“仓库结构与职责”，同时覆盖受跟踪目录、关键根文件和本地生成目录。表格明确“内容与边界、生命周期、必要性、主要维护入口”，避免读者把业务项目生成结构与插件源码仓库结构混淆。

备选方案是新增 `docs/repository-structure.md` 或为每个目录增加 README。前者会制造第二层入口并增加引用维护，后者会扩大文档数量和 AI 默认读取面，因此不采用。

### AGENTS 只保留执行约束

扩展 `AGENTS.md` 的结构职责，让 AI 能快速路由到 marketplace、发布源码、规划合同、活动材料、设计、测试和本地运行目录；详细能力与使用方式继续只放 README。两者通过职责而非重复正文保持一致。

### outputs 使用单一根忽略规则

删除所有 `/outputs/<topic>/` 条目，改为 `/outputs/`。这与 v2 体积门禁的零上限一致，也能保护尚未迁移的本地旧数据不进入 Git。`design/`、`.workflow-history/` 和 `openspec/specs/` 不匹配该规则，仓库测试将显式验证反忽略边界。

备选方案是继续维护主题白名单；它要求每个新任务修改 `.gitignore`，与统一运行目录合同冲突，因此不采用。

### 删除不可复现的根 UI Review 项目配置

根 `.frontend-ui-review/config.json` 的四个场景全部引用不存在的 outputs 路径，适配器没有独立职责。删除两个受跟踪文件，但不删除插件模板、UI Review 脚本、fixture 或本地 runs。未来若仓库重新具备真实页面与设计输入，应从当前模板重新建立项目配置，而不是恢复失效路径。

### 在现有仓库卫生测试中增加回归

复用 `tests/repository-hygiene.test.mjs`，新增以下断言：

- 任意根 outputs 文件被忽略，且 `.gitignore` 不再出现主题级 outputs 规则；
- README 职责地图覆盖声明的关键路径与必要性字段；
- 根失效 UI Review 配置不再受跟踪，插件模板和测试 fixture 仍存在；
- 持久设计、正式规格和事件文件保持可提交。

不创建新的测试文件，因为这些断言与现有 Git 忽略和跟踪边界属于同一功能职责。

### 修正规格而不恢复历史正文

`ai-context-efficiency` 中旧的“历史需求正文必须存放年度归档”要求改为按生命周期模式分流：v2 使用活动需求、正式规格和事件，legacy-readonly 才按需读取旧归档。这样正式合同与当前实现一致，不需要重新引入已删除目录。

## Risks / Trade-offs

- [删除根 UI Review 配置后无法直接复跑历史四场景] → 这些场景当前已无法运行，Git 历史仍可恢复；未来配置必须绑定真实受跟踪输入。
- [统一忽略 outputs 可能隐藏旧工具的新输出] → 这是 v2 的预期边界；体积门禁继续拒绝强制加入 Git，README 指向 `.frontend-ai-workflow/` 与 `design/` 的正确目的地。
- [职责表随目录增长而过期] → 仓库治理测试检查关键路径集合，新增顶层职责时必须同步 README。
- [路径规则跨平台差异] → 使用 `git check-ignore --no-index` 和稳定相对路径断言，并由五平台 CI 验证最终候选提交。

## Migration Plan

1. 更新根职责文档和 `.gitignore`，不触碰本地被忽略文件。
2. 删除两个失效的受跟踪项目配置文件。
3. 更新仓库卫生测试并运行聚焦验证。
4. 运行共享验证和人工引用反查；最终提交后由五平台 CI 验证。
5. 若需要回滚，只恢复本变更涉及的受跟踪文件；本地 outputs 和运行缓存始终保持原状。
