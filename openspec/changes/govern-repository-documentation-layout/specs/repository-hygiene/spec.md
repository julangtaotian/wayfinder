## ADDED Requirements

### Requirement: 仓库职责地图与持久项目配置必须保持有效

仓库 MUST 在根文档中维护覆盖关键根文件、受跟踪顶层目录和本地生成目录的职责地图，并 MUST 为每个条目说明内容边界、生命周期、必要性和主要维护入口。AI 维护约束与使用说明 MUST 保持分工，不得通过为普通源码目录重复增加入口文档来替代根职责地图。根 `outputs/` MUST 作为整体退役并被统一忽略；持久设计输入、正式规格和生命周期事件 MUST 保持可提交。仓库只有在页面、设计依据、目标源码和交互事实均可由受跟踪内容复现时，才能长期保留项目级 UI Review 配置与适配器。

#### Scenario: 维护者查询仓库目录职责

- **WHEN** 维护者需要判断关键根文件、顶层目录或本地生成目录的用途与保留策略
- **THEN** 根职责地图提供唯一且可定位的内容边界、生命周期、必要性和维护入口
- **AND** `AGENTS.md` 只补充执行约束，不复制完整使用说明

#### Scenario: 旧工具继续写入根 outputs

- **WHEN** 任意旧工具在根 `outputs/` 下生成文件
- **THEN** Git 通过单一根规则忽略该文件，体积门禁仍以零上限拒绝被强制跟踪的 outputs 内容
- **AND** `design/`、`openspec/specs/` 与 `.workflow-history/` 不被误忽略

#### Scenario: 项目级 UI Review 配置依赖失效目标

- **WHEN** 仓库根 UI Review 配置引用的页面、设计依据或源码目标已不存在且没有当前项目事实可重建
- **THEN** 仓库移除该项目级配置与配套适配器，不把不可执行配置描述为正式交付能力
- **AND** 插件模板、运行脚本和测试 fixture 保持可用
