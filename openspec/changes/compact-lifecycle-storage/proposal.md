## Why

当前需求完成会长期保存需求正文、OpenSpec 归档和多层证据目录，使仓库体积、状态迁移步骤和 AI 读取成本随需求数量线性增长。依据 D-01～D-19，本变更把完成历史收敛为紧凑事件，把完整规划与普通证据限定在活动期和本地运行期，同时保留 OpenSpec 原生校验、规格同步和安全恢复能力（A-01～A-10）。

## What Changes

- **BREAKING**：完成后的权威状态从“需求正文已验收 + 永久归档目录”切换为 lifecycle schema v2 追加事件；活动需求和活动变更在成功完成后移除。
- 新增事件 schema、状态投影、仓库级完成锁、事务恢复、Git 特殊状态保护和基于 merge-base 的历史差异门禁。
- OpenSpec 原生 archive 仅作为事务内规格同步步骤使用，成功写入事件后清除临时归档；不修改内置 OpenSpec 运行时。
- 默认不跟踪普通验证输出；严格或高风险完成至多保留一个有界证据包。运行、缓存和事务分别写入统一忽略目录。
- 增加按阶段压缩的上下文输出、正式规格重复/退役/上下文预算诊断及测试定位歧义诊断。
- 增加安全存量迁移预览和显式写入，阻止未知文件、符号链接、仍被引用资产或用户未跟踪内容被误删。
- CI 拒绝 v1/v2 混写、事件篡改、无事件的活动变更删除和被跟踪的运行时产物，并为普通平台产物设置 14 天保留期。
- 更新技能、模板、仓库说明和验证脚本，不再指导逐主题扩充 `outputs` 或移动证据引用。

## Capabilities

### New Capabilities

- `compact-lifecycle-history`: 生命周期事件 schema、状态投影、分支/多项目语义、事务锁、Git 差异和安全存量迁移。

### Modified Capabilities

- `verifiable-change-delivery`: 完成流程由永久归档改为原生同步后追加紧凑事件并清理活动材料，证据信任边界保持分层。
- `repository-footprint-governance`: 从 tracked outputs 数量预算升级为禁止跟踪运行时/归档路径，并覆盖规格与测试上下文增长诊断。
- `ai-context-efficiency`: 增加 plan/implement/verify/complete 阶段上下文编译，不创建新的持久副本。
- `ai-ui-review-artifacts`: UI Review 配置与运行产物分离，运行结果默认位于统一忽略目录。

## Impact

- 主要代码：完成入口、需求解析、历史状态、项目检查、体积门禁、UI Review 存储、验证运行时和迁移脚本。
- 主要合同：生命周期格式升级为 v2；旧归档只读兼容，旧写入器与混合结构失败关闭。
- CI：五平台矩阵与共享验证继续存在，新增差异门禁和产物保留策略；外部结果不回写仓库。
- 数据：不重写 Git 历史，不删除未跟踪内容；存量删除必须经过预览与显式授权。
- 依赖：继续仅使用 Node.js 标准库，不新增第三方包。
