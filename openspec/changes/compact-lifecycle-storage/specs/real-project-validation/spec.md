## MODIFIED Requirements

### Requirement: 可能写入的验证必须与原工作区隔离

系统 MUST 只在原项目执行只读事实检查。初始化写入、重复执行、升级、测试、构建、缓存生成或清理等可能产生文件的操作 MUST 在 `.frontend-ai-workflow/runs/real-project-validation/<run-id>/` 下由精确提交创建的有界隔离副本中执行，并 MUST NOT 联网安装或更新依赖、跟随越界符号链接、复用父 Git 根、修改原仓库 Git 元数据或写入 `outputs/`。（D-03、D-04、D-10、D-13；A-03、A-09）

#### Scenario: 生命周期操作在隔离副本执行

- **WHEN** 验证需要显式写入初始化、重复写入、升级或项目测试
- **THEN** 命令工作目录和全部验证缓存位于本轮有界受管运行目录
- **AND** 原项目执行前后的提交与工作区状态完全一致

#### Scenario: 隔离依赖无法安全准备

- **WHEN** 项目测试依赖缺失、磁盘预算不足或依赖树包含无法安全隔离的越界链接
- **THEN** 系统将对应测试阶段标记为 `blocked` 并保留原因
- **AND** 系统不得联网安装依赖或回退到原工作区执行可能写入的命令

#### Scenario: 验证结束或中途失败

- **WHEN** 单项目或整轮验证成功、命令失败或进程异常结束
- **THEN** 系统执行该项目的有界清理并单独记录清理状态
- **AND** 清理失败不得覆盖原始失败，也不得删除其他 run、缓存或项目资产
