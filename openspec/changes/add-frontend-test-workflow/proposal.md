## Why

当前需求与变更工作流能够要求 AI 补充测试，却没有独立、可审查、可重复校验的测试用例产物。测试设计、测试代码和验证证据之间缺少 `TC-*` 追踪层，使写代码前的覆盖审查、存量缺口分析和需求修订后的失效判断都依赖单次 AI 判断。（D-01、D-02、D-05、D-10）

## What Changes

- 新增唯一公共 `$frontend-test` 入口，支持只读分析、持久化测试方案、项目原生测试实现和聚焦验证四类意图。（D-01、D-03）
- 为活动变更新增 `test-plan.md` 派生技术产物，以 `TC-*` 关联 D/A、规格、状态、测试定位、命令、结果、V-* 与需求修订基线。（D-02、D-04、D-05）
- 新增测试上下文识别与 `plan / implement / complete` 三阶段校验，拒绝未确认事实、未知引用、危险路径、生成测试误用、过期方案和未完成结果。（D-06、D-08、D-10）
- 让测试实现只使用项目已有设施并只修改专用测试；缺少设施或发现产品缺陷时明确阻断或交接，不安装依赖、不修改业务源码。（D-07、D-08、D-13）
- 将聚焦结果分类、V-* 证据同步、视觉/人工验证交接和测试方案状态接入现有变更实施、项目检查与完成门禁。（D-09、D-11）
- 使用 Vue 3 + Vite + Vitest fixture 完成首版兼容证明；验证专用 Vitest 按需准备在 `outputs/frontend-test-runtime/`，不在项目根目录保留安装产物，并同步 0.15.0 的 Skill、模板、脚本、文档、结构校验和发布元数据。（D-12、D-14）
- 将 CI、路径、临时目录、子进程、包管理器入口、环境变量和机器可读诊断标记为跨平台高风险修改，接入共享检查清单、稳定结构断言、平台差异回归与真实矩阵证据边界。（D-15）

## Capabilities

### New Capabilities

- `frontend-test-workflow`: 定义测试上下文分析、`TC-*` 测试方案、分阶段校验、项目原生测试实现、聚焦验证、结果分类和需求修订失效合同。（D-01～D-12；A-01～A-09）

### Modified Capabilities

- `feature-test-file-strategy`: 将既有专用测试选择和生成测试保护规则扩展到测试方案与独立测试实现入口。（D-07、D-08；A-03、A-04、A-07）
- `verifiable-change-delivery`: 对已声明测试方案的变更增加方案有效、未过期且证据通过的硬门禁，并对跨平台高风险变更增加显式标记、共享检查清单、确定性回归和真实 CI 矩阵证据要求。（D-06、D-09、D-10、D-15；A-03、A-06、A-08、A-11）

## Impact

- 新增公共 Skill、测试用例规则、OpenSpec 测试方案模板、上下文检查和方案校验脚本。
- 调整需求模板、需求编写与变更 Skill、项目健康检查、完成入口、结构校验、README、manifest 和版本元数据。
- 新增 `tests/frontend-test-workflow.test.mjs`，并在 Vue 3 + Vite + Vitest fixture 上验证形成、实现、执行与幂等闭环。
- 插件生产脚本继续仅使用 Node.js 标准库；真实 Vitest 兼容证据所需固定依赖只按需进入 `outputs/frontend-test-runtime/`，不进入项目根目录、插件运行时或业务项目，也不增加后台服务、远程连接或业务源码修改权限。（D-08、D-13、D-14；A-07、A-10）
- 新增跨平台 CI 防回归参考，并由仓库规则、受管模板、`$frontend-change` 和结构/合同测试共同保证该参考随插件发布且在高风险变更中被读取。（D-15；A-11）
