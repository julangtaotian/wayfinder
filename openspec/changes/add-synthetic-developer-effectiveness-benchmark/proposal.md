## Why

当前仓库只能证明工作流门禁和真实项目生命周期能够运行，不能用可重复数据回答插件是否缩短交付、降低返工或提高一次验收通过率。历史任务又缺少完整时间和交互记录，因此需要先建立受控、诚实标注的合成配对基准，验证效果采集链路并形成后续真实开发者研究的可执行基础。

## What Changes

- 新增默认只预览的合成开发者效果基准入口，固定项目 Git 基线、六个模拟需求和十二次配对执行清单（D-01、D-02、A-01、A-02）。
- 在有界输出目录内建立相同起点的插件组和对照组工作区，隔离公开需求、隐藏验收与另一组结果，并证明业务源仓库零变化（D-03～D-06、D-10、A-03、A-05）。
- 通过可注入的非交互执行器调用 Codex，记录插件实际路线、结构化事件、真实退出码、超时和安全清理状态；工作流初始化成本与单任务交付时间分开（D-04、D-05、A-03、A-07）。
- 新增稳定指标 schema 和汇总，区分未知、零值、执行失败、验收失败、误阻断候选和有效样本，并输出可导入现有指标工作簿的数据（D-07～D-09、A-04、A-06）。
- 新增独立测试方案及跨平台确定性回归，覆盖路径、临时目录、环境变量、子进程、脱敏、恢复和中断清理；本机试点与真实五平台 CI 分层报告（D-11、D-12、A-07）。
- 不增加第三方运行时依赖，不提交业务源码副本、依赖、日志、凭据或本机绝对路径。

## Capabilities

### New Capabilities

- `synthetic-developer-effectiveness-benchmark`: 定义安全生成模拟需求、配对运行插件与对照组、自动验收、采集效果指标和限制结论的完整行为合同。

### Modified Capabilities

- 无。

## Impact

- 主要影响 `plugins/frontend-ai-workflow/scripts/` 下的新基准编排与指标模块、仓库命令入口、独立测试文件和验证分组。
- 复用现有真实项目验证的 Git 基线、隔离工作区、路径安全、日志脱敏和资源预算约束，但不改变 `real-project-validation` 的既有对外行为。
- 运行证据进入 `outputs/developer-effectiveness-benchmark/<run-id>/`，默认不进入普通测试的真实代理执行，也不修改三个业务项目。
- 跨平台高风险命中路径、临时目录、子进程、环境变量和机器可读诊断；受影响平台与仓库五平台 CI 矩阵一致。
