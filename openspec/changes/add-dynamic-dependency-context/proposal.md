## Why

项目识别当前用固定包名列表生成技术栈，未预置框架、私有包和普通第三方依赖会被静默省略，有限兼容画像也可能被误读为完整项目结论。需要把依赖事实动态、完整地交给 AI，再由 AI 结合配置和源码总结职责，避免插件白名单决定项目真实技术边界。（D-01、D-02、D-04、D-05；A-01～A-04）

## What Changes

- 从根 `package.json` 的 production、development、peer、optional 四类声明动态生成有版本、可追溯、稳定排序的完整直接依赖画像，并为无效分组或版本提供稳定机器诊断。（D-02、D-03、D-07；A-01）
- 初始化、升级和检查入口复用同一动态画像；人类摘要显示总数、展示数和截断数，完整机器清单不受摘要上限影响。（D-03、D-04、D-10、D-11；A-02、A-05）
- 更新 AGENTS、Wayfinder、OpenSpec 与分析规则：AI 必须读取完整依赖事实并结合配置、源码区分事实、推断与待确认，不能根据固定列表或空画像否定框架存在。（D-01、D-05、D-12；A-03、A-04）
- 保留现有 preset、终端画像、平台画像和公共入口，将其明确定位为有限兼容/安全信号，而非完整技术栈、运行时或发布证明。（D-06、D-12；A-04）
- 使用独立手写测试覆盖未知框架、私有包、跨分组版本、空值、非法声明、稳定摘要、共享入口与无联网/安装副作用；本地统一验证后仍以最终提交五平台 CI 作为跨平台交付证据。（D-08～D-12；A-05、A-06）
- 本轮不发现 workspace 子包，不解析传递依赖，不查询 registry/漏洞/许可证，不删除现有兼容画像，也不新增框架专用适配器。（D-06、D-08、D-09、D-12）

## Capabilities

### New Capabilities

- `dynamic-dependency-context`: 定义直接依赖事实的动态收集、分组追溯、稳定摘要、异常诊断、共享入口消费及无副作用边界。（D-01～D-04、D-07～D-12；A-01、A-02、A-05、A-06）

### Modified Capabilities

- `deep-project-analysis`: 深度分析增加依赖事实读取与配置/源码交叉核对要求，禁止用包名或有限画像直接生成完整语义结论。（D-01、D-05、D-12；A-03、A-04）
- `wayfinder-workspace`: 三份受管上下文改为同步动态依赖摘要及其完整性边界，并在显式升级时保持幂等与自定义内容保护。（D-03、D-04、D-08、D-11；A-02、A-03、A-05）
- `project-target-profile`: 终端和平台画像明确为有限兼容/安全信号；未知或未命中不得覆盖、删除或否定完整动态依赖事实。（D-06、D-12；A-04）

## Impact

- 主要实现：`plugins/frontend-ai-workflow/scripts/inspect-project.mjs`、新增独立依赖画像模块、`bootstrap-project.mjs` 及三份受管模板。
- 分析规则：需求指南、深度分析说明和相关 Skills；不新增公共 Skill 或命令。
- 测试：新建 `tests/dynamic-dependency-context.test.mjs`，既有工作流和画像测试只做必要兼容断言调整。
- 数据合同：`inspectProject` 增量增加 `dependencyProfile`；旧字段保留，普通初始化仍只读，显式升级才更新目标项目。
- 跨平台高风险：命中路径、包管理器入口和机器可读诊断；覆盖 Linux x64/ARM64、Windows x64、macOS Intel/ARM64。（D-10；A-06）
- 依赖与外部系统：生产实现只使用 Node.js 标准库，不联网、不安装或执行目标依赖。（D-08、D-11）
