## ADDED Requirements

### Requirement: 完成入口必须迁移证据引用并执行归档后审计
系统 SHALL 在完成预览中列出所选活动变更证据引用到实际带日期归档前缀的确定性改写，并 MUST 只在完成前门禁通过后执行归档。归档成功后，系统 MUST 原子更新需求内属于该变更的证据引用与状态，并立即从实际归档目录执行 complete 审计；成功响应必须以该审计通过为前提。（D-05、D-09、D-10，A-02、A-04）

#### Scenario: 预览完成动作
- **WHEN** 完成前门禁通过但调用方没有显式写入
- **THEN** 系统返回预计归档目标、逐项引用改写和归档后审计动作，不修改需求、变更或规格

#### Scenario: 正式归档多个证据引用
- **WHEN** 需求引用所选活动变更下的验证说明和多个 JSON 证据，且调用方显式执行完成
- **THEN** 系统归档后把每个活动路径改为引擎返回的实际归档路径，需求状态变为已验收，并从归档目录通过 complete 审计

#### Scenario: 无关路径与 URL 同时存在
- **WHEN** 需求还包含其他变更、项目外禁止目标或外部 URL
- **THEN** 系统只改写所选变更的安全项目相对前缀，不改写其他变更、普通文字或 URL

### Requirement: 归档引用迁移必须幂等且可恢复
系统 SHALL 防止归档日期重复、目标冲突和无关内容覆盖，并 MUST 在归档成功但需求写入或归档后审计失败时返回稳定错误 code、实际归档目标、待修复引用和可重复恢复动作。恢复不得重跑项目验证或伪造完成成功。（D-10、D-11，A-05）

#### Scenario: 对已迁移需求重复运行恢复
- **WHEN** 需求引用已经指向实际归档目录且状态已更新
- **THEN** 系统识别现有归档目标并只执行一致性审计，不重复增加日期前缀或再次改写相同路径

#### Scenario: 归档成功但需求原子写入失败
- **WHEN** OpenSpec 已返回实际归档目录，但需求临时文件重命名失败
- **THEN** 系统返回部分完成 code、归档目标、原引用和目标引用，保持非成功状态并允许后续安全恢复

#### Scenario: 归档后完整审计失败
- **WHEN** 引用改写后任一必需证据不存在、损坏或与需求记录不一致
- **THEN** 系统返回归档后审计失败和具体 V-*，不得报告需求完整验收

### Requirement: 历史失效引用必须可见但不被静默改写
系统 SHALL 在只读检查中识别已验收需求指向不存在活动变更目录的证据引用，并 MUST 输出可定位迁移警告；没有用户明确启动迁移变更时，不得批量修改历史需求，也不得把失效引用继续报告为完整证据。（D-08、D-10，A-06）

#### Scenario: 历史需求引用已归档的活动路径
- **WHEN** 项目检查发现历史需求引用 `openspec/changes/<change>/...`，该活动目录不存在但唯一归档候选存在
- **THEN** 系统报告原路径、候选归档路径和迁移状态，保持只读且不自动写回
