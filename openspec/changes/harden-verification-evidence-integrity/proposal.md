## Why

现有完成门禁能够检查 Markdown 状态与证据文件是否存在，却不能证明自动验证真实执行、发现了计划测试或仍对应当前工作区；活动变更归档后，需求内证据路径还可能失效。现在需要在不改变“完成阶段不重跑”的前提下补齐机器证据、归档迁移与 UI 报告身份，让插件输出从过程说明升级为可复核的交付记录。（D-01、D-04、D-05、D-10、A-02、A-04）

## What Changes

- 新增版本化验证证据完整性能力：受控执行聚焦命令，以退出码、测试定位命中、工作区指纹与安全路径生成随变更归档的 JSON 证据。（D-02、D-03、D-04、D-13，A-01、A-08）
- 扩展需求、测试方案和完成检查，使新合同沿 TC-* → V-* → JSON 核验，并拒绝 Markdown-only、零测试、损坏、过期、越界和未知版本证据；门禁本身仍不重跑命令。（D-05、D-07、D-09，A-02、A-03）
- 扩展完成入口，预览并迁移活动变更证据引用到实际归档目录，随后执行归档后审计；历史记录保持只读警告和显式迁移边界。（D-08、D-10、D-11，A-04、A-05、A-06）
- 扩展 UI Review Markdown，使报告展示运行 ID、场景指纹、实际采集器、基线、状态文件和证据摘要，并与状态 JSON 保持一致。（D-12，A-07）
- 把路径、临时 outputs、无 shell 子进程、包管理器入口、结构化诊断和真实 CI 证据作为跨平台高风险项，分别形成聚焦、本地全量和五平台证据。（D-14，A-09）
- 不新增生产依赖、公共 Skill 名称、远程服务、日志平台或签名系统，不在完成阶段联网或自动重跑。（D-06、D-13、D-15，A-08）

## Capabilities

### New Capabilities

- `verification-evidence-integrity`: 定义本地自动验证的机器证据 schema、真实执行、零测试保护、工作区新鲜度、安全路径、多证据解析与历史兼容合同。（D-02～D-09，A-01～A-03、A-06、A-08）

### Modified Capabilities

- `verifiable-change-delivery`: 完成门禁消费持久机器证据，统一完成入口预览并迁移证据引用、执行归档后审计和报告可恢复的部分失败。（D-05、D-08～D-11，A-02～A-06）
- `plugin-ui-review-automation`: 确定性 Markdown 报告增加可独立识别且与状态 JSON 一致的运行身份与证据摘要。（D-12，A-07）

## Impact

- 影响插件验证证据生成与校验脚本、需求决策校验、测试方案完成校验、变更完成入口、UI Review 报告渲染、相关 Skills/模板/结构校验和测试。
- 新增持久路径 `openspec/changes/<change>/evidence/*.json`；完整命令日志与临时 fixture 只写入 `outputs/<验证主题>/`。
- 生产代码继续只使用 Node.js 标准库；现有 OpenSpec 生命周期、业务项目源码、测试框架和历史归档内容默认不变。（D-08、D-13、D-15，A-06、A-08）
- 跨平台高风险：是。命中路径、临时目录、子进程、包管理器入口、机器可读诊断、CI；受影响平台为仓库声明的 Linux x64/ARM64、Windows x64、macOS Intel/ARM64。（D-14，A-09）
