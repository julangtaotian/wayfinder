## Context

依据 D-01、D-02、D-03，对应 A-01、A-02、A-03；见 proposal.md。已有真实轨迹证明复杂指南被局部问题误加载；新增否定性句子未解决入口仍暴露整条工作流的问题。

## Goals / Non-Goals

目标是让常用只读路径的默认读取面显著下降，同时完整操作仍有单一可定位的原流程。入口各不超过 2400 UTF-8 字节。其他技能与脚本不在本次范围。

## Decisions

1. 入口保留意图选择、局部处理与停止条件；完整测试流程和初始化流程各迁至一份参考。相比继续追加规则，结构隔离直接减少首次加载的无关段落。
2. 移动既有流程正文，修正目录相对引用并逐段核对，保留准入与复杂边界。不会为了压缩字节删除验证门禁。
3. 对照基线固定为上一轮新版同题记录；候选仅运行一次。沿用相同模型、推理设置和 fixture，不加引导正确答案的额外提示。75 秒、5 小时账户已用 55% 停止；中止不算失败分数或节省收益。实验没有硬 token 限制能力，不将事后 usage 当作实时额度硬上限。
4. 既有链接、归档回归与统一验证负责确定性保护；人工逐项核对复杂场景，模型样本只评价有限只读任务，不冒充全部技能行为覆盖。

## Risks / Trade-offs

- 模型仍可能多读 → 以真实命令轨迹检查；不能用入口缩短宣称已省额度。
- 复杂模式多一次参考读取 → 保留完整规则更重要，本次不承诺复杂任务 token 下降。
- 缓存和服务延迟不稳定 → 报告全部用量字段，单次耗时只作为观察。
- 跨平台高风险：是；三个既有合同测试需要跟随参考文件位置，使用既有 path API，断言仍验证原规则；影响五平台，由本地回归定位与后续真实 CI 分别取证。无产品代码、运行时或 CI 改动。临时验证命中路径、子进程、环境变量和 Git fixture，遵守 cross-platform-ci-checklist，仅本机验证，不更新五平台发布结论。

## Migration Plan

验证源码后供用户提交；本轮不自动更新安装缓存。不通过时可恢复两个入口并删除新参考，归档算法无需回滚。
