## Why

仓库级验证每次都会重新解析 Vitest 的依赖树，并在结束时删除唯一的 npm 缓存；这使受限网络、离线复验和跨环境排错不稳定。将依赖树锁定并把可复用缓存与临时运行时分离，可在保持根目录无依赖的同时让验证具备可复现、可离线和可清理的行为。用户还要求以现有五平台矩阵证明该链路，而非仅依赖本机模拟。（D-01、D-02、D-03、D-04、D-05、D-06）

## What Changes

- 提交最小的 Vitest 验证运行时清单与锁文件，准备过程改为 `npm ci`。
- 将可复用 npm 缓存移至独立、被忽略且可显式清理的 outputs 子目录。
- 为准备命令与统一验证增加显式 `--offline`，离线缓存缺失时以稳定机器诊断失败关闭。
- 扩展跨平台回归测试、验证文档和验证证据。
- 在每个现有平台 runner 上在线预热缓存、清理运行时、以源码共享运行时执行离线共享验证并清理两类临时目录，再生成平台运行时进行专属验证。

## Capabilities

### New Capabilities

- 无。

### Modified Capabilities

- `frontend-test-workflow`：锁定验证依赖、分离缓存生命周期，并支持可验证的离线准备与统一验证。

## Impact

- 受影响代码：验证运行时准备、清理和统一验证入口、平台 CI 工作流，以及对应测试与文档。
- 不新增根依赖、不修改业务项目依赖、不修改插件发布运行时。
- 涉及 macOS、Linux、Windows 的 npm JavaScript 入口、路径、临时目录、环境变量和稳定诊断合同。
