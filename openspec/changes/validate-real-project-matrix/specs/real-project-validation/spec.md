## Purpose

为插件在真实历史项目上的识别、受管生命周期和测试链提供隔离、可重复、可审计的验证合同，并确保缺失证据、环境阻塞或单机结果不会被夸大为完整兼容。

## ADDED Requirements

### Requirement: 真实项目验证必须固定可追溯基线

系统 MUST 在执行真实项目验证前记录项目 ID、规范化根路径、Git 顶层目录、分支、精确提交和干净状态，并 MUST 将该快照作为本轮后续证据的新鲜度基线。原项目提交漂移或出现工作区修改时，系统 MUST 阻断该项目所有可能写入或运行依赖的后续阶段，不得继续沿用旧证据。（D-01、D-03、D-05；A-01、A-08）

#### Scenario: 干净项目进入验证

- **WHEN** 项目根、Git 顶层、分支、精确提交与矩阵声明一致且工作区干净
- **THEN** 系统记录基线并允许该项目继续执行只读识别与隔离验证

#### Scenario: 项目在执行前发生漂移

- **WHEN** 项目提交、分支或工作区状态与已记录基线不一致
- **THEN** 系统将该项目后续写入型阶段标记为 `blocked` 并报告稳定漂移原因
- **AND** 系统不得修改原项目或把旧运行结果绑定到新快照

### Requirement: 可能写入的验证必须与原工作区隔离

系统 MUST 只在原项目执行只读事实检查。初始化写入、重复执行、升级、测试、构建、缓存生成或清理等可能产生文件的操作 MUST 在 `outputs/real-project-validation/<run-id>/` 下由精确提交创建的有界隔离副本中执行，并 MUST NOT 联网安装或更新依赖、跟随越界符号链接、复用父 Git 根或修改原仓库 Git 元数据。（D-03、D-04、D-10、D-13；A-03、A-09）

#### Scenario: 生命周期操作在隔离副本执行

- **WHEN** 验证需要显式写入初始化、重复写入、升级或项目测试
- **THEN** 命令工作目录和全部验证缓存位于本轮有界输出目录
- **AND** 原项目执行前后的提交与工作区状态完全一致

#### Scenario: 隔离依赖无法安全准备

- **WHEN** 项目测试依赖缺失、磁盘预算不足或依赖树包含无法安全隔离的越界链接
- **THEN** 系统将对应测试阶段标记为 `blocked` 并保留原因
- **AND** 系统不得联网安装依赖或回退到原工作区执行可能写入的命令

#### Scenario: 验证结束或中途失败

- **WHEN** 单项目或整轮验证成功、命令失败或进程异常结束
- **THEN** 系统执行该项目的有界清理并单独记录清理状态
- **AND** 清理失败不得覆盖原始失败，也不得删除其他 run 或既有 outputs 资产

### Requirement: 真实项目矩阵必须分层执行并保持真实结果分类

系统 MUST 依次记录基线、只读识别、隔离生命周期、项目原生测试链、人工边界和插件统一验证，并 MUST 为每个项目与阶段使用 `passed`、`limited`、`blocked` 或 `defect`。脚本存在、依赖声明、preset 命中、退出码 0 或正确阻断中的任意单项 MUST NOT 被单独解释为完整能力通过。（D-05、D-06、D-07、D-08；A-02、A-04、A-05、A-06）

#### Scenario: 已认证 Vitest 项目完成闭环

- **WHEN** P1 的真实 Vitest 命令在精确提交的隔离副本中发现目标测试并成功退出
- **THEN** 系统记录实际命令、运行器、测试发现、退出码和证据，并可将该项目对应测试单元标记为 `passed`

#### Scenario: 非 Vitest 项目真实运行

- **WHEN** P2、P3 或 P4 使用项目已有 Jest/Vitest 命令运行
- **THEN** 系统按实际测试发现与退出状态记录结果，同时保持该运行器的有限支持声明
- **AND** 本次成功不得自动升级为同类所有项目或所有配置完整认证

#### Scenario: 缺少测试命令或目标定位

- **WHEN** P5、P6 或任一项目没有可用测试命令、运行器证据或可定位测试
- **THEN** 系统返回 `blocked` 或 `limited` 及稳定原因，不安装替代运行器、不虚构命令且不生成通过证据

#### Scenario: 退出成功但没有发现测试

- **WHEN** 项目命令退出码为 0 但运行器没有发现计划测试或没有目标定位
- **THEN** 系统将结果记为 `blocked` 而不是 `passed`

### Requirement: 真实项目证据必须有界且不包含敏感内容

系统 MUST 为每个运行保存项目 ID、提交、环境、命令 argv、阶段、稳定状态、稳定 code、退出码、必要摘要和产物描述；持久日志或附件 MUST 使用仓库内相对路径、大小和 SHA-256 校验。系统 MUST NOT 持久化环境变量值、令牌、Cookie、业务响应、私有配置正文、未跟踪源码全文或无关绝对路径。（D-07、D-10、D-14；A-02、A-09）

#### Scenario: 保存自动运行证据

- **WHEN** 自动阶段完成并准备持久化证据
- **THEN** 证据能够根据稳定字段、退出状态和受控附件复核结果
- **AND** 机器断言不依赖完整中文文案、平台路径分隔符或终端换行

#### Scenario: 日志包含潜在敏感内容

- **WHEN** 子进程输出包含环境变量值、凭据形态、业务响应或未跟踪文件正文
- **THEN** 系统不得将原文写入持久证据，并将该证据单元标记为需人工复核或阻断

### Requirement: 缺陷和支持结论必须与验证执行解耦

系统 MUST 将发现的插件问题记录为独立缺陷，包含项目、精确提交、稳定复现、预期、实际和影响范围；当前矩阵 MUST NOT 在同一验证步骤直接修复插件产品逻辑或业务源码。最终报告 MUST 分别列出已通过、有限、正确阻断、缺陷和未覆盖范围，并 MUST NOT 将本机、单项目、fixture 或单运行器证据外推为无漏洞、完整兼容或全平台通过。（D-09、D-11、D-12、D-13、D-14；A-07、A-10）

#### Scenario: 真实项目暴露插件缺陷

- **WHEN** 插件输出与可追溯项目事实或已确认规格不一致
- **THEN** 当前运行将该单元标记为 `defect` 并生成独立缺陷输入
- **AND** 其他不依赖该缺陷的项目和阶段可以继续验证，但当前变更不修改产品逻辑

#### Scenario: 汇总六项目结论

- **WHEN** 矩阵完成或因环境条件部分完成
- **THEN** 报告逐项显示证据层级、结果和剩余风险
- **AND** pnpm、React + Vite、真实 workspace/Monorepo、多应用、远程设计同步、后端链和未运行平台继续明确为未覆盖
