## ADDED Requirements

### Requirement: 完成流程必须分层归档已验收需求

系统 MUST 在变更归档、证据引用迁移和归档后完整审计成功后，把完整需求正文原子迁入 `requirements/archive/<year>/`，在原路径写入轻量已验收存根并刷新稳定目录索引。正式成功响应 MUST 报告根存根、归档正文和索引目标。（D-03、D-04；A-02、A-07）

#### Scenario: 正常完成并归档需求

- **WHEN** 需求、测试方案、证据、规格同步、变更归档和完整审计全部通过
- **THEN** 完整需求 MUST 只保留在年度归档路径，根路径 MUST 成为可定位正文的轻量存根，索引 MUST 指向同一正文

#### Scenario: 完成预览

- **WHEN** 全部门禁通过但调用方没有显式 `--write`
- **THEN** 系统 SHALL 列出预计需求归档路径、存根和索引动作，且 SHALL NOT 修改任一文件

#### Scenario: 需求归档写入部分失败

- **WHEN** 变更已经归档但需求正文、存根、索引或归档后审计任一步骤失败
- **THEN** 系统 MUST 返回稳定部分失败 code、实际变更归档目录、需求正文候选路径和可重复恢复参数，不得报告完成成功

### Requirement: 需求归档恢复必须保持幂等

系统 MUST 能从根完整需求、根存根或唯一年度归档正文恢复未完成迁移；重复恢复 MUST NOT 再次增加年份目录、生成第二份正文、重复改写证据或重新运行项目验证。（D-04；A-02）

#### Scenario: 正文已迁移但存根或索引未完成

- **WHEN** 恢复流程发现唯一归档正文且根入口或索引缺失
- **THEN** 系统 MUST 补齐缺失结构并执行只读完整审计，不移动正文或重跑项目命令

#### Scenario: 迁移已经完全完成

- **WHEN** 对同一需求再次执行恢复
- **THEN** 结果 MUST 保持相同归档路径和索引，不产生内容变化

#### Scenario: 存在多个归档正文候选

- **WHEN** 同一需求 ID 在历史目录存在多个无法判定的正文
- **THEN** 恢复 MUST 失败并列出冲突目标，不得自行选择或覆盖
