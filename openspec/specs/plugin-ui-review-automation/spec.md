# plugin-ui-review-automation Specification

## Purpose
让安装 `frontend-ai-workflow` 的前端项目能够在没有独立管理平台的情况下执行可重复、可追溯且可安全自动修复的 UI 验收闭环。
## Requirements
### Requirement: 插件必须提供职责分离的 UI 验收闭环
插件 SHALL 提供 UI 验收、UI 修复和 UI 复验三个公共入口；三个入口 MUST 通过同一项目运行状态衔接，并且不得要求独立 PC 客户端、Web 管理服务或数据库。（D-01、D-02、D-07，A-01）

#### Scenario: 单独执行 UI 验收
- **WHEN** 用户在已安装插件的前端项目中请求验收一个已配置场景
- **THEN** UI 验收入口只负责校验配置、采集证据、形成问题结论和写入待处理运行状态，不直接修改源码

#### Scenario: 串联验收修复与复验
- **WHEN** 一次验收发现可修复问题且用户继续执行修复与复验
- **THEN** 三个入口通过原运行 ID、父运行 ID和场景指纹串联，最终结果能够区分通过、未解决与新增问题

### Requirement: 项目配置必须经过确定性安全校验
系统 SHALL 使用带版本号的项目配置定义产物根目录、自动修复模式和至少一个验收场景；每个场景 MUST 包含稳定 ID、HTTP(S) 页面、有效视口、仓库相对设计依据和至少一个目标节点。Playwright 场景 MAY 声明仓库相对适配器或兼容项目命令，二者 MUST 互斥；适配器 MUST 是项目内已存在的模块文件。系统 MUST 拒绝未知版本、重复场景、危险路径、无效视口、缺失设计依据、空目标节点或越界适配器。（D-04、D-05、D-08、D-10，A-02、A-07）

#### Scenario: 有效配置生成稳定场景指纹
- **WHEN** 同一项目以相同页面、视口、设计内容、目标节点、交互说明和 Playwright 适配器重复读取配置
- **THEN** 系统输出相同规范化场景和 SHA-256 场景指纹

#### Scenario: 配置路径可能越出项目
- **WHEN** 配置、设计依据、Playwright 适配器或产物根目录使用绝对路径、`..`、符号链接越界或项目根目录本身
- **THEN** 系统以中文错误拒绝且不创建运行目录

#### Scenario: 同时声明适配器和兼容命令
- **WHEN** 同一 Playwright 场景同时声明项目适配器与项目命令
- **THEN** 系统以中文错误拒绝歧义配置且不执行任何一个入口

### Requirement: UI 验收运行必须保留有限且可恢复的状态
系统 SHALL 为每次场景验收创建独立运行 ID和版本化状态，记录阶段、状态、场景指纹、父运行、实际采集器、确定性结论、问题摘要和受控产物路径。运行未完成、结论不确定或失败时 MUST NOT 写成通过；重复运行 MUST NOT 覆盖其他运行或未知文件。新版本读取历史基线时 MUST 保留原场景指纹和采集器语义，不得把历史状态静默升级为更强结论。（D-05、D-07、D-08、D-12、D-14，A-02、A-05、A-09、A-11）

#### Scenario: 零问题验收完成
- **WHEN** 验收在声明场景范围内提交零个问题、完整证据和明确通过的确定性比较
- **THEN** 运行状态为有限范围 `passed` 并保留实际截图、比较指标、标注截图和 Markdown 报告路径

#### Scenario: 零问题但结论不确定
- **WHEN** 验收没有可交付问题但存在待分析、中置信度、对齐失败或缺失的必需证据
- **THEN** 运行状态为 `inconclusive`，不得写成 `passed` 或进入自动修复

#### Scenario: 运行目录存在未知内容
- **WHEN** 新运行目标目录已存在未知文件或不属于同一运行状态
- **THEN** 系统停止写入并保留既有内容

#### Scenario: 读取历史状态基线
- **WHEN** 新入口读取仍受支持的旧状态作为查看或复验基线
- **THEN** 系统保留历史指纹、采集器和有限结论，只有新的独立运行才能写入新版本状态

### Requirement: 自动修复必须默认关闭写入并执行完整门禁
系统 SHALL 将自动修复默认模式设为 `suggest`；`off` MUST 禁止修复，`suggest` MUST 在没有当前任务显式授权时只输出建议，`apply` MAY 允许进入修复。任何实际修复前 MUST 同时存在高置信度问题、仓库相对源码文件、稳定锚点、允许修改范围、禁止修改范围和至少一条复验断言；否则不得修改源码。（D-03、D-05、D-08，A-03）

#### Scenario: 默认建议模式没有授权
- **WHEN** 项目未设置自动修复模式或模式为 `suggest`，且用户没有在当前任务显式授权
- **THEN** 系统返回建议决策，不修改源码，并说明需要授权

#### Scenario: 应用模式缺少修复上下文
- **WHEN** 自动修复模式允许应用但任一问题缺少源码目标、稳定锚点、修改边界或复验断言
- **THEN** 系统拒绝应用且运行状态保持未修复

#### Scenario: 修复应用完成
- **WHEN** 修复获得授权并且只修改报告声明的安全范围
- **THEN** 系统将已应用问题记录为待复验，不得直接将验收状态改为通过

### Requirement: 复验必须使用相同场景上下文
系统 SHALL 只允许使用与基线运行相同的场景指纹创建复验；复验 MUST 复用页面、视口、设计依据、目标节点、结构化交互、比较规则和基线实际采集器，并 MUST 按稳定问题指纹区分已关闭、未解决和新增问题。只有未解决与新增问题均为空且确定性结论不是 `inconclusive` 时结果 SHALL 为通过。（D-06、D-09、D-11、D-12，A-04、A-06、A-09）

#### Scenario: 修复后问题全部关闭
- **WHEN** 复验场景指纹与基线一致，使用基线实际采集器，原问题全部消失、没有新增问题且确定性比较明确通过
- **THEN** 复验状态为 `passed`，并列出已关闭问题

#### Scenario: 复验出现未解决或新增问题
- **WHEN** 复验仍包含原问题或出现新的稳定问题指纹
- **THEN** 复验状态为 `failed`，并分别列出未解决和新增问题

#### Scenario: 同一问题的实际差异数值变化
- **WHEN** 复验仍命中相同选择器、问题类型和目标值，但实际尺寸、像素数或差异比例与基线不同
- **THEN** 稳定问题指纹保持不变并归类为 `remaining`，不得同时记为原问题已关闭和新增问题

#### Scenario: 复验结论不确定
- **WHEN** 复验没有未解决或新增高置信度问题，但确定性比较结果为 `inconclusive`
- **THEN** 复验状态保持 `inconclusive`，不得把原问题推断为已经关闭

#### Scenario: 复验上下文发生变化
- **WHEN** 当前配置计算出的场景指纹与基线运行不同，或者基线实际采集器已不在当前采集计划中
- **THEN** 系统拒绝直接复验并要求重新开始一次独立验收

### Requirement: 插件自动化不得静默扩大外部依赖与权限
系统 SHALL 优先使用插件内置的固定版本 Playwright 和匹配发布平台的 Chromium headless shell，通过项目适配器产生机器可读证据；既有项目命令配置 MUST 继续按原合同运行。只有场景显式声明且当前环境提供能力时，才可使用 Codex Browser 或同类视觉能力作为兜底。系统运行阶段不得安装或下载 Playwright 与浏览器，也不得修改主分支、提交或推送代码、创建 PR、读取认证数据或绑定特定 AI 工具与代码托管服务。（D-01、D-03、D-07、D-08、D-09、D-10，A-03、A-05、A-06、A-07）

#### Scenario: 确定性主路径可用
- **WHEN** 插件运行时版本、完整性、操作系统与 CPU 均匹配，项目适配器成功产生配置要求的实际截图和结构化结果
- **THEN** 系统使用该证据完成验收，业务项目无需声明或安装 Playwright，也不再要求或自动调用视觉兜底

#### Scenario: 当前环境没有可用采集器
- **WHEN** 内置 Playwright 运行时缺失、不完整、平台不匹配或适配器没有产生完整证据，且未声明视觉兜底或当前 AI 工具不提供该能力
- **THEN** UI 验收入口报告明确阻塞，不执行依赖安装或联网下载，也不生成虚假通过结果

#### Scenario: 兼容旧项目命令
- **WHEN** 既有场景只声明有效的 `projectPlaywright.command` 和结果路径
- **THEN** 采集计划继续输出原项目命令合同，不强制迁移适配器或改变单采集器语义

### Requirement: UI 验收必须提供可移植采集计划和显式视觉兜底
系统 SHALL 为每个场景输出机器可读采集计划，计划 MUST 包含主采集器、可选兜底采集器、允许的采集顺序和 Playwright 可移植性信息。新 Playwright 场景 MUST 能够通过仓库相对适配器使用插件内置运行时；计划 MUST 输出运行时来源、固定版本、目标平台、兼容性、不可用原因、参数数组和项目内结果路径。兼容项目命令继续使用参数数组。视觉采集器只能在场景已声明时作为显式兜底。没有新增字段的既有单采集器配置 MUST 保持原行为。（D-08、D-09、D-10，A-01、A-02、A-06、A-07）

#### Scenario: 其他 AI 工具读取项目 Playwright 主路径
- **WHEN** 场景以 Playwright 为主采集器并声明有效适配器和结果路径，且内置运行时兼容当前平台
- **THEN** 采集计划输出可直接执行的插件命令、结果路径、`portable: true`、固定运行时信息和已声明的视觉兜底，且不要求业务项目安装 Playwright 或依赖 Codex Browser

#### Scenario: 内置运行时与当前平台不兼容
- **WHEN** 采集计划发现浏览器资产的操作系统或 CPU 与当前环境不匹配
- **THEN** 计划输出 `portable: false` 和明确中文原因，不执行适配器或任何安装命令

#### Scenario: 主采集器不可用时选择视觉兜底
- **WHEN** Playwright 主路径无法产生完整证据且场景已声明 Browser 兜底
- **THEN** 调用方可以使用新的运行 ID 显式选择 Browser 开始验收，运行状态记录 Browser 为实际采集器

#### Scenario: 老配置没有兜底字段
- **WHEN** 场景只声明既有 `browser` 或命令式 `project-playwright` 采集器
- **THEN** 采集计划只允许该采集器，不自动增加或切换到另一种采集器

#### Scenario: 采集计划包含非法命令或兜底
- **WHEN** Playwright 适配器越界或不存在、项目命令为空、结果路径越界、兜底与主采集器相同或调用方选择未声明采集器
- **THEN** 系统以中文错误拒绝配置或运行，不执行命令且不创建错误通过状态

### Requirement: 默认 Playwright 路径必须执行受限结构化交互
系统 SHALL 允许新配置使用受限结构化步骤描述常见 UI 交互，并 MUST 按声明顺序执行点击、悬停、填写、按键、选择、勾选、显隐等待、文本或 URL 断言和分段截图。步骤动作、目标、值、断言和顺序 MUST 参与场景指纹；系统 MUST 拒绝未知动作、未知字段、任意 JavaScript、Shell、动态模块、越界文件和非唯一操作目标。既有字符串交互 MUST 保持原自定义适配器说明语义，不得被默认适配器猜测执行。（D-04、D-08、D-11，A-08）

#### Scenario: 结构化步骤打开并检查弹窗
- **WHEN** 场景依次声明点击触发按钮、等待弹窗可见、填写字段、断言文本和采集弹窗证据
- **THEN** 默认 Playwright 适配器按稳定索引执行全部步骤，在有限动画、字体和双帧渲染稳定后截图，记录每步结果并产生包含弹窗最终状态的截图和结构化证据

#### Scenario: 弹窗可见断言在过渡动画首帧成立
- **WHEN** 点击后弹窗节点已经可见但仍在执行有限透明度或位移动画
- **THEN** 执行器等待动画结束和双帧稳定后再执行分段或最终截图；稳定超时必须失败关闭，不得把透明或半透明弹窗作为通过证据

#### Scenario: 交互步骤包含任意代码或未知动作
- **WHEN** 新配置在交互步骤中声明脚本、Shell、动态模块、未知动作、额外字段或项目外文件
- **THEN** 系统在启动浏览器和创建运行产物前以中文错误拒绝配置

#### Scenario: 等待异步创建的节点
- **WHEN** `wait-for` 声明节点可见或已挂载，而目标节点在步骤开始后、超时前才插入 DOM
- **THEN** 执行器等待目标状态成立后校验唯一命中并继续；只有超时或最终非唯一时才失败关闭

#### Scenario: 旧配置保留字符串交互
- **WHEN** 既有配置继续使用非空字符串交互说明
- **THEN** 系统保持既有场景指纹和自定义适配器语义，默认适配器明确要求项目实现而不推测自然语言动作

### Requirement: UI 证据必须形成确定性三态结论
系统 SHALL 对声明范围内的 DOM、计算样式和受控图片区域执行确定性比较，并 MUST 将结论分类为 `passed`、`needs-fix` 或 `inconclusive`。只有所有必需证据完整且比较明确通过时才能写入 `passed`；明确超出阈值时 MUST 写入 `needs-fix`；分析未完成、图片无法对齐、证据不足、中置信度差异或比较器失败时 MUST 写入 `inconclusive`。图片差异如果缺少稳定源码修复上下文 MUST 继续作为不可自动修复问题交付，不得伪造修复目标。（D-05、D-06、D-09、D-12，A-04、A-09）

#### Scenario: DOM 与图片区域均明确通过
- **WHEN** 实际节点属性满足全部声明断言，图片区域尺寸可对齐且差异没有超出阈值
- **THEN** 系统输出 `passed`、比较指标和对应证据路径，且不调用视觉兜底

#### Scenario: 视觉范围只声明文本与显隐断言
- **WHEN** 场景声明视觉范围，但没有任何计算样式、几何或图片区域证据
- **THEN** 系统输出 `inconclusive` 并明确证据范围不足，不得使用视觉通过措辞；已声明 Browser 兜底时只返回显式兜底需求

#### Scenario: 计算样式发生子串碰撞
- **WHEN** 视觉范围声明计算样式期望为 `57px`，实际值为 `157px` 或其他只包含期望子串的不同值
- **THEN** 系统按精确样式值输出 `needs-fix`，不得沿用文本包含语义写成通过

#### Scenario: 图片区域没有有效比较像素
- **WHEN** 声明的成对掩码覆盖图片比较区域的全部像素
- **THEN** 系统输出 `inconclusive` 和零有效像素证据，不得以零差异比例写成通过

#### Scenario: 行高或控件中心线超过几何容差
- **WHEN** 场景声明行高固定值，或声明按钮中心线相对输入框中心线的允许偏差，且实际几何超出容差
- **THEN** 系统输出高置信度 `needs-fix`、实际值、期望值与容差；节点或参考几何缺失时改为 `inconclusive`

#### Scenario: 明确视觉差异缺少源码上下文
- **WHEN** 图片区域差异明确超出阈值但配置没有提供可验证的源码锚点和目标值
- **THEN** 系统输出 `needs-fix` 和不可自动修复问题，修复门禁不得允许 AI 将其当作已授权修复候选

#### Scenario: 证据不能形成可靠结论
- **WHEN** 设计图与实际截图无法按声明区域对齐、只存在中置信度差异、分析仍待完成或比较依赖失败
- **THEN** 系统输出 `inconclusive`，不得过滤后写成零问题通过或进入自动修复

#### Scenario: 不确定结果声明了视觉兜底
- **WHEN** 结论为 `inconclusive`，场景已声明 Browser 兜底且当前 AI 工具提供该能力
- **THEN** 调用方可以使用新的运行 ID 显式执行视觉兜底并提交完整结论；没有声明或没有能力时保持 `inconclusive`

### Requirement: 内置 Playwright 必须按平台选择并真实验证运行包
系统 SHALL 从插件随附的按 `platform-arch` 索引运行包中选择唯一匹配项，并 MUST 独立校验固定 Playwright 版本、浏览器 revision、许可和文件摘要。本轮发布物 MUST 覆盖 `darwin-arm64` 与 `linux-x64`；两个平台的支持结论都必须来自真实 Chromium 启动和截图，运行阶段不得联网下载或修改业务项目依赖。其他平台 MUST 明确报告不受支持。（D-08、D-10、D-13，A-07、A-10）

#### Scenario: Apple Silicon Mac 选择匹配运行包
- **WHEN** 当前环境是 `darwin-arm64` 且对应运行包完整
- **THEN** 系统只选择该平台元数据和浏览器资产，真实启动 Chromium 并产生有效截图

#### Scenario: Linux x64 CI 选择匹配运行包
- **WHEN** GitHub Actions 的 Linux x64 Runner 检出完整发布资产并执行统一验证
- **THEN** 系统选择 `linux-x64` 运行包，真实启动 Chromium 并产生截图，浏览器阶段不得以平台不兼容跳过后报告支持通过

#### Scenario: 当前平台没有运行包或摘要变化
- **WHEN** 当前 `platform-arch` 不在索引中、平台资产混装、许可缺失或任一摘要变化
- **THEN** 系统输出不可用原因和 `blocked` 结论，不读取其他平台资产作为回退，也不执行安装命令

### Requirement: 跨工具统一入口必须安全编排验收与复验
系统 SHALL 提供一个不绑定特定 AI 工具或 CI 的 Node.js 入口，统一组织配置检查、采集计划、状态创建、结构化交互、Playwright 证据、确定性判断、报告和相同上下文复验。入口 MUST 默认只预览，只有显式 `--write` 才产生受控运行产物；预览 MUST 在创建产物前执行与正式写入相同的纯就绪校验，只有可执行计划返回 `readyToWrite: true` 和退出码 0，不可执行计划 MUST 返回 `readyToWrite: false`、`blocked` 和退出码 3。正式运行 MUST 输出稳定 JSON 和退出码 `0=passed`、`1=needs-fix`、`2=inconclusive`、`3=blocked`。入口不得启动任意项目命令、自动修改源码、提交推送或回写远程状态。（D-01、D-03、D-07、D-14、D-15，A-11、A-13）

#### Scenario: 默认预览统一验收
- **WHEN** 调用方选择版本 2 受信适配器、可用平台运行包和完整比较规则，但没有传入 `--write`
- **THEN** 入口输出 `readyToWrite: true`、规范化计划、预计产物和运行能力，不创建状态、截图或报告目录

#### Scenario: 复验预览上下文已经变化
- **WHEN** 调用方预览复验，但当前场景指纹、基线状态或实际采集器不满足复验条件
- **THEN** 入口在创建产物前输出 `blocked` 和退出码 3，不得先返回成功计划再把同一事实延迟到 `--write` 拒绝

#### Scenario: 项目适配器内容不是受信内置模板
- **WHEN** 版本 2 配置指向项目内自定义或被修改的 JavaScript 适配器
- **THEN** 采集计划标记其为非受信项目适配器，预览立即输出 `readyToWrite: false`、`blocked` 和退出码 3且不创建产物；统一入口不得动态导入、执行、自动覆盖或提示直接追加 `--write`，只有摘要匹配插件模板的适配器进入内置主路径，且摘要参与场景指纹

#### Scenario: 显式执行统一验收
- **WHEN** 页面已经可访问且调用方以 `--write` 执行有效 Playwright 场景
- **THEN** 入口按固定顺序完成采集、判断、状态和报告，返回与最终结论一致的 JSON 和退出码，不在同一命令中修改业务源码

#### Scenario: 通过统一入口复验历史基线
- **WHEN** 调用方提供合法基线状态并显式执行复验
- **THEN** 入口复用基线场景指纹与实际采集器，输出已关闭、未解决、新增或不确定结果，禁止切换采集器

#### Scenario: 页面、交互或基础设施阻塞
- **WHEN** 页面不可访问、结构化步骤失败、匹配平台运行包不可用或受控产物无法写入
- **THEN** 入口输出 `blocked` 和退出码 3，保留既有完整运行且不尝试启动项目或安装依赖

### Requirement: 真实项目迁移必须保持受信适配器和证据来源
系统 SHALL 在已有版本 2 自定义适配器迁移时保持原文件不被隐式覆盖，并 MUST 要求假登录、接口模拟和固定数据由不含真实凭据的项目自有本地 HTTP(S) 页面环境准备。迁移后 MUST 使用当前受信模板和新的独立场景基线。通过外部代理、样式注入或其他受控方式复现的问题 MUST 标记为受控故障，不能代替真实源码当前态验收；适配器、页面环境和配置问题 MUST NOT 进入业务源码修复候选。（D-02、D-03、D-06、D-08、D-09、D-15，A-01、A-03、A-04、A-06、A-13）

#### Scenario: 项目自有页面环境准备验收状态
- **WHEN** 真实页面需要本地假登录、接口模拟或固定数据才能稳定复现
- **THEN** 项目既有流程或用户明确准备的本地页面环境在受信适配器之外提供这些非敏感事实；配置和适配器不得保存真实 Cookie、Token、密码或动态项目模块

#### Scenario: 迁移版本 2 自定义适配器
- **WHEN** 用户明确授权把已有自定义版本 2 验收配置迁移到统一入口
- **THEN** 调用方保留原文件，外置页面环境职责，复制当前受信模板并建立新的场景指纹与独立基线；没有迁移授权时只输出阻塞原因和迁移清单

#### Scenario: 通过受控方式复现缺陷
- **WHEN** 调用方通过外部代理、样式注入或固定响应构造失败基线
- **THEN** 运行与交付报告明确标记为受控故障，只证明发现与复验机制；同时保留真实源码当前态独立验收，且受控问题与环境问题不进入业务源码修复候选
