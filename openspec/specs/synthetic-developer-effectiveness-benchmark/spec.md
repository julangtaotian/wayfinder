# synthetic-developer-effectiveness-benchmark Specification

## Purpose
为真实前端项目提供安全、可重复且可审计的合成配对基准，在不修改业务仓库的前提下比较插件组与对照组的交付过程，并诚实区分模拟结果、无效样本和真实开发者效果。

## Requirements

### Requirement: 基准必须先固定安全且可重复的项目基线

系统 MUST 默认只预览，并在任何写入或代理执行前校验项目路径、独立 Git 根、分支、40 位提交、工作树状态摘要、运行 ID、模型配置、时间预算、任务规模与输出边界。业务项目已有未提交内容 MUST 被排除在隔离副本之外，且运行前后的分支、提交和状态摘要 MUST 完全一致。持久证据 MUST 使用项目别名和提交标识，不得包含业务项目的开发机绝对路径。

#### Scenario: 合法配置只产生无写入预览
- **WHEN** 用户传入三个可读取项目及完整运行参数，但没有显式写入选项
- **THEN** 系统返回三个项目别名、分支、提交、六个需求、十二次运行和输出相对位置，且不创建工作区、不调用代理、不改变源仓库或既有输出

#### Scenario: 危险或运行期漂移基线失败关闭
- **WHEN** 项目指向文件系统根、用户主目录、非独立 Git 根、非预期提交，或分支、提交、已有工作树状态摘要在运行期间发生变化
- **THEN** 系统以稳定 `code`、`target`、`status` 和真实退出状态阻止受影响阶段，不用人类消息或平台路径作为唯一定位

#### Scenario: 已有未提交内容被排除但保持不变
- **WHEN** 项目开始运行前已有用户未提交内容，但分支、HEAD 和状态摘要能够读取
- **THEN** 系统仅从已提交 HEAD 创建隔离副本，记录未提交内容已排除，并在运行结束后证明源项目状态摘要没有变化

### Requirement: 模拟需求必须在执行前生成、校验并冻结

系统 MUST 为每个项目生成两个不依赖真实账号或生产接口的模拟需求，总计六个用例并覆盖小型、中型和大型复杂度。每个用例 MUST 在任一执行组启动前冻结公开需求、预期工作流路线、受控初始补丁、独立正确实现、已知错误变体、允许命令、澄清答案、隐藏验收器与内容摘要；执行代理只能读取公开需求和按需释放的澄清答案。冻结预检 MUST 证明初始状态和错误变体验收失败、参考实现和独立正确实现验收通过，并拒绝依赖局部变量名、语句顺序、格式或完整参考源码的答案匹配型验收器。完整六用例矩阵 MUST 同时包含可验证的快速路线和完整路线代表样本，且完整路线不能仅由文件数、补丁行数或复杂度标签推断。

#### Scenario: 六个用例通过冻结预检
- **WHEN** 需求生成阶段得到每个项目两个候选，并且所有候选的初始补丁、独立正确实现、错误变体、公开需求、允许命令和隐藏验收器均可在隔离副本执行
- **THEN** 系统只在初始状态与错误变体失败且参考实现与独立正确实现通过后，写入带稳定任务 ID、项目 ID、复杂度、预期路线、质量状态、文件摘要和 SHA-256 的冻结清单
- **AND** 系统在任何配对运行前停止修改这些内容

#### Scenario: 答案匹配型候选不能冻结
- **WHEN** 独立正确实现因变量名、表达式顺序、分号、格式或参考源码文本不同而失败，或者已知错误变体仍然通过
- **THEN** 系统以稳定质量错误拒绝候选并进入有界作者纠正，不得放宽验收、修改正确实现来迎合参考答案或启动配对代理

#### Scenario: 完整矩阵缺少代表路线
- **WHEN** 六用例矩阵缺少快速路线或完整路线，或者完整路线样本只按文件数、补丁行数或复杂度标签声明
- **THEN** 系统在启动代理前以稳定矩阵错误拒绝整轮运行

#### Scenario: smoke 模式校验单例质量
- **WHEN** 用户只预检或执行一个 smoke 用例
- **THEN** 系统不要求该单例同时代表两条路线，但仍要求该用例的初始状态、参考实现、独立正确实现和错误变体通过各自语义门禁

#### Scenario: 不可验收候选不能进入运行
- **WHEN** 候选依赖真实登录、生产写入、远程权限、不受控网络、越界命令、重复任务 ID、空验收器、缺少明确预期路线、缺少独立正确实现或错误变体，或者任一补丁无法重放
- **THEN** 系统替换候选或以稳定阻断状态停止整轮执行，不得通过放宽验收或向代理泄露隐藏实现继续运行

### Requirement: 配对运行必须隔离插件组和对照组

系统 MUST 为同一用例建立两个从相同提交和初始补丁派生的独立工作区，并使用相同模型、推理强度、时间预算、公开需求、澄清预案与验收器。插件组 MUST 记录真实工作流路线。对照组 MUST 使用 Codex 提供的配置忽略、插件关闭与宿主技能发现关闭选项，且 MUST 不调用 frontend-ai-workflow 技能或产生工作流管理产物；基准 MUST 在持久化事件中再次检查插件技能证据并在发现污染时使样本无效。

#### Scenario: 插件组完成工作流准备后开始计时
- **WHEN** 插件组工作区尚未完成项目工作流初始化
- **THEN** 系统先在可复用基线上完成初始化并单独记录准备时长，任务的首次交付与总周期计时从模拟需求正式交给执行代理时开始

#### Scenario: 两组按冻结参数独立执行
- **WHEN** 同一用例的插件组与对照组开始运行
- **THEN** 两组只能访问自己的工作区和公开输入，运行清单记录相同基线与预算、实际启动顺序和不同执行模式，且任一组不能读取另一组的提示、日志、差异或结果
- **AND** baseline 启动参数显式忽略用户配置、关闭插件并跳过宿主技能发现，不复制或记录认证凭据

#### Scenario: baseline 事件暴露插件污染
- **WHEN** baseline 的结构化事件、工具调用或最终消息包含 frontend-ai-workflow 技能名称或调用证据
- **THEN** 系统以稳定污染代码将该运行标记为无效并排除效果比较，不得把污染运行伪装为普通 baseline

#### Scenario: 执行路线与产物不符时样本无效
- **WHEN** 插件组没有与冻结预期相符且可验证的快速或完整路线记录，或对照组产生需求、OpenSpec 等插件工作流产物或调用证据
- **THEN** 系统把该次运行标记为无效并记录稳定原因，不得仍计入效果比较

### Requirement: 执行器必须支持首次交付、澄清和返工循环

系统 MUST 通过非 shell、可注入、可超时和可恢复的执行器保存结构化阶段事件。代理首次提交可验收结果后，独立验收器 MUST 运行；验收失败时只把必要失败反馈返回原会话并计为一次返工，代理提出材料中未回答的问题时只按冻结澄清预案响应并计数。

#### Scenario: 首次验收通过
- **WHEN** 执行代理第一次结束实现且隐藏验收器全部通过
- **THEN** 系统记录一次验收通过、零返工、真实首次交付时长和总周期，并保留验收命令、退出状态、结果摘要与差异统计

#### Scenario: 验收失败后原会话返工
- **WHEN** 第一次或后续验收失败且没有超过冻结返工上限
- **THEN** 系统向同一会话提供经过脱敏的失败反馈，返工次数增加一，再次运行相同隐藏验收器并保留每一轮结果

#### Scenario: 代理请求必要澄清
- **WHEN** 代理明确请求公开需求未回答、但冻结澄清预案已定义的问题
- **THEN** 系统只释放对应答案并继续同一会话，澄清次数增加一；未命中预案的问题不得由编排器临时发明业务规则

#### Scenario: 超时、启动失败或中断
- **WHEN** 子进程无法启动、超过时间预算、返回非零状态或收到终止信号
- **THEN** 系统分别记录启动错误、真实退出码、超时或中断，终止当前子进程，保留已完成证据，并进入有界清理流程

### Requirement: 指标必须保留未知语义和可审计来源

系统 MUST 为每次运行记录首次交付时长、总周期、澄清次数、返工次数、阻断次数、误阻断候选、一次验收结果、最终状态、改动文件与行数、命令退出状态、执行路线和证据描述。无法可靠提取或确实未发生的字段 MUST 为带原因的 `null`，不得用零值或 Git 提交时间推断；首次交付前即阻断的运行在阻断和最终状态证据完整时 MUST 保留为有效失败结果，不能因首次交付为 null 而排除。

#### Scenario: 完整运行形成有效样本
- **WHEN** 运行具有冻结基线、合法路线、开始时间、最终时间、全部适用计数、独立验收或证据完整的阻断结果和完整证据摘要
- **THEN** 系统标记该运行有效，并允许它进入同用例配对比较；已交付运行必须有首次交付时间，首次交付前阻断则以带原因的 null 保存该字段

#### Scenario: 不完整运行保持无效
- **WHEN** 任一必填指标、路线证据、验收结果或持久证据缺失
- **THEN** 系统将缺失字段保留为 `null`，列出数据质量原因并排除该运行及对应不完整配对，不得补零或推断成功

#### Scenario: 误阻断只有确定性反证时自动成立
- **WHEN** 代理报告阻断，且冻结预检或同一未改变环境中的确定性检查证明所需文件、命令或资源当时可用
- **THEN** 系统标记 `false-blocker-confirmed`；只有语义判断或证据冲突时标记 `review-required`，不自动算入确认误阻断率

### Requirement: 证据持久化与清理必须限制在本轮输出根

系统 MUST 把冻结清单、结构化事件、脱敏日志、验收摘要、差异统计、指标和清理结果限制在 `.frontend-ai-workflow/runs/developer-effectiveness-benchmark/<run-id>/`，并将可复用缓存限制在 `.frontend-ai-workflow/cache/`。这些内容默认不进入 Git 或 `outputs/`。成功、阶段失败和进程异常均 MUST 清理本轮工作区；清理失败 MUST 保留原始运行结果并单独报告。

#### Scenario: 持久输出经过脱敏和限长

- **WHEN** 代理、Git 或验收命令输出包含业务绝对路径、令牌、Cookie、密码、私钥或超过大小上限
- **THEN** 系统替换业务路径别名、拒绝保存敏感原文并截断非敏感超长内容，同时记录稳定脱敏或截断状态

#### Scenario: 清理只作用于有界工作区

- **WHEN** 一轮运行成功、失败、超时或中断后开始清理
- **THEN** 系统只删除本轮工作区下已验证的非符号链接目录；越界、根目录、用户主目录或符号链接目标必须失败关闭

#### Scenario: 恢复运行不覆盖既有证据

- **WHEN** 使用同一运行 ID 重启已部分完成的基准
- **THEN** 系统校验冻结清单和既有证据摘要，只继续允许恢复的未完成阶段；内容冲突或已完成输出重写请求必须阻断

### Requirement: 汇总必须明确合成属性与结论门槛

系统 MUST 按项目、复杂度和执行组汇总有效样本、一次验收通过率、平均首次交付时长、平均总周期、平均澄清、平均返工和确认误阻断率，并生成稳定 JSON 与工作簿导入数据。所有输出 MUST 显著标记为合成基准并列出限制。

#### Scenario: 六个配对样本完整时生成相对比较
- **WHEN** 六个用例的插件组和对照组均为有效样本
- **THEN** 系统报告十二次运行和六个有效配对的分组指标、逐用例差异与限制，但不把结果描述为真实开发者或团队生产收益

#### Scenario: 有效配对不足时不形成优劣结论
- **WHEN** 至少一个用例缺少任一执行组的有效样本
- **THEN** 系统展示已采集状态、无效原因和现有描述性指标，并明确 `conclusionStatus=insufficient-pairs`

### Requirement: 跨平台验证必须与本机试点分层

系统 MUST 对路径、临时目录、环境变量、子进程、结构化诊断、超时、中断和清理提供确定性平台回归，并分别记录聚焦测试、本地统一验证和真实五平台 CI 证据。

#### Scenario: Windows 与 POSIX 路径得到一致机器结果
- **WHEN** 回归输入 Git 风格 Windows 路径、Node 风格 Windows 路径、POSIX 路径、尾部分隔符、空格和非 ASCII 目录
- **THEN** 系统对比较双方使用相同目标平台路径语义，生成一致别名和稳定机器字段，不直接启动 Windows `.cmd` 包装器

#### Scenario: 没有真实矩阵证据时只报告本地结果
- **WHEN** 聚焦回归和本地统一验证通过但同一提交的五平台 CI 尚未完成
- **THEN** 系统只声明本地层级通过，并把外部矩阵保持待执行，不得宣称跨平台发布验证完成

### Requirement: 合成基准必须记录 Codex Token 用量与未知语义

系统 MUST 只从 Codex JSONL 的 `turn.completed` 事件读取非负整数 usage 字段，并 MUST 分别记录 input、cached input、output、reasoning output 和可复算 total Token。没有合法 usage 事件时相关指标 MUST 为 `null` 并带数据质量原因，不得用零值、文本长度、时间或账号额度推断。

#### Scenario: 多轮运行包含合法 usage

- **WHEN** 同一执行样本的一个或多个 `turn.completed` 事件提供合法 Token 字段
- **THEN** 系统按字段累计各轮用量并记录具有 usage 的 turn 数
- **AND** total 等于 input 与 output 之和，cached input 和 reasoning output 作为其子维度单独保留

#### Scenario: usage 缺失或非法

- **WHEN** JSONL 没有 `turn.completed.usage`，或字段为负数、非整数、字符串或不可解释结构
- **THEN** 系统把 Token 指标保存为 null 并记录 `missing-token-usage` 或 `invalid-token-usage`
- **AND** 该字段不进入 Token 均值或配对差值，但其他完整指标仍按既有规则判断

### Requirement: Token 汇总必须与效果结论边界一致

系统 MUST 在执行组、项目、复杂度和逐用例配对中汇总有效且具有 Token 证据的样本，并 MUST 将总 Token、input、cached input、output 与 reasoning output 写入 JSON、CSV 和人工复核报告。配对缺少任一侧 Token 时该项差值 MUST 为 `null`；合成 Token 差值不得描述为真实开发者或团队生产收益。

#### Scenario: 有效配对两侧都有 Token

- **WHEN** 同一合成用例的插件组和对照组均有效且具有完整 Token 指标
- **THEN** 系统报告插件组减对照组的 Token 差值和各组平均值
- **AND** 报告继续显著标记 synthetic 与描述性比较限制

#### Scenario: 配对任一侧 Token 未知

- **WHEN** 有效配对中任一侧缺少可靠 Token 证据
- **THEN** 系统保留其他效果指标并把 Token 差值设为 null
- **AND** 系统明确 Token 样本数，不把未知值当 0 拉低平均值

### Requirement: 任务作者重试必须使用有界诊断纠正合同错误

系统 MUST 在任务作者首次尝试时明确补丁、允许路径和可用性检查的一致性合同。候选校验失败且仍有重试额度时，下一次作者输入 MUST 只增加上一次失败的稳定错误代码与可选安全目标，不得注入原始错误正文、日志、绝对路径、凭据或业务源码。系统 MAY 根据实际补丁行确定性重算 hunk 的旧/新声明数量，但 MUST NOT 修改路径、起始行、上下文或增删正文；规范化后的候选 MUST 在冻结前通过既有双向预检。重试次数 MUST 保持有界，达到上限后 MUST 返回最后一次真实失败，不得放宽冻结门禁或启动后续配对运行。

#### Scenario: 首次候选的路径字段不一致

- **WHEN** 候选的业务补丁目标或可用性检查目标没有被 `allowedPaths` 覆盖
- **THEN** 系统以稳定代码和安全目标拒绝候选，并把这两个机器字段加入下一次作者提示
- **AND** 下一次提示继续要求全部业务补丁目标与可用性目标由 `allowedPaths` 覆盖

#### Scenario: 首次候选包含损坏补丁

- **WHEN** 候选的 seed、reference 或 evaluator 不是可按规定顺序应用的完整 unified diff
- **THEN** 系统拒绝候选，并让下一次作者只根据稳定失败代码与安全目标重新生成完整候选
- **AND** 系统不得在编排器内猜测或修补补丁路径、起始行、上下文或增删内容

#### Scenario: hunk 声明数量与正文不一致

- **WHEN** 候选 hunk 的旧/新声明数量与实际上下文、删除和新增行数不一致
- **THEN** 系统只重算并替换这两个数量，保持路径、起始行、可选标题和补丁正文不变
- **AND** 规范化后的候选仍须在冻结前通过 Git 双向应用与独立验收

#### Scenario: 诊断目标为空

- **WHEN** 上一次失败具有稳定错误代码但没有安全目标
- **THEN** 下一次提示只加入错误代码，不生成空目标说明，也不加入原始错误消息

#### Scenario: 重试额度耗尽

- **WHEN** 允许的作者尝试全部失败
- **THEN** 系统返回最后一次真实错误，清理本轮隔离作者工作区，并停止冻结、预检和配对执行

#### Scenario: 插件基线初始化创建当前管理文件

- **WHEN** bootstrap 在隔离副本创建或更新共享合同声明的工作流管理文件
- **THEN** 系统允许这些路径进入插件基线提交，并保持源项目不变
- **AND** 任一共享集合外的业务路径变化仍以稳定错误失败关闭

#### Scenario: reference 验收器发生运行期错误

- **WHEN** reference 状态的独立验收因语法、模块加载、引用、类型或断言错误失败
- **THEN** 系统只把对应固定错误码与用例 ID 交给下一次作者尝试
- **AND** 系统不得把验收输出、stack 或源码片段加入作者提示

#### Scenario: evaluator 检查需要编译的源码

- **WHEN** evaluator 需要观察 `.ts` 或 `.vue` 文件
- **THEN** evaluator 必须保持为 Node 可直接执行的 JavaScript ESM，并以文本级方式观察该源码
- **AND** evaluator 不得把未转换源码直接交给 `eval`、`new Function` 或 `vm`

### Requirement: 完整基准调用必须支持新增运行预算

系统 MUST 允许调用方为一次完整配对基准调用设置正整数新增运行预算。预算只计算本次调用新执行并持久化的 plugin 或 baseline 结果，已存在且被恢复逻辑跳过的结果 MUST NOT 占用预算。未设置预算时，系统 MUST 保持连续执行全部未完成运行的既有行为。

#### Scenario: 单次预算到达

- **WHEN** 调用方设置新增运行预算为 1 且仍有多个未完成运行
- **THEN** 系统最多新增一条运行结果，清理本次受管工作区并返回稳定暂停状态
- **AND** 系统不得生成完整实验结论或失败占位

#### Scenario: 恢复暂停的运行

- **WHEN** 同一冻结实验再次以新增运行预算 1 调用
- **THEN** 系统跳过已有结果且不消耗预算，并按固定顺序执行下一条未完成运行
- **AND** 调整调用级预算不得改变冻结输入摘要

#### Scenario: 所有运行已经完成

- **WHEN** 恢复调用发现固定矩阵的所有结果均已持久化
- **THEN** 系统生成完整汇总并进入既有完成状态

#### Scenario: 新增运行预算非法

- **WHEN** 调用方提供零、负数、非整数或缺失的预算值
- **THEN** 系统在启动代理前以稳定参数错误拒绝调用
