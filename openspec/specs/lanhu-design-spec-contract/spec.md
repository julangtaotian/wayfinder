# 蓝湖设计规范契约

## Purpose

定义蓝湖事实来源、Markdown 结构、组件视觉值、技术栈边界和本地图标资产的可追溯交付要求，使未接触原始画板的 AI 和研发人员都能稳定读取、实现、复核并定位每项规范的来源与适用边界。

## Requirements

### Requirement: 蓝湖设计事实必须可追溯

系统 SHALL 以蓝湖 33 张原始画板和标注面板作为设计事实源，并在每个关键颜色、尺寸、间距、圆角、边框、字体或布局值旁标明“蓝湖标注”“画板实测”或“研发补充”。

#### Scenario: 记录标注面板中的精确值

- **WHEN** 蓝湖标注面板提供明确数值和单位
- **THEN** Markdown 必须原样记录该值并标记为“蓝湖标注”

#### Scenario: 记录从画板测量的值

- **WHEN** 蓝湖没有文字标注但可从 Web `@1x` 画板测量
- **THEN** Markdown 必须记录测量对象、近似值和“画板实测”来源，不得表述为精确标注

#### Scenario: 记录研发行为

- **WHEN** 静态画板无法定义键盘、异步、错误恢复或可访问性行为
- **THEN** Markdown 必须将规则放入“研发补充”，不得标记为蓝湖设计事实

### Requirement: 裸占位符必须被消除

系统 MUST 清除规范正文和表格中含义不明的 `—`、可确认却未补齐的“未标注”和把源设计“待定”当实现结论的描述。

#### Scenario: 缺失值可从蓝湖确认

- **WHEN** 裸占位符对应的值可从蓝湖标注或画板几何确认
- **THEN** 系统必须写入明确数值、单位和来源等级

#### Scenario: 字段对组件不适用

- **WHEN** 某个字段对当前组件没有意义
- **THEN** 系统必须写“无/不适用”及具体原因，而不是横线

#### Scenario: 蓝湖源没有定义

- **WHEN** 蓝湖画板本身没有给出视觉或交互规则
- **THEN** 系统必须写“蓝湖未定义”、缺失内容和是否阻断完全还原，不得自行推算为设计事实

### Requirement: Markdown 清单和场景必须完整

系统 SHALL 维护 1 个索引、30 份详细规范、26 份组件类规范、45 张蓝湖画板映射和 183 条唯一组件画板场景，并使每条组件场景映射到可见内容、样式/状态或研发补充；新增响应式表单布局属于基础规范，不得伪造额外 `SCN-*`。

#### Scenario: 检查全量文档

- **WHEN** 运行文档契约测试
- **THEN** 测试必须确认 31 个 Markdown 文件、30 份详细规范和 45 张画板映射均存在且本地链接有效

#### Scenario: 检查全量组件场景

- **WHEN** 运行场景映射测试
- **THEN** 测试必须确认 26 份组件类规范共有 183 条唯一场景，且每条场景都有可观察说明

#### Scenario: 合并文档对应多张画板

- **WHEN** 辅助色、日期时间选择器、Table 或响应式表单布局的同一 Markdown 对应多张蓝湖画板
- **THEN** 索引和文档必须保留每张画板的独立名称与内容边界，视觉验证不得少算画板

#### Scenario: Table 源画板包含重复示例

- **WHEN** Table 基础画板以相同内容重复展示“自定义索引”
- **THEN** 文档必须只建立一条可执行规范场景，并明确记录源画板重复，不得伪造第二种状态

### Requirement: 规范必须可被机器稳定读取

系统 SHALL 使用稳定标题、表头、单位和来源词汇，使未见过蓝湖的 AI 能从 Markdown 区分元数据、组件结构、视觉规则、图标资产、画板场景、必要状态、蓝湖未定义项和实现边界。

#### Scenario: AI 解析详细规范

- **WHEN** AI 仅读取任一详细规范
- **THEN** AI 必须能定位来源画板、组件组成、关键尺寸/样式、图标资产、场景列表、必要状态和实现边界

#### Scenario: 解析显式色值和尺寸

- **WHEN** 自动测试扫描 HEX、像素尺寸和组合尺寸
- **THEN** 所有显式值必须使用稳定格式并能关联到来源等级

#### Scenario: 文档内部出现矛盾

- **WHEN** 表格值与正文说明不一致
- **THEN** 文档契约测试必须失败并指出文件和冲突内容

### Requirement: 蓝湖未定义场景必须有研发补充边界

系统 SHALL 保留 `Select` 自定义模板、筛选选项和远程搜索三个源设计未定义场景，并提供不冒充蓝湖事实的可见 UI 补充。

#### Scenario: 自定义模板

- **WHEN** AI 实现自定义选项模板场景
- **THEN** 文档必须说明可见信息结构、选中反馈、禁用规则和可访问名称，同时标明蓝湖未定义的部分

#### Scenario: 本地筛选

- **WHEN** AI 实现筛选选项场景
- **THEN** 文档必须说明输入、匹配结果、无结果、清空和保留已选值的行为边界

#### Scenario: 远程搜索

- **WHEN** AI 实现远程搜索场景
- **THEN** 文档必须说明输入、加载、空结果、失败、已选值和恢复后的可见 UI；请求频率、过期响应和接口算法不作为通用视觉规范

### Requirement: 已知组件必须描述可执行的视觉结构

系统 SHALL 为每个已知组件记录组成区域、顺序、包含关系、显式尺寸、颜色、字体、间距、边框、圆角、阴影、文案、初始状态和必要交互状态；对不适用字段必须给出原因。

#### Scenario: AI 读取组件结构

- **WHEN** AI 读取任一组件规范
- **THEN** AI 必须能区分组件外框、内容区、标签/文本、前后缀、操作区、状态反馈和弹出层等适用组成区域

#### Scenario: 组件存在多种尺寸

- **WHEN** 蓝湖展示 Large、Default、Small 或其他尺寸变体
- **THEN** 文档必须分别记录控件高度、内部间距、文字规格、图标规格和适用场景，不得只写尺寸名称

#### Scenario: 组件存在必要交互状态

- **WHEN** 蓝湖或规范明确 Default、Hover、Focus、Active、Selected、Disabled、Loading、Empty、Error 或展开/收起状态
- **THEN** 文档必须记录触发条件和发生变化的可见属性，不得要求 AI 从组件库默认主题推断

### Requirement: 规范必须保持技术栈无关

系统 MUST 只约束最终 UI 结构和可见结果，不得把 Element、Element Plus 或其他框架/组件库的组件名、属性名、事件名和主题变量写成唯一实现方式。

#### Scenario: 目标项目已有组件库

- **WHEN** AI 在已有 PC 项目中应用规范
- **THEN** AI 可以复用项目组件库，并必须覆盖与规范冲突的默认尺寸、颜色、图标和状态样式

#### Scenario: 目标项目没有合适组件

- **WHEN** 现有组件库无法表达规范中的结构或状态
- **THEN** AI 可以包装、扩展或自行实现组件，但最终视觉仍必须满足同一规范

#### Scenario: 文档提供实现建议

- **WHEN** 某个组件需要说明常见实现方式
- **THEN** 建议必须标记为“非强制实现建议”，不能替代设计事实和可观察验收值

### Requirement: 图标必须作为本地可替换资产交付

系统 MUST 将蓝湖中用于组件操作或状态表达的图标优先下载/导出为本地 SVG；无法取得矢量时 SHALL 保存最高可用清晰度 PNG，并在对应 Markdown 中建立有效引用。

#### Scenario: 记录图标资产

- **WHEN** 组件包含前缀、后缀、清空、展开、翻页、上传、关闭、状态或其他图标
- **THEN** 文档必须记录图标语义、本地相对路径、画布/显示尺寸、默认颜色、适用状态和来源等级

#### Scenario: AI 使用项目图标库替换

- **WHEN** 目标项目已有语义相同的图标
- **THEN** 只有在视口尺寸、线宽、颜色、对齐和状态变化满足文档边界时才允许替换，并应优先使用本地设计资产

#### Scenario: 蓝湖无法提供独立图标文件

- **WHEN** 图标只存在于栅格画板且无法可靠分离
- **THEN** 文档必须写“蓝湖未提供独立资产”、可见尺寸和替换边界，不得伪造矢量路径或保留失效链接

### Requirement: PC 端响应式表单布局必须可执行

系统 MUST 在独立基础规范中完整记录“后台适配规范”12 张画板，并以视口宽度、右侧内容区几何、列数、间距、拉伸和降级边界表达 AI 可直接执行的 PC 端表单布局规则。

本要求实现 `D-19`，并由 `A-09` 验证。

#### Scenario: 视口处于三列区间

- **WHEN** PC 视口宽度在 `1024px～1439px`
- **THEN** 右侧表单字段组必须按 3 个等宽列排列，并以 `8px` 作为字段列间距

#### Scenario: 视口处于四列区间

- **WHEN** PC 视口宽度在 `1440px～1919px`
- **THEN** 右侧表单字段组必须按 4 个等宽列排列，并以 `8px` 作为字段列间距

#### Scenario: 视口处于六列区间

- **WHEN** PC 视口宽度不小于 `1920px`
- **THEN** 右侧表单字段组必须按 6 个等宽列排列，并以 `8px` 作为字段列间距

#### Scenario: 中间参考分辨率只拉伸列宽

- **WHEN** 视口为 `1200px` 或 `2560px`
- **THEN** 系统必须分别保持 3 列或 6 列并自动拉伸可用列宽，不得把这两个参考画板误判为新的列数断点

#### Scenario: 还原右侧工作区壳层

- **WHEN** AI 还原 `1024px × 768px` 参考画板的固定后台壳层
- **THEN** 右侧工作区必须记录并采用 `x=124px`、`y=48px`、`884px × 704px`、背景 `#FAFBFC`、圆角 `4px`，页面底色为 `#EEF1F5`，同时保留设计标注的 `16px` 边界节奏

#### Scenario: 操作组遇到空间不足

- **WHEN** 查询、重置、展开或收起操作组无法完整放入当前可用位置
- **THEN** 操作组必须整体换到下一可用位置，不得拆分按钮、压缩文字、截断图标或造成横向越界

#### Scenario: 视口小于蓝湖最小基准

- **WHEN** PC 视口宽度小于 `1024px`
- **THEN** 文档必须明确蓝湖未定义该范围，并要求目标项目选择最小宽度或项目级降级策略，不得把推测的 1 列或 2 列写成蓝湖设计事实

#### Scenario: 源规则出现 1400 与 1440 冲突

- **WHEN** AI 读取规则总览中的“1400 状态 4 等分”
- **THEN** 文档必须同时记录同页 `1440` 规则和 `1440` 原始画板证据，并将可执行断点归一为 `1440px`

### Requirement: 响应式布局规范必须吸收还原修正并使用可读画板名称

系统 MUST 将真实项目还原确认的通用 UI 约束写入正式响应式规范，并在响应式正文与 README 公共索引中以原始尺寸、列数和状态或用途命名 12 张参考画板，不得要求 AI 解释 `copy / copy 2` 等源文件名。

本要求实现 `D-21`，并由 `A-11` 验证。

#### Scenario: 真实还原修正进入正式规范

- **WHEN** AI 读取响应式表单布局规范
- **THEN** 文档必须明确字段控件占满等分列、主操作使用 `#FF6014`、组件库默认主题不得覆盖规范、操作组不可拆分且页面不得横向越界

#### Scenario: 画板展示名直接表达布局含义

- **WHEN** AI 或研发读取正文中的 12 张画板映射或 README 画板索引
- **THEN** 每张画板展示名必须包含原始尺寸和列数或用途，同尺寸同列数画板必须再以基础、空数据或数据状态区分，两个索引区均不得出现 `copy` 或 `copy 2`

#### Scenario: README 与正文名称保持一致

- **WHEN** AI 从 README 定位响应式表单布局规范
- **THEN** README 第 34～45 行的 12 个画板名称与正文映射中的规范化名称必须集合相同且顺序一致

#### Scenario: 可读命名不破坏追溯

- **WHEN** 画板展示名从蓝湖源命名迁移为可读名称
- **THEN** 文档路径、README 链接、画板数量和 12 个稳定画板 ID 必须保持不变

#### Scenario: 验证专用实现不得进入通用规范

- **WHEN** 双组件库验证使用 iframe、组件库类名、截图路径或其他测试设施
- **THEN** 正式响应式规范不得把这些实现细节写成通用 UI 要求

### Requirement: 纯 AI 输入目录必须包含响应式表单布局规范

系统 MUST 根据 `D-23` 将 D-19 至 D-22 已验收的响应式表单布局规则同步到纯 AI 输入目录，并由 `A-13` 验证规范完整性、README 可发现性和输入纯净边界。

#### Scenario: AI 从纯输入目录定位响应式规范

- **WHEN** AI 只读取 `outputs/lanhu-ai-ui-spec/`
- **THEN** README 必须直接链接 `foundations/responsive-form-layout.md`，并将其计入基础规范、详细规范和 Markdown 文件总数

#### Scenario: 纯 AI 文档保留全部可执行规则

- **WHEN** AI 读取纯输入版响应式表单布局
- **THEN** 文档必须完整包含 3/4/6 列断点、`16px / 8px`、工作区壳层、左侧标签、约 `12px` 标签间距、操作组、12 张画板映射和 `<1024px` 未定义边界

#### Scenario: 纯 AI 文档不携带验证过程

- **WHEN** 同步正式规范到纯 AI 输入目录
- **THEN** 目标文档不得包含蓝湖设计源外链、还原状态、验收环境、截图、证据路径或双组件库验证过程

#### Scenario: 纯 AI 文档本地引用可解析

- **WHEN** 自动检查纯 AI README 和响应式文档中的本地 Markdown 链接
- **THEN** 每个相对链接必须解析到 `lanhu-ai-ui-spec` 目录内的现有文件

### Requirement: 精简 AI 规范必须成为唯一活动蓝湖交付

系统 MUST 仅将 `outputs/lanhu-ai-ui-spec/` 作为当前仓库的活动蓝湖 AI 输入合同；该目录 MUST 保留可执行 Markdown、本地必要资产和可解析索引，但 MUST NOT 包含历史验证工程、组件库构建产物、原始批量截图或三方对比矩阵。（D-01、D-02；A-01）

#### Scenario: AI 读取蓝湖规范

- **WHEN** AI 需要使用后台 UI 规则
- **THEN** 它 MUST 能仅通过 `outputs/lanhu-ai-ui-spec/` 定位规范、场景和本地引用，不读取已退役目录

#### Scenario: 仓库执行蓝湖规范检查

- **WHEN** 聚焦测试验证精简规范
- **THEN** 测试 MUST 检查 Markdown 索引、场景唯一性和本地引用，不要求历史截图或双组件库工程存在

### Requirement: 精确视觉事实必须只写入精简 AI 规范

后续经正式需求确认且影响真实 UI 的尺寸、间距、颜色、文案、初始状态、面板结构和图标显示值 MUST 直接写入精简 AI 规范，并 MUST 保持技术栈无关；验证外壳、组件库 DOM、截图位置和内部算法 MUST NOT 进入规范。（D-02；A-01）

#### Scenario: 新确认可见精确值

- **WHEN** 后续需求确认一个可见 UI 参数且当前规范尚未记录
- **THEN** 对应 AI Markdown MUST 写入数值、适用场景和事实来源，不再维护第二份镜像目录

#### Scenario: 参数只服务验证实现

- **WHEN** 参数只控制测试设施、证据采集或组件库适配
- **THEN** 系统 MUST NOT 把该参数写入通用 AI 规范
