## Requirements
### Requirement: 需求必须包含可追溯决策台账
工作流在新建或修订受管需求时 MUST 在同一 `REQ-*.md` 中维护“决策台账”。每条决策 MUST 使用唯一的 `D-<两位或更多数字>` ID，并包含决策项、状态、取值和来源。状态 MUST 是“已确认”“项目默认”“暂定”或“待确认”之一。

#### Scenario: 原始描述包含未决业务行为
- **WHEN** 原始描述没有定义关闭语义、权限、接口、输入规则、持久化、兼容范围或其他用户可见边界
- **THEN** 工作流 MUST 将该项记为“待确认”或带来源的“暂定”，且 MUST NOT 将其写成已确认事实

#### Scenario: 使用项目默认策略
- **WHEN** 工作流采用项目规则或有源码证据的默认策略
- **THEN** 决策台账 MUST 标记为“项目默认”，并记录规则或源码来源

### Requirement: 验收标准必须映射验证证据
工作流 MUST 给每条可验收标准分配唯一的 `A-<两位或更多数字>` ID，并在需求内的“验收—证据映射”中记录关联决策、验证方式、证据位置与预期断言。验收标准与映射 MUST 一一对应。

#### Scenario: 字段错误文案属于验收行为
- **WHEN** 需求要求非法输入显示指定错误文案
- **THEN** 映射 MUST 指向验证该可见文案的自动断言或明确人工检查，而不能只记录“未进入成功流程”

#### Scenario: 无法自动验证的兼容边界
- **WHEN** 验收项依赖设备、浏览器或视觉布局
- **THEN** 映射 MUST 标记人工验证，并记录目标视口、环境或检查结果

### Requirement: 拆分文档和任务只能使用可实施决策
规格、设计和任务 MUST 以 `D-*` 与 `A-*` 引用需求事实。`tasks.md` MUST NOT 引用“暂定”或“待确认”的 `D-*`；未确认决策必须先回到需求确认，而不能生成实现任务。

#### Scenario: 任务引用待确认关闭行为
- **WHEN** 实施任务引用状态为“待确认”的关闭语义决策
- **THEN** 校验 MUST 失败并说明该决策需要确认，不得继续把它当作实现要求

#### Scenario: 拆分文档引入未知决策
- **WHEN** 任务引用需求台账中不存在的 `D-*`
- **THEN** 校验 MUST 失败并指出未知 ID，要求先补充或修订需求事实源

### Requirement: 需求决策校验必须可重复执行
插件 MUST 提供不依赖第三方包的命令行校验器，输出稳定的机器可读结果和中文错误信息。它 MUST 校验需求台账、验收—证据映射以及可选变更任务对决策的引用。

#### Scenario: 有效需求和任务
- **WHEN** 需求的表、ID、状态、验收映射与任务引用均有效
- **THEN** 校验器 MUST 返回成功，并输出解析后的决策与验收数量

#### Scenario: 需求结构不完整
- **WHEN** 需求缺失决策台账、验收映射、来源、断言结果或对应验收 ID
- **THEN** 校验器 MUST 返回失败和中文结构错误，不得静默跳过
