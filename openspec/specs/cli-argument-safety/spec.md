# cli-argument-safety Specification

## Purpose
为插件的项目识别、初始化、检查、升级和迁移命令提供一致的参数边界，确保无效输入在读取或修改目标项目之前安全失败，同时保持所有合法调用兼容。
## Requirements
### Requirement: 合法 CLI 参数保持兼容
五个受影响入口 MUST 继续接受各自已经声明的值型和布尔型参数，并保持默认目标目录、默认 dry-run、退出状态和机器可读输出字段的现有语义。（D-01、D-03；A-01）

#### Scenario: 使用显式目标目录
- **WHEN** 调用方为受影响入口传入 `--target` 和有效目录，并按入口需要传入合法布尔选项
- **THEN** 系统按照该入口当前行为处理目标目录，且不得因安全加固改变现有 JSON 字段或默认写入语义

#### Scenario: 使用默认目标目录
- **WHEN** 调用方不传入 `--target`
- **THEN** 系统继续使用当前工作目录作为默认目标，并保持写入仍需显式授权

### Requirement: 无效 CLI 参数必须明确失败
五个受影响入口 MUST 拒绝未知参数；值型参数缺少值、值为空或后继令牌是另一个 `--` 选项时，也 MUST 以非零状态和中文错误立即失败。（D-01、D-02；A-02）

#### Scenario: 传入未知参数
- **WHEN** 调用方传入入口没有声明的选项
- **THEN** 系统返回非零状态并指出不支持的参数

#### Scenario: 目标参数没有值
- **WHEN** 调用方传入末尾 `--target` 或空字符串目标值
- **THEN** 系统返回非零状态并指出 `--target` 缺少值

#### Scenario: 目标参数后紧跟另一选项
- **WHEN** 调用方传入 `--target --write` 或同类选项令牌组合
- **THEN** 系统把它视为目标值缺失，而不是当前目录回退、目标路径或后续写入授权

### Requirement: 参数失败不得产生项目副作用
参数解析 MUST 在项目识别、范围扫描、规划引擎调用和文件写入之前完成；任何参数错误都不得创建、更新、迁移或删除目标项目文件。（D-02、D-03；A-02）

#### Scenario: 写入选项与无效参数同时出现
- **WHEN** 初始化、升级或迁移入口同时收到写入选项和任一无效参数
- **THEN** 系统在进入项目逻辑前失败，目标目录内容保持不变

#### Scenario: 只读入口收到无效参数
- **WHEN** 项目识别或健康检查入口收到无效参数
- **THEN** 系统不得把缺失目标回退为当前目录，也不得返回一次看似成功的项目检查结果
