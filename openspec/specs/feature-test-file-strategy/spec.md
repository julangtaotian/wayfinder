## Requirements

### Requirement: 新功能测试文件必须按职责选择

工作流在编写需求、规划变更、形成测试方案或实施新功能时，MUST 区分“复用测试模式”和“复用测试文件”。它 MUST 优先在同一功能的手写专用测试中追加场景；不存在该文件且功能包含页面交互、表单状态或关键业务流程时，MUST 在项目既有测试目录中创建名称表达功能职责的专用测试文件。独立测试入口 MUST 在 `test-plan.md` 中记录该选择、Git 基线和稳定测试定位，并 MUST 在重复实施时避免添加同一 TC。（D-07、D-08；A-03、A-04、A-07）

#### Scenario: 已有同一功能的手写专用测试

- **WHEN** 工作流发现覆盖同一功能的手写专用测试文件
- **THEN** 它 MUST 在该文件中追加新场景，并复用项目既有的测试工具、mock 与断言模式

#### Scenario: 新增独立页面交互

- **WHEN** 页面新增表单、弹窗或关键业务交互，且不存在同一功能的手写专用测试
- **THEN** 工作流 MUST 创建模块内命名清晰的专用测试文件，并覆盖该交互的主流程和必要边界

#### Scenario: 重复实现同一测试方案

- **WHEN** 独立测试入口再次实施已经具有稳定测试定位的 TC
- **THEN** 工作流 MUST 识别既有实现并保持文件不变，不得重复添加测试标题、断言或专用文件

### Requirement: 通用生成测试不得默认承载新功能

文件名包含 `.generated.spec.` 的测试 MUST 被视为通用生成测试基线。需求、变更规划、测试方案和测试实现 MUST 将其仅用于理解既有覆盖与测试风格，且 MUST NOT 默认把新功能场景追加到其中。只有项目自定义规则明确允许时，才可例外；例外 MUST 在需求与测试方案中记录依据，并在实施阶段再次校验。（D-06、D-07；A-03、A-04）

#### Scenario: 只有路径相近的生成测试

- **WHEN** 与受影响页面路径最接近的现有测试是 `.generated.spec.*`
- **THEN** 工作流 MUST 为新功能选择或创建专用测试文件，而不是把该生成测试作为新场景的目标

#### Scenario: 项目规则允许例外

- **WHEN** 项目受管规则明确要求修改某个生成测试文件
- **THEN** 工作流 MAY 按该规则执行，并 MUST 在测试文件策略与测试方案中记录规则来源和例外理由

#### Scenario: 测试方案未经授权指向生成测试

- **WHEN** plan 或 implement 校验发现自动 TC 的目标包含 `.generated.spec.` 且没有项目规则依据
- **THEN** 校验 MUST 返回非零并阻止测试实现，不得静默改写目标路径

### Requirement: 需求必须记录测试文件策略

需求文档 MUST 在“测试与验证”中记录测试文件策略，包含新建或复用的决定、目标文件路径、Git 基线和选择理由。活动变更采用独立测试方案时，需求或变更元数据 MUST 明确该方案为必需，并由 `test-plan.md` 记录逐用例目标。变更实施前 MUST 复核该策略；策略与项目实际测试结构冲突时，MUST 先修订需求、规划或测试方案，不得静默改变测试落点。（D-02、D-04、D-06、D-07；A-02、A-03、A-04）

#### Scenario: 编写新功能需求

- **WHEN** 工作流为新功能生成或修订需求文档
- **THEN** 文档 MUST 写明测试文件策略及其目标路径、Git 基线和理由

#### Scenario: 活动变更采用独立测试方案

- **WHEN** 用户为已确认需求和活动变更持久化 TC 用例
- **THEN** 变更 MUST 明确要求 `test-plan.md`，且方案中的测试目标不得与需求测试文件策略冲突

#### Scenario: 实施时发现策略不合适

- **WHEN** 实施前发现需求或测试方案将新功能测试指向通用生成测试或不存在的错误位置
- **THEN** 工作流 MUST 先将策略修订为符合项目实际结构的专用测试方案，再实施测试

### Requirement: 验证范围必须按影响面选择
工作流 MUST 将聚焦测试作为局部页面、组件、表单或独立业务交互的默认自动验证。全量测试或 coverage 仅在请求层、鉴权、路由、构建、共享组件或共享状态受影响，缺少可用聚焦测试，用户明确要求，或需求中记录了发布级理由时运行。需求文档 MUST 记录验证范围、将执行的命令和选择理由。

#### Scenario: 局部页面交互完成
- **WHEN** 改动仅影响页面内部交互且存在对应专用测试
- **THEN** 工作流 MUST 运行该专用测试和必要构建，且 MUST NOT 因最终交付自动执行全量测试或 coverage

#### Scenario: 公共边界受影响
- **WHEN** 改动影响请求层、鉴权、路由、构建、共享组件或共享状态
- **THEN** 工作流 MUST 在需求或变更计划中记录公共影响，并运行与该影响相称的全量测试或 coverage

#### Scenario: 明确升级验证范围
- **WHEN** 用户要求全量验证、没有可用聚焦测试，或需求记录了发布级理由
- **THEN** 工作流 MAY 执行全量测试或 coverage，并 MUST 报告触发原因和与本次需求无关的既有失败或网络噪声
