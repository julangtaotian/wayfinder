# feature-test-file-strategy Specification

## Purpose
定义显式测试实现对项目既有文件、生成基线和重复执行的保护，确保新增测试遵循项目原生布局、不会污染生成文件，并能在重复执行时保持稳定。

## Requirements

### Requirement: 测试实现必须区分模式复用与文件复用

系统 MUST 优先在同功能手写专用测试中追加场景；没有同类文件时，MAY 在项目既有测试目录创建职责明确的专用测试。通用共享测试、聚合套件或仅框架相同的文件不得被视为同功能文件。

#### Scenario: 已有同功能手写测试
- **WHEN** 最近测试覆盖相同模块和用户行为
- **THEN** 系统在该文件增加最小场景并遵循现有 fixture、mock 与断言模式

#### Scenario: 只有共享聚合测试
- **WHEN** 现有文件只覆盖通用设施或多个无关功能
- **THEN** 系统创建命名明确的专用测试，而不是扩大共享文件职责

### Requirement: 生成测试默认只读

名称或内容表明由工具生成的测试文件 MUST 作为只读基线。除非用户明确要求修改生成源并授权重新生成，系统 MUST NOT 直接编辑生成文件。

#### Scenario: 生成基线已覆盖目标
- **WHEN** 生成测试可用于观察回归但不是手写所有者文件
- **THEN** 系统保留该文件并在手写专用测试中补充缺口

### Requirement: 重复实施不得复制同一场景

系统 MUST 根据测试标题、套件上下文和可观察断言识别已存在场景。再次执行同一请求时 MUST 更新必要断言或保持无变更，不得追加重复用例。

#### Scenario: 同一测试请求再次执行
- **WHEN** 目标文件已经包含等价场景
- **THEN** 系统不新增重复测试，并报告现有定位
