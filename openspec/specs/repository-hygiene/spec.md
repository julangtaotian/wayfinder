# repository-hygiene Specification

## Purpose
为仓库定义可重复验证的提交边界，使本机、敏感和可重建文件不会误入远程仓库，同时保护插件离线运行时与持久验收证据的完整交付。

## Requirements

### Requirement: 仓库必须过滤本机敏感与可重建文件

系统 MUST 忽略环境变量文件、操作系统元数据、未共享的编辑器目录、交换或备份文件、临时文件、普通依赖目录、包管理器与构建缓存、日志、覆盖率以及通用测试报告；系统 MUST 允许公开环境模板被版本控制。持久 outputs、发布物和验收证据 MUST 由仓库体积预算显式允许，不得通过宽泛忽略规则吞掉，也不得因为历史上已跟踪而无限增长。（D-01、D-06；A-01、A-03）

#### Scenario: 开发者生成本地环境和缓存文件

- **WHEN** 工作区出现 `.env.local`、编辑器交换文件、包管理器缓存、测试结果或 Playwright 报告
- **THEN** Git 将这些路径标记为已忽略，不把它们列为候选提交

#### Scenario: 开发者提供公开环境模板

- **WHEN** 工作区存在 `.env.example` 或带环境名的 `.env.*.example`
- **THEN** 最终忽略规则允许这些公开模板进入版本控制

#### Scenario: 仓库包含有意交付的构建内容

- **WHEN** 离线运行时、受管 outputs 或验收证据包含有意交付的生成内容
- **THEN** 系统不以通用规则误排该内容，但体积审计 MUST 按受控路径与预算决定是否允许提交

### Requirement: 内置运行时必须区分生产内容与可重建内容

系统 MUST 在普通 `node_modules/` 被忽略后显式允许 OpenSpec 与 Playwright 内置生产依赖被版本控制，并 MUST 再次忽略两套运行时的 `.bin/`、系统元数据和缓存；已经受跟踪但不参与运行时入口或完整性校验的 `.bin` 链接 MUST 从仓库移除，锁文件、许可证、完整性清单与 LFS 平台资产 MUST 保持可提交。（D-01、D-05；A-02、A-03）

#### Scenario: 内置运行时增加生产包文件

- **WHEN** 受控升级在 OpenSpec 或 Playwright 内置 `node_modules` 中增加生产包、许可证或锁文件
- **THEN** Git 允许这些运行时交付文件进入候选提交并由完整性检查核验

#### Scenario: 包安装生成命令链接或缓存

- **WHEN** 内置运行时目录出现 `node_modules/.bin/`、`.DS_Store` 或缓存内容
- **THEN** Git 忽略这些可重建或本机专属文件

#### Scenario: 可重建命令链接已经受 Git 跟踪

- **WHEN** 索引复核发现 OpenSpec `.bin/node-which` 或 `.bin/yaml` 仍受跟踪
- **THEN** 系统移除这些链接且保持目标生产包、运行时入口和完整性检查有效

#### Scenario: 平台浏览器资产由 LFS 管理

- **WHEN** Playwright 的受支持平台资产被检查或更新
- **THEN** 路径继续由 Git LFS 规则管理且不被提交过滤排除

### Requirement: 提交过滤边界必须受到自动回归保护

系统 MUST 使用仓库专用自动测试验证忽略样例、反忽略样例和关键已跟踪路径；测试 MUST 读取真实 Git 忽略语义、保持只读，并在规则漏排或误排时返回非零状态和具体路径。（D-06、D-07、D-10；A-01、A-02、A-03、A-04、A-05）

#### Scenario: 提交过滤规则符合合同

- **WHEN** 开发者运行仓库卫生专用测试或根级全量测试
- **THEN** 所有应忽略、应保留和应持续跟踪的样例均通过，测试不创建持久垃圾文件

#### Scenario: 关键交付路径被新规则误排

- **WHEN** 某条规则导致运行时生产文件、LFS 平台资产、验收证据、需求、规格或归档变更不可提交
- **THEN** 专用测试失败并指出误排路径

#### Scenario: 当前跟踪集合接受规则升级

- **WHEN** 新忽略规则应用到已有仓库
- **THEN** 除两个明确移除的可重建 `.bin` 链接外，当前生产运行时和持久交付路径仍在 Git 索引中

### Requirement: 平台资产必须支持按目标检出且保持完整性

Git LFS MUST 继续保存五个受支持平台的规范浏览器源；开发环境和 CI MAY 只检出当前目标平台目录，但平台完整性、冒烟和打包 MUST 要求该目标的真实文件存在。LFS 指针文本、缺失文件或其他平台资产 MUST NOT 被当作目标平台已准备。（D-09、D-10、D-11、D-13；A-04、A-08）

#### Scenario: CI 准备矩阵目标平台

- **WHEN** 矩阵任务声明一个受支持平台
- **THEN** 检出流程 MUST 只拉取该平台资产，后续统一验证与打包 MUST 使用真实目标文件执行

#### Scenario: 目标资产仍是 LFS 指针

- **WHEN** 完整性、冒烟或打包读取到 LFS 指针而不是真实浏览器文件
- **THEN** 命令 MUST 以稳定 code 和目标路径失败，不得跳过或回退其他平台

#### Scenario: 开发者使用轻量克隆

- **WHEN** 开发者跳过默认 LFS smudge 并选择当前平台
- **THEN** 文档化流程 SHALL 只获取目标平台且不修改远端规范源，其他平台任务仍明确不可执行
