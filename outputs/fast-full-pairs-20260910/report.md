# 快速流程与完整流程三组配对复验

结论：第三项已完成。三个明确、局部、可聚焦验证的任务共执行 6 个主样本；快速与完整流程的最终功能质量均为 10/10，隐藏验收 6/6 通过，隐藏验收后外部返工均为 0。对于这类任务，快速流程没有牺牲质量，而完整流程平均消耗 4.67 倍未缓存输入 Token、4.23 倍耗时、5.60 倍命令和 22.12 倍工具输出。

## 配对条件

- 当前安装 build：`0.18.0+codex.20260910061812`。
- 模型与推理：`gpt-5.6-terra / medium`。
- 三组任务：搜索关键词归一化、状态文案兜底、分页窗口边界。
- 每组快速与完整工作区拥有相同 Git 树；隐藏测试在模型完成后注入，模型不可见。
- 质量满分 10：隐藏验收 5、可见验证 1、写入范围 1.5、保护文件 1、路由合同 1、报告真实性 0.5。
- 隐藏验收失败时最多追加一次外部返工；实际 6 个样本首次隐藏验收全部通过，没有启动追加调用。
- 顺序交替为快→全、全→快、快→全，降低固定先后顺序影响。

## 质量

六个实现都通过冻结隐藏边界和可见测试，且没有越过允许业务文件、依赖、构建配置或保护文件。快速流程三次都正确识别“无匹配活动变更 + 明确局部结果”，只修改源码和邻近测试；完整流程在两个合法数字需求样本中都完成 Plan、Implement、Verify、规格同步和归档。

搜索完整样本的功能质量仍为 10/10，但它的需求文件名 `REQ-2026-SEARCH.md` 不符合插件数字编号合同，导致需求正文分层归档部分失败。该问题属于评测夹具，不计入合法输入下的完整生命周期成功率；后两组在执行前修正为 `REQ-2026-102/103.md`，均完整归档。因此完整流程的有效生命周期样本是 2/2，不应写成 2/3 插件失败。

## 返工

隐藏验收后的外部返工为快速 0、完整 0。内部过程存在明显差异：快速流程没有失败门禁或实现修正；完整流程共出现 5 个可辨认修正事件，其中包括一次搜索测试设计越界、一次语义证据/元数据修正、一次由非法夹具编号导致的归档恢复、一次分页规格追踪补全，以及一次不支持 `--help` 后读取脚本源码恢复。机器层面记录到 7 个非零验证/工具命令，数量大于修正事件，因为一个修正事件可能经过多个失败命令。

分页快速样本没有失败，但在全量脚本已通过后又运行了一次精确文件测试，属于重复验证而非返工；这是快速路径仍可压缩的一处小浪费。

## 未缓存 Token

快速流程三组共 62,076，平均 20,692；完整流程共 289,900，平均 96,633。完整流程是快速流程的 4.67 倍。逐组倍率为搜索 6.78×、状态 6.53×、分页 2.88×。

主要增量来自规划引擎状态/指令、proposal/spec/design/tasks、需求门禁、验证记录、同步和归档上下文，而不是业务实现本身。完整流程的价值是长期追踪和强门禁，不应把这些 Token 解释为纯浪费；但对已经决定的局部改动，它们没有带来本轮可观察的功能质量增益。

## 耗时

快速流程平均 65.235 秒，完整流程平均 275.749 秒，完整流程约为 4.23 倍。逐组倍率为搜索 6.15×、状态 3.23×、分页 3.69×。状态完整样本是最干净的完整流程：0 失败命令、202.358 秒；说明完整流程自身可以稳定完成，但固定治理成本仍显著高于快速路径。

## 判断与后续治理点

当前路由设计方向正确：明确、局部、无共享契约风险且能聚焦验证的任务应优先快速流程；需要决策台账、活动变更、规格同步、证据治理或归档追踪时才进入完整流程。

后续若继续优化，优先级建议为：

1. 为公共脚本提供稳定的参数用法或 `--help` 机器输出，减少完整流程读取实现源码恢复。
2. 让完整流程更早识别“是否需要独立测试方案 / 强制机器证据”，避免验证阶段才补技术派生产物。
3. 强化规格与 A-* 追踪的生成提示，减少 plan 门禁后的文档修正。
4. 快速流程在聚焦验证已经充分时避免重复执行同一测试。

这些是本轮行为证据支持的效率治理点，不是发布阻断。三组都是小型纯函数任务，尚未覆盖共享组件、API、权限、依赖、构建或跨平台变更，不能据此否定完整流程在高风险任务中的质量价值。
