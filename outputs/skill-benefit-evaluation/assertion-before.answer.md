这个断言覆盖的是：**两条给定订单、关键词为 `""`、省略 `status`（默认 `"all"`）时，返回结果与输入数组深度严格相等**。测试名称里的“全部”有前提：没有其他状态限制。

**实际覆盖了什么**

- 样本包含 `paid`、`pending` 两种状态；断言检查返回数组的长度、元素内容及顺序，不只是数量。
- 源码中 `status === "all"` 为真，`!query` 也为真，因此两条订单都被保留。
- 具体状态比较、订单号和客户名的搜索匹配都被短路跳过。虽然执行了 `trim().toLowerCase()`，空字符串无法检验去空白、大小写转换是否有效。

**重要遗漏，按优先级排列**

| 边界 | 建议检查的结果及意义 |
|---|---|
| 空关键词＋指定状态 | `{ keyword: "", status: "paid" }` 只返回 `A-1`；`pending` 只返回 `B-2`。这是最重要的遗漏：空关键词只取消搜索限制，状态筛选仍应生效。 |
| 纯空白关键词 | `"   "`、`"\t\n"` 按当前实现等同空关键词；同时检查指定状态，防止空白处理绕过状态筛选。 |
| 省略参数 | `filterOrders(orders)`、传 `{}`、`keyword: undefined` 应走默认关键词；显式 `status: "all"` 也尚未覆盖。 |
| 空订单数组 | 空关键词和非空关键词下都应返回 `[]`。当前样本始终有两条数据。 |
| 非空搜索及条件组合 | 分别覆盖订单号、客户名、大小写、首尾空白、部分匹配和无匹配；再检查“关键词命中但状态不符”返回空数组，确认两条件按 **AND** 生效。 |
| 输入不被修改 | 当前期望值直接使用传入的 `orders`，没有调用前快照。若实现原地修改输入并返回它，比较仍可能通过。 |

- **错误实现即使始终 `return orders`，也能满足这个断言。** 它几乎不能区分正确筛选和完全不筛选。
